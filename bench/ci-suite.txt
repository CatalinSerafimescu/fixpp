# bench/ci-suite.txt — the benchmark binaries the CI `bench` gate runs (#209).
#
# ONE source of truth, read by BOTH ci/run-bench-suite.sh (what to execute) and
# tools/bench_compare.py (what to compare). Two hand-maintained copies of a list
# is how a gate silently stops covering something.
#
# FORMAT — exactly three whitespace-separated fields:
#
#   <exe path, relative to the build dir>   <tier-3 comparand>   <tier-2>
#
#   tier-3 comparand : `gb-json:<path under bench/baselines/>`  — a genuine
#                      Google-Benchmark baseline; ±5% deltas are REPORTED.
#                      `none:<reason>` — no machine comparand exists. The reason
#                      is PRINTED; a row is never silently skipped, because a
#                      skipped row is how a gate reads green on nothing.
#   tier-2           : `paired` or `no` — whether this binary is compared
#                      base-vs-candidate on the same runner (the HARD timing
#                      signal). See .specify/ci209-bench-gate.md §3.
#
# ⚠️ THE EXE PATHS ARE NOT ALL `bin/`. bench/ sets RUNTIME_OUTPUT_DIRECTORY
# per subdirectory — wire/core/capi/codegen/dictionary/sync each get their own,
# while tls and session land in `bin/`. A single-directory assumption would make
# the "binary missing" cell fire on a correct tree.
#
# ── WHY AN EXPLICIT ALLOWLIST AND NOT `ctest -L bench` ────────────────────────
# This job invokes NO CTest at all — it runs binaries by path. That, and only
# that, is what keeps `compile_time_bench` out: it breaches its own flat 3 s
# ceiling at ~4.5 s for `v44` and always has (#209), so a label sweep would red
# on main immediately. For the record, `ctest -L bench` resolves to SIX
# configured entries, three of which ARE Google-Benchmark binaries registered
# through the `fixpp_add_tls_bench` function — see .specify/ci209-bench-gate.md
# §1a, where an earlier "exactly four, none of them benchmarks" claim is
# corrected.
#
# ── SELECTION RULE: single-threaded, CPU-bound, no network, no disk WRITE ─────
# Applied PER BINARY, not per directory. An earlier draft excluded whole
# directories because one member was noisy, which dropped deterministic hot
# paths (`bench_pinset_*`, `bench_async_mutex_uncontended`, `fix_time_bench`,
# `bench_memory_store`) for their siblings' sins.
#
# Excluded, each for its own stated reason:
#   bench_async_mutex_contended     contention is a scheduling measurement
#   bench_threading                 explicitly a concurrency benchmark
#   bench_file_store                real disk I/O
#   bench_verify_peer_in_envelope   real TLS handshake
#   bench_tls_handshake_loopback    loopback sockets
#   bench_async_read_some_dispatch  loopback sockets
#   bench_async_write_issue         loopback sockets
#   log_spike                       a tail-latency noise instrument by design
#   log_enqueue_bench               its only baseline is library_build_type=debug
#   placeholder_bench               measures nothing; its baseline is the
#                                   null-cpu_time shape tier 1 rejects
#   heartbeat_bench                 an explicit SCOPE PLACEHOLDER
#                                   (heartbeat_bench.cpp:31-38), not a measurement
#   check_alive_bench               its measured operation compiles to a no-op in
#                                   release (check_alive_bench.cpp:7-26), so a
#                                   release timing lane measures nothing
#
# ⚠️ Every exclusion above cites a SOURCE property of that binary. An earlier
# draft excluded whole directories because one member was noisy, which dropped
# deterministic hot paths for their siblings' sins; `log_enqueue_bench` in
# particular was excluded for having a debug baseline when the real reason is
# that it runs a drain thread (log_enqueue.cpp:11-23,62-80).
