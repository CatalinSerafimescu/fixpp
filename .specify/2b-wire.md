## 1. Goals

1. Define the five public wire primitives — `Framer`, `Parser`, `OffsetTable`, `Writer`, `Validator` — and the `View` flyweight base they share, so every higher layer (typed messages from **2c**, session FSM from `2d`-adjacent modules, MessageStore from **2e**, C-ABI accessors from **2i**, tap from **2l**) compiles against a single, locked surface.
2. Lock the **flyweight + caller-owned-buffer** model `[SYN §3.1 Q2]`: views never own bytes; lifetime is the buffer's; enforcement is layered (`[[clang::lifetimebound]]` on Clang; debug-build generation counters trap on use-after-reuse).
3. Lock the **hybrid offset-table** access model `[SYN §3.1 Q1]`: eager when consumer goes through the typed dictionary surface (random-access intent); lazy on the raw iterator path (streaming intent); choice templated by access mode — *no runtime branch on the hot path*.
4. Lock the **repeating-group representation** `[SYN §3.1 Q3]`: typed `group_view<T>` is the default; `.iter()` opt-out skips group-index construction for streaming callers.
5. Lock the **custom-field handling** `[SYN §3.1 Q4]`: opaque round-trip preservation by default; `unknown_fields()` filtered view over the offset table; no vector materialization; per-session dialect overlays (COM-011, owned by **2c**) promote known-unknowns into the typed surface.
6. Specify the **framing** discipline: multi-message TCP reads, partial-read carry-over, BodyLength + CheckSum verification *before* the parser sees a frame.
7. Specify the **error surface** for wire failures (parse errors, validator errors, framer errors), routed through `[arch §5.3]`'s `expected_t<T>` and the `fixpp::core::error` enum.
8. Stay zero-allocation between parse and `fromApp` `[const §VIII.5]` and exception-free across the same window `[arch §5.3]`.

### 1.1 Scope boundary — what wire owns vs what it doesn't

Wire owns the *wire format mechanics* — bytes-in / bytes-out, structural validity, and the index over a parsed frame. It does **not** own:

- **Field representation types.** Decimal is `decimal<T>` from **2a**; integer/string/timestamp/UTCTimestamp/etc. are `dict::field_traits<...>` from **2c**. Wire calls into those traits' `from_chars` / `to_chars` at the byte boundary; it never re-implements field decoding.
- **Typed message classes.** `fixpp::v50sp2::NewOrderSingle{view}` is generated by **2c**. Wire provides the underlying `MessageView` and `OffsetTable`; codegen wraps them with typed accessors.
- **Session semantics.** Sequence numbers, gap fills, ResendRequest/Test Request — all session-FSM concerns owned by `2d`-adjacent (and the session module's own Phase 4 spec). Wire reports a parsed-and-structurally-valid frame upward; it does *not* know about MsgSeqNum invariants.
- **Application semantics.** Order-state-machine concerns belong in user code; wire does not interpret OrdStatus, ExecType, etc.
- **FIX dialect overlays.** Adding/replacing tag definitions for a counterparty-specific dialect is a **2c** concern (the dialect overlay re-binds `dict::FieldRef`s); wire just consumes whichever metadata table the dictionary hands over.

### 1.2 Magnitude domain — what the wire layer is sized for

> **Critical:** these caps are sized in the **right dimension**. The offset table allocates *one entry per field occurrence*, not per distinct tag. A `MarketDataIncrementalRefresh` with 100 instruments × 10 levels per side reuses ~30 distinct tags but emits ~6000 occurrences. v0.1 conflated the two; v0.2 caps in occurrence space.

- **Frame size.** Default `Framer` accepts frames up to **256 KiB** (`fixpp::wire::default_max_frame_bytes`). Above that → `error::wire_frame_too_large`. Configurable per-`SessionConfig`. Rationale, by venue / message type:
  - FX retail / single-instrument equities: typical inbound ≤ 4 KiB → ~64× headroom.
  - Equity options `SecurityList` over a single underlying (CBOE SPX, ~3000 active strikes): ~150 KiB → ~1.7× headroom. Tight; users on equity-options venues should raise to 1 MiB.
  - 1000-strike option-chain `MarketDataIncrementalRefresh`: ~200 KiB → ~1.28× headroom. Same caveat — raise the cap.
  - Default 256 KiB is *not* "10× headroom for everyone"; it's "comfortable for FX/equities, tight for options, raise for derivatives". Document this trade so users tune for their venue.
- **Offset-table entries.** Default cap of **4096 total field occurrences per message** in the offset table (`default_max_offset_entries`); configurable. Above → `error::wire_offset_table_full`. This is the load-bearing memory bound — a 4096-entry table is `4096 × 12 = 48 KiB` of arena (§4.4) plus a `8192-slot` open-address pointer overlay (32 KiB on a 4-byte slot). At the cap the offset table consumes ~80 KiB of the per-message arena before any hash-overlay rehash growth.
- **Repeating-group entries per instance.** Default cap of **4096 entries per group instance** (`default_max_group_entries_per_instance`); configurable. Above → `error::wire_group_too_large`. Per-instance, not aggregate (a `NewOrderList` with 100 orders × 50 legs each is allowed because no single instance exceeds 4096; a single 8192-entry leg block is not). Real-venue caveat: CME / equity-options `SecurityList` responses on full options chains can produce single group instances > 4096 (e.g., CME SPX equity options ≈ 3000 active strikes; some venue snapshots include inactive strikes pushing past 5000). Users on those venues raise to 65535 (the natural `uint16_t` saturation, since `NoXxx` is a FIX `NumInGroup` integer field) and accept the per-message-arena footprint that follows.
- **Tag numeric range.** `uint16_t` (0..65535) — covers FIX standard tag space (1..~5000) plus user-defined custom tags (5000..9999) plus dialect overlay headroom. Above → `error::wire_tag_out_of_range`. The offset-table entry is **12 bytes** (§4.4 — `uint16_t tag + uint32_t offset + uint32_t length + 2-byte group sub-index tail`), pinned by `static_assert` at the same site. *No separate distinct-tag cap*; the v0.1 "4096 distinct tags per message" cap is **deleted** — distinct-tag count was never the cost driver, and the `uint16_t` storage shape already saturates at 65535.

These are caller-tunable bounds, not invariants of the FIX spec; they exist to bound memory and DoS surface against a hostile peer. The `[arch §11 row 1]` measurement spike (§10 Q1) measures both the raw `entry[]` array and the hash overlay, in occurrence space, on the venue/message corpora named above.

## 2. Non-goals

- **No FIXP / SOFH / SBE encoding** in v1.0 (W-015, W-016 are P3 — post-v1 per `[arch §4.3]` catalogue list). The wire layer is structured to accommodate a future binary encoding (the `Parser`/`Writer`/`OffsetTable` split is encoding-neutral on paper), but the v1.0 bytes are exclusively Tag=Value SOH `[FIX50SP2 §3]`.
- **No checksum-bypass mode.** Some legacy QuickFIX users disable CheckSum verification for performance; we don't. CheckSum is *cheap* (an unsigned byte-sum modulo 256, not a hash — see §6.1 step 5 / §4.5 for the exact algorithm; v0.1 incorrectly described it as XOR) and skipping it loses a primary corruption signal. If a counterparty mandates skipping, the user wraps `Framer` with their own pre-validator — we do not provide a switch.
- **No allocation between parse and `fromApp`** `[const §VIII.5]`. The per-message arena (`SessionConfig::message_arena`, `[arch §5.2]`) is reset *after* `fromApp` returns, not during. Trait specializations that allocate (e.g., `decimal<cpp_dec_float>`) must use the arena; the wire layer always passes it.
- **No exceptions across the parse → `fromApp` boundary** `[arch §5.3]`. The five wire primitives are `noexcept` end-to-end; trait wrappers around throwing third-party libraries trap (`fixpp::core::detail::trap_throw`, see `2a §4.2 note`).
- **No session-FSM behavior.** Sequence checks, ResendRequest, TestRequest, etc., are **session-module-Phase-4** concerns. Wire reports `frame_parsed_ok` upward and leaves dispatch to the session FSM.
- **No bidirectional coupling with codegen.** Wire is a leaf module from codegen's perspective; codegen depends on wire (calls `Parser`/`Writer`), not the other way around. The `Validator` interface (§4.6 — runtime-virtual in v0.2) holds a `dict::table_view` *by value*; `dict::table_view` is itself a concept-shaped value type (defined in **2c**), so there is no virtual `wire/` → `dict/` runtime edge. The dict-side cost is N values per supported FIX version, not N templated `Validator` instantiations.

## 4. Public API — C++

### 4.1 The `View` flyweight base

```cpp
// include/fixpp/wire/view.hpp
namespace fixpp::wire {

// All wire-layer views inherit the flyweight contract: zero-copy, no ownership,
// lifetime is the underlying buffer's. The base is empty at runtime; it exists
// to anchor the [[clang::lifetimebound]] markers and the debug-build generation
// counter.
class View {
public:
    constexpr View() noexcept = default;

    // [[clang::lifetimebound]] on `*this` here: the returned span aliases
    // the View's data, which itself aliases the originating buffer. Clang
    // chains the warning into the caller's lifetime context.
    [[nodiscard]] constexpr std::span<const std::byte>
    bytes() const noexcept [[clang::lifetimebound]]
        { return {data_, len_}; }
    [[nodiscard]] constexpr bool empty() const noexcept { return len_ == 0; }

protected:
    constexpr View(std::byte const* data [[clang::lifetimebound]],
                   std::size_t len,
                   detail::generation_token gen) noexcept
        : data_(data), len_(len)
#ifndef NDEBUG
        , gen_(gen)
#endif
    {}

#ifndef NDEBUG
    void check_alive() const noexcept;   // traps if gen_ != originating-pool's current generation
#else
    constexpr void check_alive() const noexcept {}
#endif

private:
    std::byte const* data_ {};
    std::size_t      len_  {};
#ifndef NDEBUG
    detail::generation_token gen_ {};
#endif
};

}  // namespace fixpp::wire
```

Notes:

- `[[clang::lifetimebound]]` on the constructor's `data` parameter triggers Clang's lifetime-check (best-effort warning). GCC honours it on parameters of view-returning functions. MSVC ignores; we accept that gap per `[const §IX.4]`.
- `detail::generation_token` is a 4-byte `(pool_id : uint16_t, gen : uint16_t)` POD. Release builds optimise it out (zero-sized member via `[[no_unique_address]]` plus `#ifndef NDEBUG`). Debug builds trap inside `check_alive()` if the originating pool has rotated past `gen`.
- Views are trivially copyable in release; debug adds the 4-byte token. We do not expose the token publicly — users can never mint a `View` directly, only receive one from `Parser` / `Framer`.

### 4.2 `Framer` — multi-message TCP framing

```cpp
// include/fixpp/wire/framer.hpp
namespace fixpp::wire {

class Framer {
public:
    struct Config {
        std::size_t max_frame_bytes = default_max_frame_bytes;     // 256 KiB
        // CheckSum verification is mandatory and not configurable. Per §2
        // non-goal "no checksum-bypass mode" and `[FIX50SP2 §3]` / W-005,
        // the only way to skip CheckSum is via `detail::framer_test_hooks`
        // in a tests/-only header — never the production API.
    };

    explicit Framer(Config c = {}) noexcept;

    // Feed bytes received from the transport. Returns zero or more complete
    // frame views into the caller-supplied `out` span; partial trailing bytes
    // are carried over inside `carry` for the next call.
    //
    // Lifetime: the returned span aliases `out`, and each frame_view inside
    // it aliases either `incoming` (when a complete frame fits in this feed)
    // or `carry` (when the previous feed left a partial that this feed
    // completed). Callers must NOT outlive `out`, `incoming`, or `carry`
    // across the next feed() call — the next feed() may rewrite carry's head
    // and the previous feed's incoming span is gone by then. Typical usage:
    // session FSM calls feed(), iterates the returned spans, hands each
    // frame_view to Parser::parse() synchronously, and never retains them.
    [[nodiscard]] expected_t<std::span<frame_view>>
    feed(std::span<const std::byte> incoming   [[clang::lifetimebound]],
         pmr_carry_buffer&          carry      [[clang::lifetimebound]],
         std::span<frame_view>      out        [[clang::lifetimebound]]) noexcept
        [[clang::lifetimebound]];

    // Diagnostic surface for partial-read state (used by tests and the tap).
    [[nodiscard]] std::size_t pending_bytes() const noexcept;
};

// pmr_carry_buffer wraps a fixed-capacity PMR vector sized to
// max_frame_bytes + small constant on construction (one allocation, lifetime
// of the session). It MUST be backed by a SessionConfig::framer_carry_arena
// (a session-lifetime PMR resource — typically a monotonic resource pinned
// to the session's lifetime), NOT by the per-message arena: carry by
// definition spans messages, so a per-message-reset arena would invalidate
// the carry between calls. The Framer never reallocates; bounded growth is
// rejected as `error::wire_frame_too_large` at the top of feed().
class pmr_carry_buffer { /* … */ };

// frame_view = bytes of one complete FIX message, BodyLength-validated and
// CheckSum-verified. Hand to Parser::parse() to get a MessageView.
class frame_view : public View {
public:
    // Body bytes (everything between 9=BodyLength's SOH and 10=CheckSum's '1').
    // Aliases the View's data; lifetime is the originating buffer's.
    [[nodiscard]] constexpr std::span<const std::byte>
    body() const noexcept [[clang::lifetimebound]];

    // (Note: the v0.1 frame_view::checksum() and body_length() accessors are
    // removed in v0.2. They returned values the caller had no reason to
    // re-verify — Framer already enforced both. If a debug introspection
    // need surfaces, reintroduce as `detail::frame_debug_view` in a
    // tests/-only header. Per Opus P3 — Codex round 2 of architecture
    // applied the same surface-discipline rule.)
};

}  // namespace fixpp::wire
```

Framing algorithm (§6.1):

1. Locate `8=FIXT.1.1` (or other BeginString) in the carry+incoming stream.
2. Parse `9=BodyLength` immediately after; reject if absent or non-numeric.
3. Locate the trailing `10=CheckSum` exactly `BodyLength` bytes past the byte after `9=...|`.
4. Verify `CheckSum` — **the unsigned byte-sum modulo 256** of every byte from the start of `8=...` through the SOH byte immediately preceding `10=` (per `[FIX50SP2 §3]` / W-005); compare to the parsed `10=NNN` (three ASCII digits, zero-padded). Mismatch → `error::wire_checksum_mismatch`.
5. If complete: emit a `frame_view` spanning the full `8=...|...|10=NNN|`. If partial: copy the trailing-incomplete bytes into `carry` and return.

The carry buffer is PMR-backed by `SessionConfig::framer_carry_arena` (session lifetime — see the `pmr_carry_buffer` comment above for why it cannot be the per-message arena). `Framer` itself owns no memory beyond its `Config`.

### 4.3 `Parser` — header-only zero-copy parser

```cpp
// include/fixpp/wire/parser.hpp
namespace fixpp::wire {

// Access mode is a compile-time selector — no runtime branch on the hot path.
// IterMode = streaming consumers (logger, tap); skips offset-table build.
// IndexMode = random-access consumers (typed messages, validator); eager build.
enum class access_mode { Iter, Index };

template <access_mode Mode = access_mode::Index>
class Parser {
public:
    // dict_metadata aliases a dictionary-table value (typically a static
    // constexpr instance generated by 2c, or a runtime overlay). The Parser
    // captures it by value (it is itself a value type — see §7.2 for the
    // dict::table_view shape) and does not extend its lifetime; callers must
    // ensure the dictionary outlives the Parser.
    explicit Parser(dict::table_view dict_metadata) noexcept;

    // Parse a checksummed frame. Returns a MessageView aliased into `frame`.
    // mr is the per-message arena; in Index mode the OffsetTable + hash
    // overlay are allocated here. In Iter mode mr is unused (offset table
    // is not built); pass nullptr or any resource — no calls land on it.
    [[nodiscard]] expected_t<MessageView<Mode>>
    parse(frame_view const& frame [[clang::lifetimebound]],
          std::pmr::memory_resource* mr) noexcept
        [[clang::lifetimebound]];

    // Allocation-free overload for Iter mode (mr would be unused anyway).
    [[nodiscard]] expected_t<MessageView<access_mode::Iter>>
    parse_iter(frame_view const& frame [[clang::lifetimebound]]) noexcept
        [[clang::lifetimebound]]
        requires (Mode == access_mode::Iter);
};

template <access_mode Mode>
class MessageView : public View {
public:
    // Common surface (both modes). All return-by-view accessors are
    // [[clang::lifetimebound]] on *this — the strings/iterators/views they
    // return alias the originating frame buffer's bytes; the MessageView
    // itself does not own them.

    [[nodiscard]] constexpr std::string_view
    msg_type() const noexcept [[clang::lifetimebound]];

    [[nodiscard]] constexpr std::uint32_t  msg_seq_num() const noexcept;

    [[nodiscard]] field_iterator
    begin() const noexcept [[clang::lifetimebound]];

    [[nodiscard]] field_iterator
    end() const noexcept [[clang::lifetimebound]];

    // Index-mode-only surface
    [[nodiscard]] OffsetTable const&
    offsets() const noexcept [[clang::lifetimebound]]
        requires (Mode == access_mode::Index);

    template <std::uint16_t Tag>
    [[nodiscard]] expected_t<field_view> get() const noexcept
        [[clang::lifetimebound]]
        requires (Mode == access_mode::Index);

    [[nodiscard]] expected_t<field_view>
    get(std::uint16_t tag) const noexcept [[clang::lifetimebound]]
        requires (Mode == access_mode::Index);

    // Repeating-group access (Index mode)
    template <std::uint16_t NoTag, class GroupT>
    [[nodiscard]] group_view<GroupT>
    group() const noexcept [[clang::lifetimebound]]
        requires (Mode == access_mode::Index);

    // Unknown-fields view (Index mode) — opaque round-trip, no vector materialization
    [[nodiscard]] unknown_fields_view
    unknown_fields() const noexcept [[clang::lifetimebound]]
        requires (Mode == access_mode::Index);
};

}  // namespace fixpp::wire
```

The two modes share `MessageView<>` via `requires`-constrained members; codegen instantiates `Parser<Index>` for typed access, the tap and logger instantiate `Parser<Iter>`. Each translation unit picks one — there is no runtime dispatch.

**`field_iterator` Length+Data handling.** The iterator must skip SOH bytes inside `data`-typed fields per `[FIX50SP2 §3]` Length+Data semantics. Because Iter mode is dict-free by design (§6.3 — the tap consumer never looks up tags), `field_iterator` cannot consult the runtime dictionary. v0.2 resolves this by using a **static `constexpr` table of FIX-standard Length+Data tag pairs** (`RawDataLength`/`RawData`, `XmlDataLen`/`XmlData`, `EncodedTextLen`/`EncodedText`, etc., enumerated from `[FIX50SP2 §3.3]`'s field-pair list) baked into `field_iterator`'s implementation. The table is exhaustive against the standard FIX 5.0 SP2 dictionary; dialect overlays that introduce *new* Length+Data pairs (rare; mostly venue-specific binary BLOB fields) need either Index mode (which has the runtime dict) or a 2c-supplied static-table specialization. This trade is logged as §10 Q5.

### 4.4 `OffsetTable` — `(tag, offset, length)` index

```cpp
// include/fixpp/wire/offset_table.hpp
namespace fixpp::wire {

class OffsetTable {
public:
    struct entry {
        std::uint16_t tag;       // 0..65535 (uint16_t range; §1.2)
        std::uint32_t offset;    // byte offset into the originating frame
        std::uint32_t length;    // value length (after '=', before SOH)
        std::uint16_t group_index_link;
            // 0 = top-level (not part of any group); otherwise an index into
            // OffsetTable's group-sub-index table identifying which group
            // instance this entry belongs to. Compressed pointer; expanded
            // lazily by group(no_tag).
    };
    static_assert(sizeof(entry) == 12);
    static_assert(alignof(entry) == 4);   // packed; no padding holes

    // Eager construction during parse (Index mode). `mr` is captured into the
    // OffsetTable as a member; subsequent lazy allocations (e.g., group())
    // re-use it. Lifetime contract: `mr` MUST outlive the OffsetTable
    // (typically both live in the per-message arena, which the session FSM
    // resets after fromApp returns).
    OffsetTable(frame_view const& frame [[clang::lifetimebound]],
                std::pmr::memory_resource* mr [[clang::lifetimebound]]) noexcept;

    [[nodiscard]] expected_t<entry> find(std::uint16_t tag) const noexcept;     // O(1) average

    // Returned span aliases the OffsetTable's internal entry[] array (which
    // lives in the captured mr). [[clang::lifetimebound]] on *this binds the
    // span lifetime to the table.
    [[nodiscard]] std::span<entry const>
    entries() const noexcept [[clang::lifetimebound]];

    [[nodiscard]] std::size_t size() const noexcept;

    // Group sub-index — built lazily on first group(no_tag) access (most
    // consumers don't touch every group). Allocates from the captured mr;
    // reused across subsequent group() calls within the same OffsetTable
    // lifetime. Returned reference aliases the table.
    [[nodiscard]] expected_t<group_index const&>
    group(std::uint16_t no_tag) const noexcept [[clang::lifetimebound]];
};

}  // namespace fixpp::wire
```

Memory shape (occurrence-keyed, per §1.2):

- `entry` is 12 bytes. Real-message footprints (top-level entries + active group sub-indices), all from the per-message arena:
  - Logon / Heartbeat / Test Request: ~10–20 entries ⇒ 120–240 B.
  - NewOrderSingle (single instrument, no allocation legs): ~25 entries ⇒ 300 B.
  - NewOrderList (10 orders × 5 legs): ~600 entries ⇒ ~7.2 KiB.
  - MarketDataIncrementalRefresh (100 instruments × 10 levels): ~6000 entries ⇒ ~72 KiB raw + ~32 KiB hash overlay = ~104 KiB. **Past the 4096 default cap** — a venue producing this needs `default_max_offset_entries` raised; users on options/derivatives venues must tune.
  - Worst-case at the default cap: 4096 entries × 12 B + 8192-slot pointer overlay ≈ 80 KiB.
- The lookup overlay is open-addressing robin-hood, capacity = next-power-of-two ≥ 1.25 × n. Average O(1); worst case O(n). The spike (§10 Q1) confirms the chosen load factor against the venue corpora named in §1.2.
- The group sub-index is a `pmr::vector<pmr::vector<entry>>`-shaped structure on the same arena: outer vector is one entry per group instance, inner vectors are the entries for that instance. Built on demand for the requested `no_tag` only — `MessageView` instances that touch only the typed accessors don't pay for groups they don't read. Reused across subsequent `group<>()` calls within the same `MessageView` lifetime.

### 4.5 `Writer` — serializer

```cpp
// include/fixpp/wire/writer.hpp
namespace fixpp::wire {

class Writer {
public:
    // dst is the caller-supplied output buffer (typically session's send arena).
    // scratch_mr is a per-message arena used for group_writer bookkeeping
    // (open-group entry-count tracking + offset list for backpatch at close);
    // Writer itself does not allocate beyond what the group bookkeeping costs.
    // Writer aliases dst and captures scratch_mr; both must outlive the Writer.
    explicit Writer(std::span<std::byte> dst [[clang::lifetimebound]],
                    std::pmr::memory_resource* scratch_mr
                                            [[clang::lifetimebound]]) noexcept;

    // Type-erased append; the typed overloads below are the normal callers.
    [[nodiscard]] expected_t<void>
    append_raw(std::uint16_t tag, std::span<const std::byte> value) noexcept;

    // Typed convenience overloads — dispatch to the field's traits' to_chars.
    template <class T>
    [[nodiscard]] expected_t<void> append(std::uint16_t tag, T const& v) noexcept;

    // Repeating-group helpers: open NoXxx, append entries, close to seal counts.
    // Returned group_writer aliases *this; nesting must close in LIFO order.
    [[nodiscard]] expected_t<group_writer>
    open_group(std::uint16_t no_tag, std::uint32_t count) noexcept
        [[clang::lifetimebound]];

    // Commit fills in BodyLength (tag 9) and CheckSum (tag 10) and returns the
    // total byte count written. After commit, the Writer is consumed.
    [[nodiscard]] expected_t<std::size_t> commit() && noexcept;

    [[nodiscard]] std::size_t bytes_written() const noexcept;
};

class group_writer {
public:
    [[nodiscard]] expected_t<void>
    append_field(std::uint16_t tag, std::span<const std::byte> value) noexcept;
    template <class T>
    [[nodiscard]] expected_t<void>
    append_field(std::uint16_t tag, T const& v) noexcept;
    void close() && noexcept;        // RAII fallback if not explicitly closed
};

}  // namespace fixpp::wire
```

`Writer::commit()` algorithm — **digit-only BodyLength**, no space padding (per `[FIX50SP2 §3]` / `[FIX50SP2 §3.3]` `Length` data type, which forbids padding):

1. While the user appends fields, the writer tracks `body_start_offset` (the byte position where `35=MsgType...|...` begins) and `body_end_offset` (the byte position immediately *before* `10=CheckSum`'s `1` character).
2. At `commit()`, compute `body_length = body_end_offset - body_start_offset`.
3. Render `body_length` as a digit-only ASCII integer (1..10 digits for BodyLength up to `default_max_frame_bytes` = 256 KiB ⇒ ≤ 6 digits in practice).
4. Determine the gap between the placeholder (which `Writer` reserved with the *correct* digit count via a pre-flight estimate at first `append_*` call — when the in-progress body is committed, the estimate is upper-bound by `bytes_written` so far, which is monotonically known) and the actual digit count. If the estimate overshot by `k` bytes, `memmove` the body left by `k` bytes to close the gap. Worst case: a single 256-KiB `memmove`; bounded.
5. Compute CheckSum: **unsigned byte-sum modulo 256** of every byte from `8=...` through the SOH preceding `10=`. Render as 3 ASCII digits, zero-padded.

Rationale for digit-only over space-padded: `[FIX50SP2 §3.3]`'s `Length` definition is "Integer field representing the length of an integer value… without leading zeroes or sign character" — leading spaces are not permitted, and digit-strict counterparties (e.g., QuickFIX's strict-mode parser, several venue gateways) will reject a `9=   123|` frame outright. The `memmove` cost (one move per message, bounded by frame size) is amortized into the `Writer::commit ≤ 80 ns` Tier 1 ceiling (§6.6) on representative 20-tag messages; for 200-tag Instrument-heavy messages the ceiling relaxes to ≤ 800 ns (also recorded in §6.6 v0.2).

### 4.6 `Validator` — runtime-virtual plugin interface

> **v0.2 design change.** v0.1 made `Validator` a concept-bound template parameterized by `DictTableView`. That sidestepped — rather than satisfied — the `[const §XIV.2]` plugin cap, broke the constitutional plugin pattern (`Validator` was the only "interface" with no runtime substitution), and forced per-FIX-version template instantiation that conflicts with the engine's "one symbol set per build" goal (`[arch §4.1]`, mirrored in 2a's `FIXPP_DECIMAL_T` rule). v0.2 makes `Validator` a runtime-virtual interface with **exactly 5 pure-virtuals** — within the cap — with a `dictionary_driven_validator` default implementation that internally consults the dictionary metadata. Users wanting stricter rules (regulator overlays, dialect strict-mode toggles) inject a different impl at session-construct time without rebuilding. Per Opus adversarial NEW P1.

```cpp
// include/fixpp/wire/validator.hpp
namespace fixpp::wire {

// Plugin interface — exactly 5 pure-virtual methods (`[const §XIV.2]` cap).
// Default impl: dictionary_driven_validator (in src/wire/, separately).
class Validator {
public:
    virtual ~Validator() noexcept = default;

    // Whole-message validation. Walks every present dictionary-known field
    // and applies (a) header/trailer order, (b) required-field presence,
    // (c) field-level type/enum/length checks, (d) conditional-required
    // rules per `[FIX50SP2 §3.4]`. Returns OK ONLY IF every dictionary-known
    // field present in the message has been type-checked by the impl.
    [[nodiscard]] virtual expected_t<void>
    validate(MessageView<access_mode::Index> const& msg,
             std::pmr::memory_resource* scratch_mr) const noexcept = 0;

    // Defense-in-depth re-check, invoked by typed accessors when users call
    // strongly-typed get<Tag>(). When validate(msg) has already cleared the
    // message, this is redundant for fields that validate(msg) checked; it
    // remains as a safety net for code paths that bypass validate() (e.g.,
    // C-ABI accessors that hand a tag/value pair directly to user code).
    [[nodiscard]] virtual expected_t<void>
    validate_field(std::uint16_t tag,
                   std::span<const std::byte> value) const noexcept = 0;

    // Required-field set for a given MsgType — exposed for callers that
    // want to drive validate() externally (e.g., the conformance test
    // harness; the C-ABI `fixpp_msg_required_fields` introspection).
    [[nodiscard]] virtual std::span<std::uint16_t const>
    required_fields(std::string_view msg_type) const noexcept = 0;

    // Is `tag` declared for `msg_type` per the dictionary? Drives the
    // dictionary-known-but-invalid-for-msg-type case (§6.5 rule 4 in v0.2,
    // which is now a hard validation error, not an unknown_fields() route).
    [[nodiscard]] virtual bool
    field_valid_for(std::string_view msg_type,
                    std::uint16_t tag) const noexcept = 0;

    // First-field-of-group rule per `[FIX50SP2 §3]` — used by group_view::iter()
    // to identify group-instance boundaries when streaming-mode consumers walk
    // a repeating group without the offset-table sub-index.
    [[nodiscard]] virtual std::uint16_t
    group_first_field(std::uint16_t no_tag) const noexcept = 0;
};

// Default implementation, exported by 2c. Constructed from a dict::table_view
// (a value-typed metadata handle); holds the table by value and consults it
// inside the virtual methods. Allocates from the scratch_mr passed to
// validate() — see §6.5 for why scratch is needed and what's allocated.
class dictionary_driven_validator final : public Validator {
public:
    explicit dictionary_driven_validator(dict::table_view dict) noexcept;
    /* …virtual overrides… */
};

}  // namespace fixpp::wire
```

Plugin-cap accounting (`[const §XIV.2]`): exactly 5 pure-virtual methods. The cap permits ≤ 5; satisfied directly. (Compare to `Application` callbacks in `[arch §6.x]` which justify 6 with explicit semantic distinctness — `Validator` does not need that justification.)

Validation rules (§6.5):

1. Header order: `8=BeginString | 9=BodyLength | 35=MsgType | ...` per `[FIX50SP2 §3]`. Out-of-order header → `error::wire_header_out_of_order`.
2. Trailer: `10=CheckSum` is the last field; nothing follows. Already enforced by `Framer`; double-checked here for defense in depth.
3. **Every dictionary-known field present is type-checked** (type, enum membership, length constraint, conditional-required). v0.1 made this opt-in per typed accessor; v0.2 makes it unconditional under `validate(msg)`. Per Codex P2 / Opus P2→P1 escalation: validation cannot depend on which fields user code happens to read. Failure → `error::wire_field_value_out_of_range` (or `wire_field_value_truncated` for the precision-loss case 2a §6.4 produces, which the validator surfaces unchanged).
4. Required fields: the validator's `required_fields(msg_type)` set MUST be present; missing → `error::wire_required_field_missing`.
5. **Dictionary-known-but-invalid-for-this-MsgType tag is a hard validation error**, not an unknown-fields route. v0.1 routed these to `unknown_fields()` for round-trip preservation; v0.2 returns `error::wire_unexpected_tag` and the session FSM emits a Session-Reject with `SessionRejectReason = 2` ("Tag not defined for this message type") per `[FIX50SP2 §2.1]`. Only **dictionary-missing** tags (genuinely unknown to both the standard dictionary and the active dialect overlay) flow to `unknown_fields()` for opaque round-trip. Per Codex P2 / Opus P2→P1.
6. Conditional rules per `[FIX50SP2 §3.4]` (Conditional-Required field semantics): supported by the v1.0 default validator at the dictionary metadata's discretion — `dict::table_view` carries the `is_required` predicate as a closure (or per-field rule pointer) per **2c**'s metadata generation rules.

### 4.7 Repeating-group view

```cpp
// include/fixpp/wire/group_view.hpp
namespace fixpp::wire {

// GroupT is a typed group struct generated by 2c (e.g., NewOrderSingle::leg).
// group_view is a flyweight over a group sub-index entry.
template <class GroupT>
class group_view : public View {
public:
    [[nodiscard]] std::size_t size() const noexcept;
    [[nodiscard]] GroupT
    operator[](std::size_t i) const noexcept [[clang::lifetimebound]];

    // Streaming opt-out: skips group-index construction. Users who want
    // to walk legs sequentially without paying the index cost call .iter().
    [[nodiscard]] iterator iter() const noexcept [[clang::lifetimebound]];

    class iterator { /* … forward iterator over group entries … */ };
};

}  // namespace fixpp::wire
```

`group_view<GroupT>::size()` and `operator[]` use the offset-table's group sub-index (built on first call). `.iter()` walks the raw byte stream from the `NoXxx` field forward, identifying group-instance boundaries by the dictionary's first-field-of-group rule (per `[FIX50SP2 §3]`); no sub-index construction.

### 4.8 Unknown-fields view

```cpp
// include/fixpp/wire/unknown_fields.hpp
namespace fixpp::wire {

// Filtered view over the offset table — yields only entries whose tag is
// genuinely unknown (not declared by the dictionary at all, not declared by
// the active dialect overlay either). Tags that the dictionary DOES define
// but that are invalid for the current MsgType are NOT routed here in v0.2;
// they produce a validation error per §4.6 rule 5 / §6.5 rule 5. Iteration
// walks the offset table inline; no vector materialization.
class unknown_fields_view : public View {
public:
    class iterator { /* … forward iterator yielding (tag, value) pairs … */ };
    [[nodiscard]] iterator begin() const noexcept [[clang::lifetimebound]];
    [[nodiscard]] iterator end()   const noexcept [[clang::lifetimebound]];
    [[nodiscard]] bool     empty() const noexcept;
};

}  // namespace fixpp::wire
```

Round-trip preservation: when a `Writer` echoes a parsed message (e.g., for resend on the session-FSM gap-fill path), it must walk both the typed fields *and* the unknown-fields view, preserving the original byte order. The merge is in-place two-pointer (both streams are offset-keyed and pre-sorted by stream position), so the merge buffer cost is zero — no allocation. The session FSM and the message store use **raw-frame storage** (per 2a §7.1 v0.3, confirmed at **2e**), so true byte-identical round-trip is the store's responsibility, not the writer's; the writer's job is structural fidelity for messages that *originate* in our process.

## 5. C ABI surface — none (delegated to 2i)

The wire layer is C++-only. No wire types (`MessageView`, `OffsetTable`, `frame_view`, `group_view`, `unknown_fields_view`) appear in `<fix/c_api.h>`. C-ABI consumers see only the **2i**-owned `fixpp_msg_t` opaque handle and the `fixpp_msg_field_*` accessor family, which internally delegates to the wire `MessageView` they wrap. This keeps `[const §X.2]` (no C++ leakage) intact.

## 6. Behavioral contract

### 6.1 Framing (TCP byte-stream → frame_view)

Inputs: a chunk of bytes `incoming` plus any `carry` from the previous call. Algorithm:

1. Append `incoming` to the logical stream `carry || incoming`.
2. Locate `8=` at offset 0 of the logical stream; if not at offset 0 → `error::wire_framing_resync` (the session FSM decides whether to disconnect).
3. Parse the BeginString (`8=…|`), BodyLength (`9=…|`). Reject non-numeric BodyLength → `error::wire_invalid_body_length`. Reject BodyLength > `Config::max_frame_bytes` → `error::wire_frame_too_large`.
4. If the logical stream contains fewer than `header_bytes + body_length + checksum_bytes` bytes → carry the partial; emit nothing this call.
5. Compute CheckSum as the **unsigned byte-sum modulo 256** of every byte in `[start_of_8 .. start_of_10)` (per `[FIX50SP2 §3]` / W-005); compare against the parsed `10=NNN` (three ASCII digits, zero-padded). Mismatch → `error::wire_checksum_mismatch` (advance past this frame; session FSM disconnects). *Not XOR* — v0.1 said "XOR sum mod 256" in error; converged to byte-sum-mod-256 in v0.2.
6. Emit `frame_view` for the complete frame; advance the logical stream past it; loop to step 2.

Carry handling: at most `header_bytes + body_length` bytes are ever carried; the carry buffer is at most `Config::max_frame_bytes + small constant`. Bounded.

### 6.2 Parse (frame_view → MessageView)

Inputs: a `frame_view` (already CheckSum-verified by `Framer`), an access mode (`Iter` or `Index`), and a PMR resource (Index mode only).

`Iter` mode:

1. Initialize a forward `field_iterator` pointing at the first byte after the `35=` field (header is parsed inline by the iterator).
2. `MessageView<Iter>::msg_type()` and `msg_seq_num()` are computed by walking the header inline; no offset table.
3. Allocations: zero. The iterator holds three pointers and a generation token (debug only).

`Index` mode:

1. Walk the frame once, emitting `(tag, offset, length)` entries into the `OffsetTable` arena allocator.
2. Build the open-address hash overlay (capacity = next-power-of-two ≥ 1.25 × n).
3. Group sub-index is *not* built — deferred to first `group<>()` call.
4. Allocations: the offset table itself + the hash overlay; both come from the per-message arena `[arch §5.2]`. No allocation outside the arena.

Both modes reject malformed frames with `error::wire_invalid_field_format` (e.g., missing `=`, missing trailing SOH on the last field, non-ASCII tag digits).

### 6.3 Hybrid offset-table access mode

The choice between `Iter` and `Index` is **per translation unit**, picked by the consumer:

- Codegen (**2c**) instantiates `Parser<Index>` because typed accessors need random-access tag lookup.
- The session FSM (`2d`-adjacent) instantiates `Parser<Index>` for inbound dispatch (it routes by `MsgType`, then hands off the typed view to user `fromApp`).
- The tap consumer (**2l**) instantiates `Parser<Iter>` — it streams bytes outward and never looks up tags.
- The async logger (**2k**) does not parse at all; it logs raw frame views.

Because `Parser<Mode>` is a template, each TU's compiler picks one branch and emits one symbol set. There is no `if (mode == Iter)` on the hot path. The cost of choosing wrong is only the one-time `OffsetTable` build; the cost of choosing right is zero.

The Phase 2 measurement spike (§10 Q1) confirms the eager-mode footprint on a real Instrument-heavy message (NewOrderList with 100 orders × 50 legs ≈ 5000 tags ⇒ ~60 KiB OffsetTable). If footprint is unacceptable we revisit with a sparse-encoding tweak; we do *not* drop hybrid mode.

### 6.4 Lifetime contract

- Every `View`-derived type (`MessageView`, `frame_view`, `field_view`, `group_view`, `unknown_fields_view`, `OffsetTable::entry`) is a flyweight over the originating `frame_view`'s buffer. Outliving that buffer is undefined behavior in release; debug builds trap.
- `[[clang::lifetimebound]]` annotations cover every constructor and view-returning member. Best-effort warnings on Clang and partial GCC; ignored on MSVC `[const §IX.4]`.
- Debug builds wire `detail::generation_token` into each `View` and trap inside `View::check_alive()` (called from every accessor) when the originating buffer pool's generation has rotated past the view's token. Debug-only — release strips the token entirely (`[[no_unique_address]]` empty member).
- Buffer pool generations rotate when a session arena resets between message batches `[arch §5.2]`. The session FSM ensures rotation happens *after* `fromApp` returns; user code that captures a `MessageView` past `fromApp` and accesses it later will trap in debug, UB in release. Documented as the *one* user-facing footgun of the flyweight contract — see `2c §7.x` for codegen's mitigation (typed messages own no view past their constructor).

### 6.5 Validation

- Triggered explicitly by the session FSM after parse and before dispatch. Not implicit in `Parser::parse` — keeps the parse hot path lean for consumers who don't validate (e.g., the tap, the async logger). When called, validation is **complete** (every dictionary-known field present is type-checked), not opt-in (v0.1's per-accessor rule was unsound — see Appendix C, Codex P2 → Opus P2→P1 escalation).
- `Validator::validate(msg, scratch_mr)` allocates from `scratch_mr` (typically the per-message arena `[arch §5.2]`). Allocation cost is bounded:
  - A `seen[]` bitmap sized to `default_max_offset_entries / 8` ≈ 512 B (in occurrence space, not distinct-tag space).
  - A `required_remaining` set materialized from `Validator::required_fields(msg_type)` — typical FIX `MsgType` declares 5–25 required fields ⇒ 10–50 B as a sorted `pmr::vector<uint16_t>`.
  - The `Conditional` rule walker uses no extra arena beyond stack space (rules are evaluated in-place against the offset table).
  - Total scratch per validate(): ~600 B worst case at the §1.2 cap.
- `Validator::validate_field(tag, value)` is allocation-free; it consults `dict::table_view`'s field-type rule and applies the type's validator directly to the byte span.
- Validator failures produce one of: `wire_required_field_missing`, `wire_header_out_of_order`, `wire_invalid_field_format`, `wire_field_value_out_of_range`, `wire_unexpected_tag` (the v0.2 dict-known-but-invalid-for-msg-type case), and `wire_field_value_truncated` (raised by 2a's decimal traits and surfaced unchanged). See §6.7 for the canonical list of `fixpp::core::error` variants this design introduces.

### 6.6 Allocation, exceptions, threading

#### Arenas — three lifetime classes, pinned

- **Per-message arena** (`SessionConfig::message_arena`, `[arch §5.2]`) — reset by the session FSM after `fromApp` returns. Holds: the `OffsetTable` `entry[]` array, the open-addressing hash overlay, the group sub-indices built lazily by `OffsetTable::group()`, the validator's `seen[]` bitmap and `required_remaining` set. *Lifetime is one inbound message.*
- **Framer carry arena** (`SessionConfig::framer_carry_arena`) — session lifetime, NOT per-message. Holds: the `pmr_carry_buffer`, sized at construction to `Config::max_frame_bytes + small constant`. *Lifetime is the session.* Carry by definition spans messages, so a per-message-reset arena would invalidate the carry between calls. v0.1 documented carry as living in the per-message arena; v0.2 corrects this — carry MUST live in `framer_carry_arena`. Per Opus adversarial NEW P1.
- **Writer scratch arena** (passed to `Writer` constructor; typically the same per-message arena since outbound write happens within one fromApp/toApp turn) — holds: the `group_writer` open-group bookkeeping (count + per-entry offset list for backpatch at `close()`). *Lifetime is one outbound message-build turn.*

#### Allocation budget (zero-`new`/`delete` enforcement)

- **Zero `new`/`delete`** between parse and `fromApp` `[const §VIII.5]`. The three arenas above absorb every wire-layer allocation; the global heap is never touched on the hot path. `tools/check_alloc.py` (§9 seam #10) verifies under `mallocnesia` on Linux/Clang Tier 1.
- **Iter mode** is zero-allocation end-to-end (no offset table; no validator; no writer in the typical Iter consumer path).
- **Index mode** allocates from the per-message arena only; bounded by §1.2 caps.
- **Validator** allocates ~600 B worst-case from the scratch arena passed to `validate()` (§6.5 detail).
- **Writer** allocates `group_writer` bookkeeping from `Writer::scratch_mr` (§4.5); for messages without repeating groups, allocation is zero.

#### Exceptions

All public surfaces are `noexcept`. Internal helpers that *might* throw (e.g., custom dictionary-table types if a user supplies a non-`noexcept` `dict::table_view` specialization) are wrapped in the same `trap_throw` helper used by 2a `§4.2 note`. Framer/Parser/OffsetTable/Writer/Validator's pure-virtual methods are declared `noexcept` — implementers wrapping throwing code must trap inside the override.

#### Threading

- `Framer` is not thread-safe — one per session, owned by the session's I/O strand.
- `Parser`, `Writer`, `OffsetTable`, `MessageView`, `Validator` are value types (or virtual interfaces with value-semantics-on-substitution). Safe on a single thread; not synchronized for concurrent access.

#### View-escape contract — load-bearing, distinct from 2a

A `MessageView` (and every view derived from it: `field_view`, `group_view<T>`, `unknown_fields_view`, `OffsetTable::entry` spans) **aliases the originating frame buffer**; the buffer's lifetime is the per-message arena's slot, and that slot is reset by the session FSM after `fromApp` returns. Capturing a `MessageView` past `fromApp` return is undefined in release; debug builds trap via the §6.4 generation-counter mechanism.

Contrast with 2a v0.3 §6.5: `decimal<T>::parse(span)` *consumes* the input span eagerly — the resulting `decimal<T>` does **not** alias. Wire views are the inverse: they alias by design (zero-copy). User code crossing a strand/thread boundary (e.g., `fromApp` posting work to a thread-pool executor per `[arch §5.1]`) cannot transport a `MessageView` directly. The supported escape hatch is **`MessageView::reify(mr) → fixpp::v50sp2::owning_message_t<...>`** defined in 2c (a deep-copy into caller-owned PMR storage; the resulting owning value is safe to move across threads, at the cost of the copy). 2c §X.Y owns the `reify`/`owning_message_t` shape; this doc records the contract and the cross-reference.

#### Latency targets (default dictionary, Linux/Clang/x86_64, warm cache)

These are bench-harness regression bars (§9 seam #5); CI fails on >5% regression vs the previous tagged release. Per Opus adversarial NEW P2: v0.1 had a wishful 250 ns Index-parse target — the math (12.5 ns/tag including hash insert) didn't square with the Iter target. v0.2 relaxes it to a defensible budget.

| Operation | Workload | Ceiling | Notes |
|---|---|---|---|
| `Framer::feed` | one frame, no carry, 80-byte body | ≤ 30 ns | byte scan + checksum sum |
| `Parser<Iter>::parse_iter` | 20-tag message | ≤ 80 ns | ~4 ns/tag, no hash insert |
| `Parser<Index>::parse` | 20-tag message | ≤ 400 ns | ~20 ns/tag including hash insert + dispatch (was 250 ns in v0.1) |
| `Parser<Index>::parse` | 200-tag Instrument-heavy | ≤ 4 µs | ~20 ns/tag, dominated by hash overlay |
| `OffsetTable::find` | after build, 32-slot hash | ≤ 15 ns | one cache line, one probe |
| `Validator::validate` | 20-tag message, full pass | ≤ 200 ns | required-set + per-field type check |
| `Writer::commit` | 20-tag message | ≤ 80 ns | byte loop + memmove for BodyLength backpatch |
| `Writer::commit` | 200-tag Instrument-heavy | ≤ 800 ns | memmove dominates |

## 7. Integration with adjacent modules

### 7.1 Decimal (`[arch §4.1]`, owner **2a**)

The wire parser invokes `decimal_traits<FIXPP_DECIMAL_T>::from_chars(span, mr)` for FLOAT-typed fields; the writer invokes `to_chars(value, dst)`. The per-message arena (`[arch §5.2]`) is the `mr` passed in. Wire never sees the underlying `T` — it is handed a span and reads back a `decimal<T>`. Lossy traits (`is_lossless_for_fix_float == false`) are *not* gated at the wire layer — per `2a §7.1` (v0.3), the gate lives at the typed-payload persistence sink (**2e**), not here. Wire passes parsed values upward unchanged.

### 7.2 Dictionary / codegen (`[arch §4.2]`, owner **2c**)

`Parser<Index>` is parameterized by a `dict::table_view` value type (defined in **2c**) — a concept-shaped contract that must provide:

- `field_ref(tag) → optional<FieldRef>` — looks up a field's type and constraints.
- `required_fields(msg_type) → span<uint16_t>` — required-field list for this message type.
- `field_valid_for(msg_type, tag) → bool` — is this tag declared for this message type?
- `group_first_field(no_tag) → uint16_t` — the dictionary's "first field of group" rule (per `[FIX50SP2 §3]`) used by `group_view::iter()` (Index mode only — Iter mode uses the static Length+Data table per §4.3).

`Validator` itself is **runtime-virtual** (§4.6) — switched in v0.2 from concept-bound to virtual to satisfy `[const §XIV.2]`'s plugin-interface contract directly. The default impl `dictionary_driven_validator` *holds* a `dict::table_view` by value. Multiple FIX versions co-existing in one binary (FIX 4.4 + FIX 5.0 SP2 — a hard requirement per `[arch §3]`) instantiate two `dict::table_view` values, but only one `Validator` impl class — so the binary cost is one vtable + N values, not N×M template instantiations. **2c** ships the production `dict::table_view` for each supported FIX version + dialect overlay; tests use `mock_dict_table` (test seam #1) plus `mock_validator` (a value-substituted virtual impl).

### 7.3 Threading + Clock (`[arch §5.1]`, owner **2d**)

Wire is clock-free — it does not stamp parse times, does not measure elapsed durations, does not decide based on wall-clock. The `Framer` reports the byte counts and the parse outcome; the session FSM (using **2d**'s `Clock` interface) stamps SendingTime, drives heartbeat timers, etc. This separation keeps wire deterministic in tests without injecting a clock.

### 7.4 MessageStore + typed-payload persistence (`[arch §4.4]`-adjacent, owner **2e**)

**Two distinct persistence sinks** — distinguishing them was the crux of the 2a v0.3 convergence and is repeated here so 2e cannot misread the rule:

- **MessageStore (the session-FSM-driven journal/replay sink).** The session FSM hands **raw frame bytes** (the `frame_view::bytes()`) to MessageStore for journaling and replay — *not* parsed `MessageView`s, and *not* parsed-then-re-serialized typed payloads. This is the 2a §7.1 v0.3 rule: replay = raw frames, decimal-trait-agnostic, byte-identical. Wire's contribution to this path is just the `frame_view::bytes()` accessor (§4.2). **MessageStore does not require a lossy-traits `static_assert`** — the bytes stored are the bytes received, and the chosen `FIXPP_DECIMAL_T` is irrelevant to the storage shape.
- **Typed-payload persistence (a *different* sink).** SBE/Avro snapshotting, control-plane decoded-record streams, audit pipelines that emit normalized typed records — these sinks persist *parsed values*, not raw frames. They lose precision irrecoverably under a `is_lossless_for_fix_float == false` engine-wide alias. The `static_assert(decimal_traits<FIXPP_DECIMAL_T>::is_lossless_for_fix_float, "...")` lives at the **typed-payload persistence write site** (defined by **2e** for any typed-payload variant of MessageStore, by **2j** for control-plane decoded snapshots) — *not* at MessageStore's raw-frame path, *not* at the wire layer.

Wire owns neither assert; the constraint is recorded here only because the wire layer is the visible producer that 2e/2j consume from. **2e** confirms the raw-frame design as the canonical MessageStore (§10 Q6); if 2e elects a typed-payload variant alongside the raw-frame default, the assert lives there.

### 7.5 C ABI message rep (`[arch §4.10]`, owner **2i**)

`fixpp_msg_t` is an opaque handle; internally it carries a `MessageView<Index>*` plus the originating frame's lifetime metadata. **2i** owns:

- The opaque handle shape and reference-counting (or arena-tied lifetime) discipline.
- The accessor functions (`fixpp_msg_field_int`, `fixpp_msg_field_decimal`, `fixpp_msg_field_string`, etc.) that translate between `MessageView::get<Tag>()` and the C-typed output.
- Error-code mapping from `fixpp::core::error` to `fixpp_error_t`.

Wire contributes: nothing C-facing. The Index-mode `MessageView` is the C++ surface that **2i** wraps.

### 7.6 Tap (`[arch §4.9]`, owner **2l**)

The tap consumer reads `frame_view::bytes()` from the parser hand-off, ring-buffers them, and ships to a downstream consumer process. Tap never re-parses; it ships the original bytes. The parser's `Iter` mode exists in part for tap's own use when it does need fielded access (rare; usually for header-only filtering before ring write).

## 8. PMR — recap

Three arenas with three lifetime classes (canonical reference; see §6.6 for the discussion):

| Arena | Lifetime | Holds | Reset by |
|---|---|---|---|
| `SessionConfig::message_arena` | per-message (reset after `fromApp`) | `OffsetTable::entry[]`, hash overlay, group sub-indices, validator scratch (`seen[]` + `required_remaining`), writer group-bookkeeping | session FSM after `fromApp` returns |
| `SessionConfig::framer_carry_arena` | session lifetime | `pmr_carry_buffer` (sized `max_frame_bytes + small constant` once at construction) | session destruction only |
| `Writer::scratch_mr` (constructor parameter) | one outbound build turn (typically the per-message arena reused) | `group_writer` open-group bookkeeping (count + per-entry offset list) | caller resets after `commit()` |

Per `[const §VIII.5]`: zero `new`/`delete` between parse and `fromApp`. The arena reset cadence for `message_arena` (per-message — the choice this doc requires — vs per-batch) is logged as `2b §10 Q4` and confirmed at **2d**; wire's preference is per-message because it bounds peak per-session memory most tightly. v0.1's "Carry is allocated from a caller-supplied PMR resource (typically `SessionConfig::message_arena`)" claim was *wrong on the lifetime axis* — carry spans messages and cannot live in a per-message-reset arena. Per Opus adversarial NEW P1.

## 9. Test seams

Per `[arch §10]` requirement (4): every design doc ends with the test seams it exposes.

1. **`mock_dict_table`** — header-only specialization of the `dict::table_view` concept; injects per-test `field_ref` / `required_fields` / `field_valid_for` tables. Lives in `tests/support/mock_dict_table.hpp`. Used by every `Parser<Index>` and `Validator` test that doesn't need the full generated dictionary. **`mock_validator`** — value-substituted virtual `Validator` impl (since v0.2 `Validator` is runtime-virtual) — same path.
2. **W-001..W-014 conformance corpus** — `tests/wire/conformance/` holds per-row corpora: `w001_tag_value_soh.csv`, `w002_header_order.csv`, etc. Each row drives a parameterized GTest. `[FIX50SP2 §3]` is the oracle.
3. **Round-trip property test** — for any FIX-valid byte sequence `b`, the round-trip `b → Parser::parse → reify → Writer → commit` produces a byte sequence whose re-parse yields a `MessageView` value-equal to the original (field-by-field, ignoring trailing whitespace insensitivity). Run on a corpus of 10⁴ generated samples.
4. **Multi-message framing (partial reads)** — feed bytes to `Framer` in 1-byte, 7-byte, 64-byte, and full-frame chunks; verify the same set of `frame_view`s emerges. Catches off-by-one in carry-handling.
5. **Latency regression** — Google Benchmark on `Framer::feed`, `Parser<Iter/Index>::parse`, `OffsetTable::find`, `Validator::validate`, `Writer::commit`, plus the 200-tag Instrument-heavy variant for parse and writer commit. CI fails on >5% regression vs baseline. Targets per §6.6 v0.2.
6. **Offset-table footprint micro-bench** — measures `OffsetTable` arena-bytes (raw `entry[]` + hash overlay separately) for representative messages (Logon, NewOrderSingle, NewOrderList × {1, 10, 100} orders, MarketDataIncrementalRefresh × {10, 100, 1000} entries on 10-level books, `SecurityList` × {1000, 3000, 5000} strikes). The Phase 2 spike (§10 Q1) consumes this.
7. **Lifetime-trap test (debug build)** — construct a `MessageView`, rotate the originating arena's generation, access the view → expect trap. Also: confirm release builds *don't* trap (UB is acceptable in release; we don't try to make it deterministic). Add a Clang `-Wdangling` smoke test that verifies the lifetimebound annotations actually fire on a known-bad capture pattern.
8. **Repeating-group equivalence** — for any group-bearing message, `group_view::iter()` and `group_view::operator[]` enumerate the same entries in the same order. Catches divergence between the two paths.
9. **Unknown-fields preservation** — generate messages with (a) intentionally-unknown tags (dictionary-missing); (b) dictionary-known-but-invalid-for-this-MsgType tags. Verify (a) the typed accessors see only typed tags; (b) `unknown_fields()` enumerates *only* the dictionary-missing ones; (c) the dictionary-known-invalid ones produce `error::wire_unexpected_tag` from the validator (v0.2 rule split per §6.5 rule 5); (d) round-trip writes the dictionary-missing tags back in original byte positions.
10. **Allocation guard (Linux)** — `tools/check_alloc.py` runs the `Framer → Parser<Index> → Validator → Writer → commit` loop under `mallocnesia`; any heap allocation between parse and commit fails CI. Verifies the §6.6 three-arena pinning. Same Linux-only caveat as 2a §9 seam #6.
11. **Fuzzer (libFuzzer)** — `tests/fuzz/fuzz_wire_framer.cpp`, `fuzz_wire_parser.cpp`, `fuzz_wire_validator.cpp`; ASan + UBSan invariants. Required by `[const §IX.4]`.
12. **CheckSum/BodyLength corruption corpus** — bit-flips in body, off-by-one BodyLength values, valid CheckSums on truncated frames, **explicit space-padded BodyLength** (`9=   123|`) frames (verifying the v0.2 `Framer` rejects them per `[FIX50SP2 §3.3]` `Length` data-type rule), and **XOR-checksum frames** (verifying the v0.2 byte-sum-mod-256 algorithm rejects them). `Framer` rejects each with the documented error.
13. **Three-arena pinning test** — construct `Framer`, `Parser<Index>`, `Writer` with three distinct PMR `monotonic_buffer_resource`s (carry, message, scratch); verify allocations land on the correct arena per §6.6. Reset each independently and confirm no use-after-reset on the others.
14. **Validator domain test** — feed messages with malformed *optional* fields (a wrong-type `Price`, an out-of-enum `Side`); verify `Validator::validate(msg)` rejects unconditionally — not contingent on any typed accessor having been called. Catches a regression to v0.1's per-accessor model.
