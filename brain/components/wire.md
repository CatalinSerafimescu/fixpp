## Why this page exists

`wire` is the **largest catalogue family — 116 rows**, more than the next three combined — and until
now had **no page**. Re-derive that standing with `python3 tools/brain_inventory.py --census`; the
number above is a snapshot and will rot, the *rank* is the durable part.

and **scanned clean** in the Step-R sweep (zero borrowed-claim markers, zero drop-in blocks).

## ⭐ The scope boundary — the most useful thing here

`wire` owns **wire-format mechanics**: bytes in/out, structural validity, and the index over a parsed
frame. It explicitly does **not** own three things people expect it to, and knowing that routes you
correctly on the first hop:

| Not owned by wire | Owned by | Why the confusion |
|---|---|---|
| **Field representation types** — decimal, integer, string, timestamp | `decimal<T>` from **2a**; `dict::field_traits<…>` from **2c** | wire *calls into* them, so they appear in wire stack traces |
| **Typed message classes** — `fixpp::v50sp2::NewOrderSingle` | generated by **2c** | wire supplies the `MessageView`/`OffsetTable` those wrap |
| **Session semantics** — sequence numbers, gap fill, ResendRequest, TestRequest | the session FSM (`2d`-adjacent + the session module's Phase-4 spec) | both operate on the same bytes |

## Locked decisions, and what each rejected

| Locked | The alternative it rejects |
|---|---|
| **Flyweight + caller-owned buffer** — views never own bytes; lifetime is the buffer's | owning views. Enforcement is *layered*, `[[clang::lifetimebound]]` being one layer, not the whole answer |
| **Hybrid offset table** — eager through the typed dictionary surface, lazy on the raw iterator | picking one. The access *intent* differs: random-access wants the index built, streaming does not |
| **Typed `group_view<T>` default, `.iter()` opt-out** | forcing group-index construction on streaming callers |
| **Opaque round-trip for custom fields**, `unknown_fields()` as a filtered view | materialising a vector — which would allocate, violating `[const §VIII.5]` |
| **`BodyLength` + `CheckSum` verified BEFORE the parser sees a frame** | parsing first and validating after. A frame that fails the envelope check never reaches the parser at all |

## The seam into the session layer

`wire_error_to_session_reject_reason` (`include/fixpp/wire/reject_reason_map.hpp`) maps a validator
error onto a FIX `SessionRejectReason(373)`.

⚠️ **The mapping values are deliberately NOT reproduced here** — read the header. What is durable is
its *shape*: it is a **total function with a defined fallback**, so an error outside the
validator-emitted set still yields a valid reject reason rather than an unmapped code escaping to the
peer.

## The constraint that shapes everything above

**Zero allocation between parse and `fromApp`** `[const §VIII.5]`, exception-free across the same
window `[arch §5.3]`. Most of the locked decisions — flyweight views, lazy offsets, filtered
`unknown_fields()` — exist to satisfy it. See
[`inbound-message-path`](./inbound-message-path.md) for how the read pump upholds it at runtime.
