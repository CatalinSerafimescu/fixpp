# Feature Specification: Harden doubly-nested repeating-group correctness (census disjointness + load guard + typed depth-≥2 context)

**Feature Branch**: `072-nested-group-hardening`

**Created**: 2026-07-12

**Status**: Draft

**Input**: Bundles GitHub issues **#180** (catalogue L-063-4 / L-062-3 — pin + guard the two structural dictionary conventions the nested-group read relies on) and **#183** (catalogue L-065-1 — the generated typed nested accessor threads the parent membership context *unpushed* on a nested descent, so a depth-≥2 member resolves under a too-short path). Both are latent-correctness hardening on the same doubly-nested-group surface; both are inert on every shipped dictionary today and require a constructed/dialect dictionary to trigger. Out of scope: the arena-exhaustion fail-loud seam (L-065-2 / #184) — that reopens a converged 065 design decision and is a separate round.

## Clarifications

### Session 2026-07-12

- Q: Where should the FR-003 nested==parent delimiter guard fire and throw — the `XmlLoader::load_*` load path, `Dictionary::as_table_view()`, or both? → A: **`XmlLoader::load_*`** — throw at the load path, reusing the existing throw-based load-error convention (a new distinct catchable typed `dict::` error), rejecting the offending dialect before any `table_view` is built and keeping `as_table_view()` allocation-only/non-throwing. The parent-chain walk needed to detect the collision (currently only performed inside `as_table_view()`) is added to the loader.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — A dictionary that violates the nested-delimiter convention is rejected at load, and the shipped dictionaries are pinned clean (Priority: P1)

The nested-group read machinery relies on two structural conventions of the shipped FIX dictionaries that are currently only asserted in prose ("no conforming dict declares it"), with nothing in the loader, `Dictionary::as_table_view()`, or the public `table_view` mutators enforcing them. A user who supplies a dialect XML — a fully public API — whose **nested group's delimiter (first_field_tag) equals its parent group's delimiter** feeds `OffsetTable::group_slices()`'s flat splitter a layout it mis-splits, silently corrupting the outer group's instance boundaries. This story converts that convention from unenforced prose into (a) a load-time **reject** for the dialect-XML path and (b) a permanent, CI-tripping **census assertion** that pins today's verified-clean state of the vendored dictionaries and trips if a future vendored-dict update (or a new version) breaks either convention.

**Why this priority**: This closes a reachable path from a public API (dialect XML load) to a silent wire-corruption bug (mis-split outer group). Silent mis-splits are the worst failure class for a wire library — the consumer cannot detect them. It is also the enabler for US2's witness: the same guard runs at load time on US2's constructed dialect, so the two stories must be designed together (the US2 witness dialect must satisfy this guard).

**Independent Test**: Load a hand-authored dialect XML whose nested group's `first_field_tag` equals its parent's and assert the load path rejects it with a catchable typed error and produces no usable view; separately, run the census assertions over all vendored group-bearing dictionaries and confirm they pass (0 delimiter collisions, 0 shared parent/child scalar members).

**Acceptance Scenarios**:

1. **Given** a dialect XML declaring a nested repeating group whose delimiter tag equals its immediate parent group's delimiter tag, **When** it is loaded through the public load path (`XmlLoader::load_from_string` / `load_from_file` → `as_table_view()`), **Then** the load path rejects it with a catchable typed dictionary error (consistent with the existing throw-based load-error convention), produces no usable table view, and does not crash, corrupt memory, or silently mis-split.
2. **Given** every vendored group-bearing runtime dictionary (the shipped `dictionaries/*.xml` set), **When** the delimiter-disjointness census assertion runs, **Then** it passes for all of them (0 nested==parent delimiter collisions), pinning today's Fable-audited clean state.
3. **Given** every vendored group-bearing runtime dictionary, **When** the parent/child scalar-member-disjointness census assertion runs, **Then** it passes for all of them (0 scalar-member tags shared between a parent group and its nested child), pinning today's clean state.
4. **Given** the shipped dictionaries (which satisfy the convention), **When** they are loaded through the guarded load path, **Then** they load unchanged — the guard is a no-op for every conforming dictionary.

### User Story 2 — A member of a grandchild (depth-3) nested group reads under its full parent path, not a frozen too-short one (Priority: P1)

The generated typed nested-group accessor descends into a nested group but re-wraps the **parent** entry's membership context onto the returned child view **unpushed** — it never pushes the nested group's own `no_tag` onto the *stored* context. The depth-1 accessor correctly seeds `[NoTag]` (`parser.hpp:309`), and passing the parent's own path to `nested_group_slices` is *correct* for slicing the immediate child — so a depth-2 group is sliced correctly. But the child view's **stored** context stays frozen at the parent's path, so the **next** descent — slicing a **grandchild (depth-3) group** — queries the grandchild's membership under a path one level too short. `as_table_view()` registered the grandchild's members under `(msg_type,[…parent,child],grandchild)`, but the frozen read queries `(msg_type,[…parent],grandchild)` → **misses** the context-scoped member store and degrades to the legacy bare-`no_tag` fallback (Defect-A-prone: silently resolves the *wrong* member set when the grandchild's count-tag is reused under a different membership elsewhere). This story fixes the **typed** path to push the nested group's own `no_tag` onto the returned view's stored context at the emitter's descent site, so a depth-≥3 member resolves under the full parent path — reconciling the typed path *up* to match 065's already-correct C-ABI cursor (which pushes on mint at `message_read.cpp:506`).

**Why this priority**: This is a pre-existing (062/063-era) latent silent-wrong-read on the typed public read API for genuinely triply-nested layouts. It is independent of, and equally load-bearing as, US1; both ship the "doubly-nested group correctness" chapter. The reconciliation direction matters: 065 recorded that the C-ABI is the *more-correct* side, so the obligation is to push the typed context, never to un-push the C-ABI cursor.

**Independent Test**: Using the real generated `v44::MassQuote` type — whose `NoQuoteSets(296)→NoQuoteEntries(295)→NoLegs(555)` chain is a shipped depth-3 nesting — driven by a **hand-built `table_view`** in which group `555`'s members are registered under the context path `(MassQuote,[296,295],555)` with the correct member set but under the legacy bare `no_tag` store with a *different* set, perform a depth-3 typed read of a `legs()` member and assert it resolves the context-scoped (correct) member. Mutation-prove the same witness is RED on the pre-fix (unpushed) emitter output (pre-fix reads the wrong bare-fallback member). The hand-built `table_view` never goes through `XmlLoader::load_*`, so this witness is **independent of US1's guard** — the two stories share no test fixture.

**Acceptance Scenarios**:

1. **Given** a `MassQuote` message whose grandchild group `555` has a context-registered member set at `(MassQuote,[296,295],555)` that differs from its legacy bare `555` registration, **When** a `legs()` (555) member is read via the typed accessor, **Then** it resolves under the full path `[296,295,555]` and returns the correct context-scoped member (not the bare-`no_tag` fallback).
2. **Given** the pre-fix (unpushed) generated flyweights, **When** the depth-3 witness runs, **Then** it is RED (resolves the wrong bare-fallback member under the frozen `[296]` path) — mutation-proven, so the witness genuinely discriminates the fix.
3. **Given** the same hand-built dictionary driven through the C-ABI nested read, **When** the depth-3 `legs()` member is read via the C-ABI, **Then** it already resolves correctly (065's `:506` push) and the post-fix typed read agrees with it — establishing typed≡C-ABI parity at depth-3 (SHOULD, if the C-ABI depth-3 witness is constructible on the hand-built dict).
4. **Given** every shipped dictionary (all inert for this defect — no shipped dict reuses a grandchild count-tag under divergent membership), **When** the full typed read + validation suites are recompiled against a **cleanly reconfigured** codegen output and run, **Then** runtime read results are byte-identical to pre-fix — the emitter change alters generated source at depth-≥2 descent sites but changes no shipped-dict runtime behavior.

### Edge Cases

- **US2 witness uses a real generated type + hand-built `table_view` (NOT an XML dialect), and is decoupled from US1's guard.** The typed accessors exist only for the four codegen-input dictionaries (v42/v44/v50sp2/vt11, generated into the build tree) — there is no way to XML-load an arbitrary dialect and get typed reads for it. So the discrimination witness MUST use a real generated type (`v44::MassQuote`, whose `296→295→555` chain is a shipped depth-3 nesting) driven by a **hand-built `table_view`** whose grandchild group `555` is registered with a *different* member set in the context store `(MassQuote,[296,295],555)` versus the legacy bare `555` store — so the pre-fix frozen-`[296]` read hits the wrong bare set and the post-fix pushed read hits the right context set. A hand-built `table_view` does NOT pass through `XmlLoader::load_*`, so US1's delimiter guard is never invoked on it. The earlier framing ("witness dialect must satisfy the guard") does not apply.
- **A 065-style production loopback witness may not be constructible for Part B.** Every shipped dict is inert for this defect and the typed layer is codegen-bound to shipped dicts, so an end-to-end dispatch-path loopback that both exercises the bug AND uses a real generated type likely cannot be built. Part B's proof therefore rests on the hand-built-`table_view` + real-type discrimination witness (typed, mutation-proven), with the C-ABI cross-check as a best-effort parity assertion, not a required dual witness.
- **Guard covers only the delimiter convention (L-063-4), not scalar-member disjointness (L-062-3).** The load-time reject enforces *nested delimiter ≠ parent delimiter* only. Parent/child scalar-member disjointness (L-062-3) stays **assertion-only** (census pin), NOT load-enforced — enforcing it at load would require a far broader membership cross-check and is out of scope. The asymmetry is intentional; the completeness gate must not read "guard the conventions" as "enforce both at load."
- **Guard entry point is the load / `as_table_view()` path only.** A dictionary built directly through the public `table_view` mutators (bypassing XML load) is NOT re-validated by this guard — that path remains the caller's responsibility (documented residual). The threat the issue names is primarily the dialect-XML path; the hand-built-`table_view` path is a smaller, explicitly-out-of-scope residual for this feature.
- **A dictionary with a nested==parent delimiter that some existing test loads.** If any current test or fixture loads/hand-builds a nested==parent-delimiter dictionary to exercise the old mis-split behavior, its failure mode changes under the guard (rejected at load) and it must be updated. (Confirm during planning.)
- **Minimum reproducing depth is depth-3 (not depth-2).** Reading a *scalar* member uses a first-occurrence wire scan, not membership context, so a depth-2 member read never exercises the bug; and slicing the immediate child (depth-2) group uses the correct depth-1-seeded path. The frozen path only diverges when slicing a **grandchild (depth-3)** group. The push fix is recursive by construction (each descent pushes its own `no_tag`), so depth-4+ inherits correctness from the same change; the witness targets depth-3 (the minimum reproducing depth), and deeper levels are covered by construction, not separate witnesses.

## Requirements *(mandatory)*

### Functional Requirements

**Part A — census pins + load-time delimiter guard (#180 / L-063-4, L-062-3)**

- **FR-001**: A permanent, CI-tripping census assertion MUST verify that no nested repeating group's delimiter (`first_field_tag`) equals its immediate parent group's delimiter. To avoid a **vacuous pass**, it MUST be derived from the **structural** loader group table (`LoaderState::groups_` / emitted `GroupRef` — `first_field_tag` + `parent_group_no_tag`), the same structural walk the FR-003 guard uses, which registers a group per raw `<group>` element **regardless of whether the count field is typed `NumInGroup` or `INT`**. This gives uniform coverage across all group-bearing runtime dictionaries — including FIX40/41/42, whose count fields are declared `INT` and therefore register **zero** groups under the `NumInGroup`-keyed `as_table_view()`/`census_for` derivation. The assertion MUST prove non-vacuous coverage (assert it observed > 0 groups for each dictionary it claims to cover). It pins today's verified-clean state (0 collisions) and trips on a future breaking vendored-dict change. It belongs with the existing 063 census (`tests/dictionary/reused_tag_census_test.cpp`).
- **FR-002**: A permanent, CI-tripping census assertion MUST verify that no scalar member tag is shared between a parent group and its nested child group, pinning today's verified-clean state (0 shared members) and tripping on a future breaking change. It MUST prove non-vacuous coverage (assert > 0 group member-sets examined per dictionary it claims to cover). Scalar-member disjointness is inherently membership-based; if the derivation cannot recover per-group member sets for the `INT`-typed-count dictionaries (FIX40/41/42), those three MUST be recorded as an **explicit unpinned residual** (FR-013 / catalogue) rather than allowed to pass vacuously as if covered.
- **FR-003**: The public XML load path (`XmlLoader::load_from_string` / `load_from_file`) MUST **reject** a dictionary in which any nested group's `first_field_tag` equals its immediate parent group's `first_field_tag`, surfacing a **new, distinct, catchable typed `dict::` error** thrown during load (consistent with the existing throw-based load-error convention — `trap_throw_or_throw`) [Clarification 2026-07-12]. Rejection MUST happen at load, before any `table_view` is built, and MUST fail the whole load (not silently skip the offending group). It MUST NOT crash, invoke UB, or silently mis-split. This is a deliberate behavior change (such a dialect previously loaded and mis-split silently). Detecting the collision requires a parent-chain walk in the loader (the walk currently lives only in `as_table_view()`); `as_table_view()` stays allocation-only and non-throwing.
- **FR-004**: The load-time guard's scope MUST be limited to the delimiter convention (L-063-4) only. Parent/child scalar-member disjointness (L-062-3) MUST remain assertion-only (FR-002) and MUST NOT be enforced at load in this feature. The asymmetry MUST be documented in the shipped behaviors-and-limitations catalogue.
- **FR-005**: The guard's enforcement point MUST be the `XmlLoader::load_*` path [Clarification 2026-07-12]. Two residuals MUST be documented as remaining caller responsibility (catalogue note), not silently implied as covered: (a) a `table_view` constructed directly via public mutators, or a `Dictionary` obtained without `load_*`, is not re-validated; (b) the loader group table (`groups_`) is **deduplicated globally first-seen-by-`no_tag`** (`expand_field_list`), so the guard checks the first-seen parent/delimiter relationship per `no_tag`, **not** a per-message-context one — a delimiter collision appearing only in a *non-first-seen* context of a reused `no_tag` is unguarded (the same L-063-3 first-seen-context residual). Both are acceptable for this feature (no shipped dict exhibits either), but MUST be recorded.
- **FR-006**: Every shipped runtime dictionary (`dictionaries/*.xml`) MUST continue to load unchanged through the guarded path — the guard MUST be a no-op for every conforming dictionary. The census assertions (FR-001/FR-002) pin that this holds.

**Part B — typed depth-≥2 pushed context (#183 / L-065-1)**

- **FR-007**: The generated typed nested-group accessor MUST push the nested group's own `no_tag` onto the **returned child view's stored** membership context, so the *next* descent resolves a grandchild group's members under the full path (`[…parent path…, child_no_tag, grandchild_no_tag]`) — matching how `as_table_view()` registers members. The fix site is the emitter's view-mint at `tools/codegen/fixpp-codegen/emit_messages.cpp:270-271` (which currently re-wraps `ctx_` verbatim as `group_view<G>{nested, ctx_}`); the emitted view's base context MUST become `ctx_` with `group_ctx = ctx_.group_ctx.pushed(<nested_no_tag>)`. **Two things MUST stay unchanged**: (i) the `nested_group_slices(...)` **call argument** stays `ctx_.group_ctx` (the parent's own path is the correct slicing context for the immediate child — the same argument the C-ABI passes); (ii) `group_view::operator[]` stays a verbatim `base_ctx_` copy — pushing there too would **double-push** the path. The depth-1 seed (`parser.hpp:309`) also stays unchanged (already correct). The push happens exactly once per descent, at mint.
- **FR-008**: The fix MUST push the **typed** path *up* to match 065's already-correct C-ABI cursor (`message_read.cpp:506` stores `parent->group_ctx.pushed(nested_tag)`). It MUST NOT un-push, alter, or regress the C-ABI cursor. Post-fix, the typed and C-ABI paths MUST agree at depth-3.
- **FR-009**: The generated flyweights are **not checked in** — codegen runs at CMake configure time into the build tree (`${CMAKE_BINARY_DIR}/_codegen/`), so the emitter change produces **no git-visible golden churn**. The emitter-source fingerprint (`cmake/Codegen.cmake`) MUST force a full re-generation on the next configure after the emitter changes; the fix MUST be verified by a **clean reconfigure** (delete `_codegen/`) so no stale generated header is compiled, followed by recompiling and running the typed-read + validation suites against the fresh output. The regen MUST change **no** shipped-dictionary runtime read behavior (the defect is inert on every shipped dict).
- **FR-010**: The strict validator's matching flat-context residual (catalogue L-063-3 — `validator.hpp` Step-3 group walk hardcodes `root_path = []`, so every nested-group membership lookup queries the root context and misses, one level worse than the accessor which at least pushes once) MUST be fixed to walk nesting-aware with a pushed context, so typed read and strict validation agree on depth-≥2 membership. This is the largest single sub-task and MUST be scoped/verified in its own right.
- **FR-011**: A **depth-3 discrimination witness** MUST exist using the real generated `v44::MassQuote` type (`296→295→555`) driven by a **hand-built `table_view`** in which grandchild group `555`'s member set differs between the context store `(MassQuote,[296,295],555)` and the legacy bare `555` store, so the pre-fix frozen-path read resolves the WRONG (bare) member and the post-fix pushed read resolves the correct (context) member. It MUST assert the correct depth-3 member post-fix and MUST be **mutation-proven RED** on the pre-fix emitter output. It SHOULD assert typed≡C-ABI agreement at depth-3 (FR-008) if a C-ABI depth-3 read is constructible on the same hand-built dictionary; a production dispatch-path loopback witness is NOT required (Part B is codegen-bound to shipped dicts, all inert — see Edge Cases).

**Cross-cutting**

- **FR-012**: The feature MUST NOT change the C-ABI (GA-frozen at `1.5.0`) — no exported C symbol, public C header, C error enum value, or C-ABI version constant may change. (Part B touches only the C++ typed path + validator + census; Part A touches only the loader/census.)
- **FR-013**: The shipped behaviors-and-limitations catalogue MUST be updated: L-063-4 and L-062-3 promoted from "unenforced convention" to "pinned (+ delimiter reject at load)"; L-065-1 and the L-063-3 validator residual promoted to "fixed"; and the following residuals recorded explicitly (not implied covered): (a) scalar-member disjointness is not load-enforced (FR-004); (b) a hand-built `table_view` / non-`load_*` `Dictionary` is not guarded (FR-005a); (c) the guard is global-first-seen, so a per-context delimiter collision in a non-first-seen context of a reused `no_tag` is unguarded (FR-005b); (d) scalar-member disjointness (FR-002) is unpinnable for the `INT`-typed-count dictionaries FIX40/41/42.

### Key Entities *(include if feature involves data)*

- **Group membership context (`group_context`)**: the `(msg_type, parent-group `no_tag` path)` under which a repeating group's members are resolved, produced by `as_table_view()` at dictionary-load time and carried on the parsed view. The defect (Part B) is that the typed descent fails to `.pushed(nested_no_tag)` this path; the fix pushes it.
- **Group delimiter (`first_field_tag`)**: the first declared field of a repeating group, used by the flat splitter to bound instances. Part A's convention/guard is about a nested group's `first_field_tag` colliding with its parent's.
- **Vendored runtime dictionary**: the shipped `dictionaries/*.xml` FIX dictionaries; the census (FR-001/FR-002) iterates every group-bearing one and pins them collision-free.
- **Hand-built discrimination `table_view`**: a `table_view` built directly via the public context-scoped (`add_group_member_ctx`) and legacy bare (`add_group_member`) mutators so that grandchild group `555`'s member set differs between the context store `(MassQuote,[296,295],555)` and the bare `555` store. Fed (with the real `v44::MassQuote` generated type) to the typed read path, it is the only vehicle that makes the Part B defect observable (RED pre-fix), since every shipped dict is inert. It does NOT pass through `XmlLoader::load_*`, so it never encounters Part A's guard.
- **Load-rejection inline-XML dialect (Part A)**: a small hand-authored XML declaring a nested group whose `first_field_tag` equals its parent's — loaded through `XmlLoader::load_*` to prove the guard rejects it. Distinct fixture from the Part B `table_view`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of the shipped runtime dictionaries load unchanged through the guarded path; the FR-001 delimiter census passes with **non-vacuous** coverage across all group-bearing runtime dicts (including FIX40/41/42, via the structural `groups_` derivation — each dict asserted to have observed > 0 groups), and the FR-002 scalar-member census passes for every dict it claims to cover (FIX40/41/42 explicitly recorded as unpinned residual, not counted as covered).
- **SC-002**: A dictionary declaring a nested delimiter equal to its parent delimiter is rejected at `XmlLoader::load_*` with a catchable typed error in 100% of cases (0 silent mis-splits), verified by a dedicated inline-XML load-rejection witness; the process does not crash or invoke UB.
- **SC-003**: A depth-3 typed read of a grandchild-group (`555`) member resolves under the full parent path `[296,295,555]` (0 wrong bare-fallback reads) on the hand-built discrimination dictionary; the witness is mutation-proven RED on the pre-fix emitter output.
- **SC-004**: On the hand-built discrimination dictionary, the post-fix typed read agrees with the C-ABI read at depth-3 (the typed path reconciled up to the C-ABI's already-pushed path; C-ABI unchanged) — asserted where the C-ABI depth-3 read is constructible on the same dictionary.
- **SC-005**: After a **clean codegen reconfigure** (build tree's `_codegen/` regenerated from the changed emitter, no stale header compiled), the shipped-dict typed-read + strict-validation suites produce byte-identical **runtime** results versus pre-fix, verified across at least the debug, sanitizer, and coverage build configurations (no golden-file diff exists — flyweights are build-tree only).
- **SC-006**: Zero change to the C-ABI versus the `1.5.0` baseline (ABI hygiene gate reports no exported-symbol / header / enum / version delta).

## Assumptions

- The load path signals errors by **throwing** typed, catchable dictionary errors (`dict::xml_*_error` via `trap_throw_or_throw`, per `include/fixpp/dict/xml_loader.hpp`); the FR-003 delimiter guard reuses this channel — a **new distinct typed `dict::` error** thrown during `XmlLoader::load_*` [Clarification 2026-07-12], not a return-based status. The seam is resolved to the load path (not `as_table_view()`), which means the loader must add the parent-chain walk that today lives only in `as_table_view()`; `as_table_view()` stays allocation-only and non-throwing.
- The 6 group-bearing shipped dictionaries satisfy both conventions today (Fable adversarial reachability audit 2026-07-08: 0 delimiter collisions, 0 shared parent/child scalar members); the guard and census are therefore no-ops / green for them. This was re-confirmed against `dictionaries/*.xml` while drafting.
- The generated flyweights are **build-tree only** (codegen at CMake configure time into `${CMAKE_BINARY_DIR}/_codegen/`); there is no checked-in golden, so the emitter change produces **no git-visible churn**. Shipped dicts do carry depth-≥3 nesting that the emitter touches (FIX44 `MassQuote` `296→295→555`; FIX41/42/43 inline nested groups), so the regenerated source *content* changes at descent sites — but runtime behavior is inert. The real hazard is a **stale `_codegen/` header** compiled into a sanitizer/coverage build → false green/red; the verify plan forces a clean reconfigure across configs (SC-005).
- The membership-aware extent machinery (062 `OffsetTable::nested_group_slices`, `build_nested_subview`; 063 context-scoped membership) and 065's C-ABI pushed-path cursor are correct and reusable as-is; Part B plumbs the *typed* path to match them, not re-derives membership.
- #184 (L-065-2 arena-exhaustion fail-loud) is explicitly out of scope and remains deferred to its own round (it reopens converged 065 Decision 6 / FR-009).
