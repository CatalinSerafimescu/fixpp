# Data Model: Dictionary-backed inbound receive parse (066)

No new wire/persisted data. This feature adds owned metadata members and threads a dictionary handle so inbound-derived views carry membership. Entities:

## Entity: Session inbound `table_view` (new, owned)

- **What**: the once-built dictionary metadata (membership predicate + field classification) the inbound `Parser` binds to. Built at `open()` from `cfg_.dictionary->as_table_view()`.
- **Lifetime/ownership**: a `Session` member with a **stable address** for the session lifetime (the dict-backed `Parser` ctor stores `std::addressof` of it — `parser.hpp:506`). Suggested shape: `std::optional<fixpp::dict::table_view> inbound_tv_`. Mirrors the owned `table_view` the strict validator already holds (`session.cpp:1173`); the two builds may later be shared, out of scope here.
- **Invariant**: never rebuilt **per message** (FR-002/FR-004). The address must be stable across a single `parse_and_dispatch_` call — the per-message `Parser` local (`session.cpp:316`) binds `std::addressof(*inbound_tv_)` only for that parse's duration; nested sub-views and clone/reify hold **owned** membership (not a borrow of `inbound_tv_`). It is built once when the dictionary is known (at `open()`, dictionary guaranteed non-null) and confined to the session's serialized-dispatch executor. `open()`-on-reconnect reseat: `inbound_tv_` is built once and **not reseated per message**. Confirmed (analyze 2026-07-09, read-it): `Session::open()` (`session.cpp:878`) is a one-time setup coroutine; reconnection is driven by a **separate** method `ReconnectFsm::drive_reconnect_attempt()` (`reconnect_fsm.cpp:104`) that does **not** re-invoke `open()` — so no reseat-during-parse hazard exists in the current architecture. (If a future `open()`-rebuild path is added, it must occur between, never during, parses — safe given strictly-serialized dispatch.)

## Entity: Inbound `MessageView` / root `OffsetTable` (behavior change)

- Gains a non-null `opaque_dict_` (→ the session `table_view`) + `group_member_fn_` + a root `group_context` (`{msg_type, path=[]}` seeded in the dict-backed ctor). Consequence: `OffsetTable::group()` uses membership-bounded extents (not `entries_.size()`), and the scalar-as-group delimiter check is live. Both the C-ABI reads and the C++ typed flyweights (which read membership from this same table via `entry_context`) become correct.

## Entity: Clone-owned `table_view` (new, owned)

- `fixpp_msg_clone` gains a **clone-owned** `table_view` member (alongside `owned_frame_`/`owned_view_`, `capi_internal.hpp:271-273`), built by copying the source view's membership via the **same** new internal `MessageView` accessor reify uses (mechanism (b)), with the clone's `MessageView` bound to it — so the clone reads groups identically to its source (FR-007). At clone time `fixpp_msg_clone(src)` holds `src`'s live dict-backed inbound view, so the accessor has membership to copy — **no** inbound-handle `dict_`-threading and **no** rebuild from a retained dict. (Clone stays `dict_`-free, as today at `message_write.cpp:439`; the pre-existing `dict_` field, `capi_internal.hpp:261-266`, serves outbound validation and is untouched.) The clone's arena already uses `new_delete` upstream (owning handle), so this owned build is within contract.

## Entity: Reify owning handle owned `table_view` (new, owned) — mechanism (b)

- `owning_message_handle` (`reify.cpp` pimpl) carries an **owned copy of the source view's membership** (a `table_view`) so its lazily-re-framed `view_cache_` is dict-backed (FR-007), rather than the current 2-arg dict-free re-frame.
- **Mechanism (b), decided at Gate A**: the membership is propagated by a NEW internal accessor on `MessageView` — the **same** accessor clone uses — that returns an **owned copy of the membership source** (the source view's `table_view`). A copied `table_view` is self-contained and safe to outlive the source session/`Dictionary` — `include/fixpp/dict/table_view.hpp:185-192` (copy ctor "duplicates the owned tables"), `:204,221` (its accessor spans "alias storage **owned by this table_view** (stable for lifetime)") — so no `shared_ptr<const Dictionary>` pin is required. The factory `detail::owning_message_handle_from_frame(rmv, view, mr)` (`reify.hpp:87`) copies that owned membership into the handle and re-frames with the **dict-backed** `MessageView` ctor bound to the owned copy's stable address. This changes **no public `reify(...)` signature and no factory signature**, and therefore does **not** touch the codegen dispatch emitter (see plan.md).
- **Accessor precondition**: it re-concretizes the source view's type-erased `opaque_dict_` (`void const*`) back to a `table_view` (`*static_cast<fixpp::dict::table_view const*>(opaque_dict_)`), so it yields membership only when the source view is dict-backed (`opaque_dict_` non-null — sound because every production dict-backed parse binds a real `table_view`, research.md:13 census). A dict-free source (`opaque_dict_` null) yields no membership → an empty copy → the clone/reify stays dict-free (the correct degenerate case).

## Reused, unchanged (FR-005)
- `Parser` dict-backed ctor; `OffsetTable::group()/consume_group_extent/nested_group_slices/build_nested_subview`; `as_table_view()`; generated flyweights; `Dictionary`. Membership-walking **algorithms** unchanged — 066 only changes which parser the session/clone/reify use. Note: **not** "signatures unchanged" — 066 adds a NEW internal accessor (the `MessageView` membership-copy that returns an owned `table_view`, used by **both clone and reify**) plus an owned `table_view` on the reify owning handle and a clone-owned `table_view` (both populated by copying the source view's membership via that same accessor — mechanism (b)); those are new *internal* surfaces. No **public `reify(...)` / factory / C-ABI** signature changes.

## State transitions
None new. `inbound_tv_` is built at `open()` and read (address-bound) by every subsequent parse; destroyed with the Session. Per-message membership state remains the existing per-message-arena `mutable` caches inside the (now dict-backed) `OffsetTable`.
