## User Scenarios & Testing *(mandatory)*

The "users" of this feature are **(a) the application developer embedding the engine** (who passes a `std::unique_ptr<MessageStoreFactory>` to `SessionConfig::store_factory` and is otherwise unaware of the store), **(b) the deferred `005` session FSM** (which consumes the 4-method seam to satisfy `[FIX-SL §4.8]` recovery), **(c) the C-ABI / SWIG / Python downstream** (which observe the async surface translated by `2i` / `2m`), and **(d) the QuickFIX migrator** (who replaces a sync `quickfix::MessageStore` impl with an async `fixpp::session::MessageStore` impl per the §4.8.A.3 migration recipe).

### User Story 1 - Persist and recover raw FIX frames across host crash (Priority: P1)

The application picks `FileStoreFactory` at session open. Outbound frames are persisted **after** `Writer::commit` finalises BodyLength + CheckSum and **before** `transport::async_write` is issued (root cause #1 ordering). Inbound frames are persisted **after** `Parser` succeeds and **before** `fromApp`/`fromAdmin` is invoked. The session host is killed with SIGKILL mid-trading. On restart, opening the same `FileStore` with the same `<sender>__<target>` triple sees every successfully-`pwrite`+`fdatasync`'d frame intact, byte-identical, with the torn record (if any) at the tail truncated cleanly. The session can replay over any `[begin, end]` range (with `end == 0` meaning "to infinity") for `[FIX-SL §4.8.3]` `ResendRequest` recovery and `[FIX-SL §4.8.5]` `SequenceReset-GapFill`.

**Why this priority**: This is the locked promise of the whole design (`[FIX-SL §4.8]` recovery + `[2a §10] Q3` raw-frame confirmation + `[const §XV.15]` no-loss-of-session-messages). Without it, every other story is decorative — the FSM has no recovery substrate, the QuickFIX migrator has no replacement, the C ABI has no wrapped handle to expose. Crash-survival + byte-equality is the single load-bearing invariant.

**Independent Test** (seams 1 / 2 / 3 / 8 / 10 / 17 — **via the scripted test-double FSM**; the "FSM-driven send/receive" framing is the test-double's, not `005`'s): `MemoryStore::store(seq, frame_bytes, dir)` × N then `retrieve(begin, end, dir, byte_collecting_visitor)` returns the same bytes in seqnum order. Same for `FileStore`, **including a fork-SIGKILL-reopen variant** under `commit_per_message` (zero loss), `commit_batched(N)` (loss bounded by the half-batch window), and `commit_interval(ms)` (loss bounded by `ms`). Portable torn-write detection (Linux Tier 1 + Windows Tier 2): programmatically truncate the log mid-record, re-open, verify the truncated record is detected via per-record CRC32 and the log is truncated to the last whole record per the §6.3.2 restart algorithm.

**Acceptance Scenarios**:

1. **Given** a `FileStore` under `commit_per_message`, **When** the FSM persists 100 outbound frames (mixed-direction, 200–4096 byte payloads) then SIGKILLs the host, **Then** on restart `retrieve(1, 0, outbound, visitor)` walks all 100 frames in seqnum order with byte-identical content; no torn-tail truncation is performed (every record's CRC32 verifies).
2. **Given** a `FileStore` whose live log is mid-record-corrupted (last record's body truncated by N bytes), **When** the store is opened, **Then** the restart algorithm detects the bad CRC32 at the last record's offset, truncates the file to that offset, `fdatasync`'s the truncation, and rebuilds the in-memory index from the surviving records; no crash, no UB.
3. **Given** an outbound frame whose `BodyLength` digit count grows 2 → 3 at `Writer::commit` (forcing the `[2b §4.5]` `memmove` backpatch), **When** the FSM calls `store(seq, committed_span, outbound)`, **Then** the persisted bytes carry the **finalised** BodyLength digits AND the CheckSum byte — never the pre-commit placeholder.
4. **Given** a peer issues `ResendRequest(begin=42, end=99)`, **When** the FSM walks `retrieve(42, 99, outbound, gap_fill_visitor)`, **Then** the visitor receives one awaitable call per persisted frame in seqnum order, sees a frame span stable across its own `co_await`, and the store **does not hold its writer mutex across the visitor's `co_await`** (a recursive store-mutating call from the visitor's awaitable does not deadlock).

### User Story 2 - Bounded resource use and operator-visible failure (Priority: P1)

The application running with `MemoryStore` under default `bounded(10_000)`-per-direction policy hits the cap; the next `store()` does **not** silently drop the oldest (which `[const §XV.15]` bans) and does **not** terminate. Instead it returns `expected_t::unexpected{store_capacity_exhausted}` and the session's caller-side backpressure policy (`block` / `disconnect_and_recover` per `[2d §4.5]`) decides the next move. An operator who mis-sizes `MemoryStore::Config` such that `(inbound_capacity + outbound_capacity) * max_frame_bytes` exceeds `EngineConfig::max_store_memory_per_session` (default 1 GiB) is **rejected at construction** by the engine's storage-DoS guard (round-2 N9 / C-R2-P1-3 close); they must either lower capacity, lower `max_frame_bytes`, or explicitly raise the cap to prove they sized for the worst case. The `FileStore` peer reports `store_io_failure` on disk full / hardware fault, with structured-log fields `{store_kind, direction, seq, file_path, errno}` for triage.

**Why this priority**: P1 because silent loss-of-session-messages is a constitutional bug (`[const §XV.15]`). The whole point of the store is to be the durable substrate the FSM stakes recovery on; a store that drops or terminates on contention defeats the recovery contract before it begins.

**Independent Test** (seams 4 / 11 / 15 / 19 — for the `flush_for_session_close()` durability cut): `MemoryStore` with `outbound_capacity = 100`, `policy = bounded`; 101st `store()` returns `expected_t::unexpected{store_capacity_exhausted}` and the entry-array index is unchanged. `unbounded` variant: 10⁵ frames stored without capacity error (no hard cap). Storage-DoS construction guard: `MemoryStore::Config` whose product exceeds the engine cap is rejected with `store_factory_failed` at `MessageStoreFactory::make()`. `FileStore::flush_for_session_close()` graceful-close drain: 32 frames stored under `commit_batched(N=64)` (half-batch), `Session::close(graceful)` invokes the hook outside phase 1's child timeout, re-open recovers all 32 frames byte-identical; `Session::close(terminal)` skips the hook per the Appendix D §D.2 contract and the 32-frame loss is the documented `commit_batched` window.

**Acceptance Scenarios**:

1. **Given** a `MemoryStore` at capacity, **When** the FSM calls `store(seq, frame, dir)`, **Then** the awaitable returns `expected_t::unexpected{store_capacity_exhausted}`, no entry is added, the writer mutex is released cleanly, and the in-memory index is unchanged.
2. **Given** a `MemoryStore::Config` with `inbound_capacity = outbound_capacity = 200_000` (worst-case ~97.7 GiB at 256 KiB `max_frame_bytes`), **When** the operator hasn't raised `EngineConfig::max_store_memory_per_session` above that worst-case, **Then** `MemoryStoreFactory::make()` returns `store_factory_failed` at construction; the session does not open.
3. **Given** a `FileStore` whose log directory has been unmounted (or whose disk is full), **When** the FSM calls `store(seq, frame, dir)`, **Then** the awaitable returns `expected_t::unexpected{store_io_failure}` and a structured-log event of `{store_kind: FileStore, direction, seq, file_path, errno}` is emitted at error level.
4. **Given** a `FileStore` under `commit_batched(N=64)` with 32 frames since the last batch boundary, **When** the engine drives `Session::close(graceful)`, **Then** the engine's Session-close sequencer dispatches `FileStore::flush_for_session_close()` via the `fixpp::session::detail::has_flush_for_session_close` concept-shaped non-virtual customization point (Opus N3-P2-1), the hook runs to completion outside phase 1's child timeout, all 32 frames become durable, and `store_cancelled` is NOT surfaced under graceful close.
5. **Given** the same `FileStore` under `commit_batched(N=64)` with 32 frames pending, **When** the engine drives `Session::close(terminal)`, **Then** `flush_for_session_close()` is **NOT** invoked and the 32-frame loss window is the documented `commit_batched` data-loss contract (§4.3.1).

### User Story 3 - Concurrent-writer, cancellation, and `reset()` atomicity under host crash (Priority: P2)

Two concurrent `store()` calls on the same store instance — a v1.0-invariant violation under both `per_session_strand` and `direct_executor` modes (the Session-layer `[2d §6.1]` debug-build assert catches it as front-line check) — **do not** receive `store_concurrent_writer`. The second arrival suspends FIFO-fairly on the per-instance `fixpp::sync::async_mutex` and proceeds when the first releases (Codex P1-5 fix; defence-in-depth against domain violations per Opus N2-P3-2). The writer mutex is `async_mutex` (`[const §XI.3]`), **not** `std::mutex` or `std::recursive_mutex` (`[const §XV.9]` no carve-out), and **not** an RW-mutex / `async_shared_mutex` (`[SYN §3.2 Q6b]` post-v1.0). Cancellation winning before any method's linearisation point completes the awaitable as `expected_t::unexpected{store_cancelled}` with **no state change**; cancellation winning after the linearisation point completes the awaitable normally with the operation's value and the new state is **durable** per §6.3 / the §6.3.5 platform durability primitives. A `FileStore::reset()` under SIGKILL is atomic at the `rename` boundary plus the platform durability primitive (Linux: parent-dir `fsync` MANDATORY; Windows: `MOVEFILE_WRITE_THROUGH` MANDATORY) — restart never observes a "reset returned success but the next open sees the old log" pathology.

**Why this priority**: P2 because the round-trip + capacity stories (P1) demonstrate the store is *useful*; this story demonstrates it is *safe* under the failure modes that historically eat data in synchronous QuickFIX-shaped stores (concurrent writes, mid-`reset()` crash, mid-cancel teardown).

**Independent Test** (seams 5 / 6 / 10 / 18 / 20): FIFO-fair concurrent-writer test under TSan + ASan with two coroutines hammering `store()` on the same instance, verifying both complete with `expected_t<void>{}` and neither sees `store_concurrent_writer`. Per-method cancellation-result-contract test: fire cancellation slot before linearisation point per method (`store`, `retrieve`, `next_seqnum`, `reset`), verify each awaitable completes with `store_cancelled`; fire after linearisation, verify normal completion. `FileStore::reset()` atomic-rename crash test: SIGKILL between (a) tmp-file open and tmp-file `fdatasync` → restart cleans `.reset.tmp`, sees old log; (b) tmp-file `fdatasync` and `rename` → restart cleans `.reset.tmp`, sees old log; (c) `rename` and parent-dir `fsync` (Linux only) → restart sees new log on most filesystems (or old log if rename was lost — log warning); each path lands a coherent restart state. Session shutdown ordering test: 100 in-flight `store()` calls + `Session::close(terminal)` under TSan + ASan, no UAF on `session_arena`. `store_seqnum_out_of_order` detection: drive `store(seq=5, …)` while `next_seqnum(outbound, false) == 1`, verify the awaitable returns the variant, entry-array unchanged, mutex acquired-then-released.

**Acceptance Scenarios**:

1. **Given** two coroutines invoking `store()` on the same `MemoryStore` concurrently from an `asio::thread_pool`, **When** both run, **Then** they serialise FIFO-fairly on the writer mutex, both eventually complete with `expected_t<void>{}`, neither receives `store_concurrent_writer`, and TSan reports no race.
2. **Given** a `FileStore::store()` whose `fdatasync` has not yet returned, **When** the caller cancels the awaitable, **Then** the awaitable completes with `expected_t::unexpected{store_cancelled}`, the frame is **not** persisted, the in-memory index entry is **not** advanced, and the writer mutex is released cleanly.
3. **Given** a `FileStore::store()` whose `fdatasync` has returned success, **When** the caller cancels the awaitable, **Then** the awaitable completes normally with `expected_t<void>{}` and the frame is durable; cancellation cannot un-do durability.
4. **Given** a `FileStore` with 5 mixed-direction frames, **When** `reset()` is called and the host is SIGKILL'd between the `rename` and the Linux parent-dir `fsync`, **Then** on restart the live log is either the old log (rename was lost) or the new log (rename was visible) — there is **no** observable "old frames + new counters" or "outbound truncated + inbound intact" intermediate state, and `reset()`'s awaitable did NOT return success (so the FSM retries on next open).
5. **Given** `store(seq=5, frame, outbound)` is called while `next_seqnum(outbound, false) == 1`, **When** the writer mutex is acquired, **Then** the verification `seq == next_seqnum(dir, false)` fails inside the critical section, the awaitable returns `expected_t::unexpected{store_seqnum_out_of_order}`, no slab memcpy / `pwrite` occurs, and the mutex is released.

### Edge Cases

- **Sequence overflow.** `next_seqnum(dir, increment=true)` when the current value is `seqnum_max` returns `expected_t::unexpected{store_seqnum_overflow}`, does NOT increment, and is **session-fatal**: the FSM surfaces this to user code (via `onLogout`-with-reason or a session-level error callback) so the operator chooses between `reset()` + `ResetSeqNumFlag(141)=Y` Logon (per `[FIX-SL §4.4.2]` / `[FIX-SL §4.4.3]`) or sticky session-fatal abort. The store does NOT autonomously reset.
- **`retrieve(begin=0, …)`.** Rejected with `store_seqnum_invalid` (FIX wire seqnums start at 1 per `[FIX-SL §4.1]`), before any visitor invocation.
- **`retrieve(begin, end, …)` with `end != 0 && end < begin`.** Rejected with `store_invalid_range`, before any visitor invocation.
- **`retrieve` over a never-persisted gap.** Returns `store_seqnum_gap` (unless the gap is at the trailing edge of `end == 0`, which is a normal end-of-store).
- **Visitor abort.** `retrieve_visitor::on_frame` returning `visit_result::abort` surfaces the visitor's `abort_error()` virtual return through `retrieve()`'s `expected_t<void>` (default impl returns `store_visitor_aborted`). The C-ABI maps this to the new `FIXPP_ERR_STORE_VISITOR` group (v0.3 / Codex C-R2-P2-3 split from `FIXPP_ERR_CANCELLED`).
- **Mid-traversal mutation.** If the writer mutex is dropped across the visitor's `co_await` and a concurrent `store()` advances the index past the tracked iterator, the next visitor call observes the new state **without UB** (frames already visited are not re-visited; iteration stops at the original `end`).
- **Cross-filesystem `.reset.tmp`.** `<...>.log.reset.tmp` is in the same directory as the live log so `rename` cannot fail with cross-device `EXDEV`; a future implementation that admits an external temp directory MUST reject cross-filesystem paths instead of falling back to copy.
- **Sentinel mismatch on open.** If the live log's sentinel record's `session_triple_hash` does not match the requested `<sender>/<target>` triple (foreign file or corrupted earlier session), `MessageStoreFactory::make()` returns `store_factory_failed`; recovery is the operator's choice.
- **Directory contention.** Two engines pointed at the same directory both writing the same `<sender>__<target>.log` — `FileStoreFactory::make()` takes an `flock` (Linux) / `LockFileEx` (Windows) advisory lock at open; the second opener gets `store_factory_failed`.
- **Stale `.reset.tmp` from a crashed prior reset.** On `FileStore` open, the restart algorithm unlinks any pre-existing `.reset.tmp` (the live log is the source of truth) before scanning records.
- **PMR poison on the recovery path.** If the visitor's caller-supplied `memory_resource` throws on allocation, the throw routes through `fixpp::core::detail::trap_throw` per `[2a §4.2]` (no terminate; `[arch §5.3]` `expected_t<T>` model) and surfaces as `expected_t::unexpected{store_visitor_aborted}`.

**Behavioural contract**

- **FR-015**: All four `MessageStore` methods MUST acquire the per-instance writer mutex (`fixpp::sync::async_mutex` per `[const §XI.3]`) on entry — including `next_seqnum`, whose counter read/increment serialises on the mutex (Opus N2-P2-2: the design retired the v0.2 "atomic fetch-add" wording). The mutex MUST remain `async_mutex` regardless of `SessionConfig::lock_policy` per `[const §XI.5]`. There MUST NOT be an `async_shared_mutex` / RW-mutex (`[SYN §3.2 Q6b]`) and there MUST NOT be a `std::recursive_mutex` transitional adapter (`[const §XV.9]` no carve-out).
- **FR-016**: A concurrent `store()` (or other mutating call) on the same store instance from outside the session serialisation domain MUST suspend FIFO-fairly on the writer mutex and proceed when the holder releases (Codex P1-5). The error variant `store_concurrent_writer` MUST NOT exist.
- **FR-017**: `retrieve` MUST acquire the writer mutex at entry to validate `begin`/`end` and snapshot the index, but MUST NOT hold the mutex across the visitor's `co_await`. Mid-traversal mutation MUST be detected and the next visitor call MUST observe the new state without UB (already-visited frames are not re-visited; iteration stops at the original `end`).
- **FR-018**: `store` MUST verify `seq == next_seqnum(dir, false)` inside the writer-mutex critical section after mutex acquire and before any slab memcpy / `pwrite`. On mismatch the awaitable MUST return `expected_t::unexpected{store_seqnum_out_of_order}` with no state mutation, and the mutex MUST be released cleanly.
- **FR-019**: `store` MUST take a deep copy of the `frame` span into store-owned storage **before** the awaitable's first suspension point per `[2b §6.4]` / `[2b §6.6]` (the wire-side per-message arena does NOT guarantee the bytes live past suspension). `retrieve_visitor::on_frame`'s span MUST be stable across the visitor's `co_await` but the visitor MUST NOT retain it past the awaitable's completion.

**Cancellation result contract**

- **FR-020**: Every method MUST honour the §6.1.4 per-method cancellation table: cancellation winning **before** the linearisation point MUST complete the awaitable with `expected_t::unexpected{store_cancelled}` and no state change; cancellation winning **after** the linearisation point MUST complete normally with the operation's value and the new state MUST be durable (FileStore: on disk; MemoryStore: in the entry array). The linearisation point per method is:
  - `MemoryStore::store`: entry-array index increment after slab memcpy (under writer mutex).
  - `FileStore::store`: successful return of `fdatasync`/`FlushFileBuffers` under `commit_per_message` (or successful `pwrite` under batched policies), under writer mutex.
  - `MemoryStore::next_seqnum(_, true)` / `FileStore::next_seqnum(_, true)`: counter increment under writer mutex (FileStore: counter-record `pwrite` + flush).
  - `MemoryStore::reset`: entry-array zero pass under writer mutex.
  - `FileStore::reset`: the `rename` of `<...>.log.reset.tmp` over `<...>.log` PLUS the platform durability primitive (Linux: parent-dir `fsync`; Windows: `MOVEFILE_WRITE_THROUGH`), under writer mutex.
  - `retrieve`: per-frame; each visitor invocation has its own linearisation boundary.

  `store_cancelled` MUST join `FIXPP_ERR_CANCELLED` at the C-ABI mapping (alongside `dispatch_aborted` and `clock_sleeps_cancelled` per `[2d §6.7]`).

### Key Entities

- **`MessageStore`** (S-011) — the 4-pure-virtual interface every store impl inherits from. Stores raw FIX frames as `std::span<const std::byte>`; carries no `Dictionary&`, no `decimal<T>` knowledge, no version dispatch. Lifetime owned by the `Session` via `unique_ptr`.
- **`MemoryStore`** (S-012) — in-memory `final` impl; bounded(10_000)-per-direction default; **test / embedded use only**. Sized for the lifetime of a single test run; production deployments use `FileStore` or a custom impl.
- **`FileStore`** (S-013) — file-based `final` impl; **production default**. Single append-only log per session with per-record CRC32 + atomic-rename `reset()` + mandatory platform durability primitives. Policy knobs: `commit_per_message` / `commit_batched(N)` / `commit_interval(ms)`.
- **`MessageStoreFactory`** — frozen-at-open factory consumed by `SessionConfig::store_factory`. `make()` returns `expected_t<std::unique_ptr<MessageStore>>` (N1).
- **`MemoryStoreFactory` / `FileStoreFactory`** — the two default factory impls shipped with v1.0.
- **`retrieve_visitor`** — awaitable per-frame visitor (root cause #2); one pure-virtual `on_frame` + one overridable `abort_error()` hook. Awaitable return shape lets the visitor's per-frame work suspend on its own async I/O without the store holding its writer mutex.
- **`direction_t`** — `inbound = 0` / `outbound = 1`; frozen enum; values reserved per `[const §X.4]`.
- **`seqnum_t`** — `using seqnum_t = std::uint32_t` placeholder; canonical type owner is the deferred Phase-4 session-module spec per §3.1 / §4.7 / §10 Q9.
- **`FileStorePolicy`** — `commit_per_message` / `commit_batched(N)` / `commit_interval(ms)`; data-loss window documented per policy.
- **`fixpp::session::detail::has_flush_for_session_close`** — concept (`requires`-clause) gating the engine-internal Session-close durability hook; the concrete `FileStore` defines `flush_for_session_close()`, `MemoryStore` does not, custom impls inherit the no-op default.
- **`fixpp::session::quickfix_compat::cfg_loader`** — config-file translation helper (`cfg_to_file_store_factory(path)`); **no runtime adapter**. Path B verdict per `[arch §11]` Q3.
- **`fixpp::core::error_code` `store_*` variants** — 10 variants under the `FIXPP_ERR_STORE_*` C-ABI prefix; mapped to four groups (`STORE_RUNTIME` / `STORE_CONSISTENCY` / `STORE_CONFIG` / `STORE_VISITOR`) plus `CANCELLED` per §6.7.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: **Round-trip byte equality.** For every `N ∈ {1, 10, 100, 10000}` and every `direction ∈ {inbound, outbound}`, `store(seq, frame_n, direction)` × N followed by `retrieve(1, N, direction, byte_collecting_visitor)` MUST produce a sequence of byte buffers byte-identical to the inputs in seqnum order — for both `MemoryStore` and `FileStore`. (Verifies S-011 / S-012 / S-013 / `[FIX-SL §4.8]` recovery contract.)
- **SC-002**: **Crash-survival recovery.** A `FileStore` host SIGKILL'd after 100 successful `commit_per_message` `store()` calls MUST, on restart, return all 100 frames via `retrieve(1, 0, dir, visitor)` byte-identical to the originals — with **0% data loss** under `commit_per_message`. Under `commit_batched(N)` and `commit_interval(ms)` the loss MUST be bounded by the per-policy documented window (no surprise loss outside the window).
- **SC-003**: **`reset()` atomicity under crash.** A `FileStore` whose host is SIGKILL'd at any point during `reset()` MUST, on restart, observe **either** the prior intact log **or** the fully-reset state — never a partial / mixed-direction / "old frames + new counters" intermediate state. `reset()`'s awaitable MUST NOT have returned success in the prior-state case (so the FSM retries on next open).
- **SC-004**: **Bounded resource use.** `MemoryStore::Config` whose product `(inbound_capacity + outbound_capacity) * max_frame_bytes` exceeds `EngineConfig::max_store_memory_per_session` MUST be rejected at construction with `store_factory_failed`. A `MemoryStore` at capacity MUST report `store_capacity_exhausted` on the next `store()` with no entry-array advance; no silent eviction; no termination.
- **SC-005**: **FIFO-fair concurrent writer; no `store_concurrent_writer`.** Two coroutines concurrently invoking `store()` on the same instance from an `asio::thread_pool` MUST both complete with `expected_t<void>{}` in FIFO-arrival order, neither receiving `store_concurrent_writer` (variant not defined), under TSan + ASan with **0** races and **0** UAFs.
- **SC-006**: **Cancellation result contract per method.** For each of the 4 methods, cancellation winning **before** the method's linearisation point MUST complete the awaitable with `expected_t::unexpected{store_cancelled}` and **0** state change; cancellation winning **after** the linearisation point MUST complete normally with the operation's value and the state MUST be durable per the §6.3.5 platform primitives.
- **SC-007**: **Hot-path zero global allocation.** `tools/check_alloc.py` post-link symbol scan + a 10⁴-message session run under `mallocnesia` MUST report **0** global-heap `new`/`delete`/`malloc` calls between parse and `fromApp`. `MemoryStore::store` MUST report **0** allocator calls under `bounded` policy after construction (tracking-PMR counter unchanged from baseline).
- **SC-008**: **Latency ceilings (warm cache, Linux/Clang/x86_64 Tier 1).** `MemoryStore::store(seq, 200-byte frame, outbound)` ≤ **200 ns**; 1 KiB frame variant ≤ **800 ns**; `MemoryStore::next_seqnum(dir, false)` ≤ **50 ns**; `MemoryStore::retrieve(100-frame range, visitor cont)` ≤ **8 µs**; `MemoryStore::reset` at default capacity ≤ **25 µs**. CI fails on > 5% regression vs the previous tagged release. `FileStore::store(commit_per_message)` soft ceiling ≤ **250 µs** (NVMe `fdatasync` floor); `FileStore::reset` soft ceiling ≤ **5 ms**. FileStore I/O-bound rows fail at > 2× regression.
- **SC-009**: **QuickFIX migration path complete.** The 5-step migration recipe in `book/migration_from_quickfix.md` MUST take a user from a `quickfix::MessageStore` subclass to a compiling-and-passing `fixpp::session::MessageStore` subclass in **0** uses of `<fixpp/session/quickfix_compat/sync_message_store_adapter.hpp>` (which does not exist). `cfg_loader::cfg_to_file_store_factory(path)` MUST read a representative QuickFIX `.cfg` and produce a `FileStoreFactory` whose `dir` matches the CFG's `FileStorePath`.
- **SC-010**: **Conformance.** A representative recorded FIX session corpus replayed through `MemoryStore` + `FileStore` MUST round-trip byte-identical (every persisted frame byte-equal to the original input).
- **SC-011**: **Test-seam count + breadth.** The feature ships **≥ 21** named test seams covering the design-doc §9 list (`[const §VII]` requires ≥ 10); the Windows variant of "FileStore portable torn-write protection" (seam 3) MUST run on the CI's Tier 2 MSVC matrix per `[const §II.3]`; the libFuzzer fuzzer (seam 21) MUST run under ASan + UBSan + TSan invariants per `[const §IX.4]`-extended.
- **SC-012**: **Cross-doc + catalogue hygiene — hybrid ownership.** By end of this feature's PR merge: `library/spec/coverage-index.md:76` lists `S-011, S-012, S-013, S-014`; OSS-002's `feature-catalogue.md` disposition reflects Path B; COM-009 gains the forward-compat note; `architecture.md` §11 Q3 reads `CLOSED in 2e v0.3`; `EngineConfig` carries the new `max_store_memory_per_session` field (default 1 GiB). By end of orchestrator's Gate-B-merge close-out (`pipeline.md` step 19): `feature-catalogue.md` rows S-011 / S-012 / S-013 Status `done` (S-014 stays `backlog` for `005`).
