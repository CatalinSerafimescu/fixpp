## Phase 3: User Story 1 — TLS-encrypted FIX session, end-to-end byte stream (Priority: P1) 🎯 MVP

**Goal**: Ship the v1.0 reference `TlsTransport` impl `asio_tls_transport` (per data-model E-9) + the default `asio_tls_transport_factory` (per data-model E-11). Operator opens an initiator session against a counterparty over TLS via ASIO + OpenSSL; the engine resolves the host, completes TCP, performs TLS handshake (consuming 011's `SslCtxConfig` + `verify_peer`), captures `peer_identity` by value into the session FSM, and exchanges FIX frames as a byte stream: inbound bytes → `Framer::feed`; outbound bytes ← `Writer::commit`. Zero heap alloc on the read-path completion-handler dispatch per `[const §VIII.5]`. The 15 `tls_*` variants from `[2g §6.6]` surface UNCHANGED via `transport_handshake_failed` diagnostic sub-reason per FR-012 + FR-034a.

**Independent Test** (per spec.md): With a stand-up counterparty (stub TLS responder presenting a valid leaf cert pinned in the initiator's `Pinset`), open a session in `mtls_pinned` mode via a freshly-constructed `asio_tls_transport`. Observe `async_connect` → `ConnectInfo`, `async_handshake` → `handshake_result.peer_id` carrying verified counterparty identity by value, and a Logon round-trip through `async_write` → counterparty → `async_read_some` parsed by `Framer::feed` without any heap allocation on the read-path completion-handler dispatch.
