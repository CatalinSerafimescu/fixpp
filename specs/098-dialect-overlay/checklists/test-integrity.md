## The equivalence oracle and its references

- [ ] CHK001 Is the append rule precise enough for every addition kind that two people writing one reference by hand produce the same file? [Clarity, Spec Terminology (Equivalent edited XML), research R-3] The cases to check are where each of these lands:
  - a new `<value>` among a field's existing values;
  - a field added to `<header>`, relative to the header's components and groups;
  - a container the base lacks, which is "appended to the root";
  - a new `fixr:code` in its code set.
- [ ] CHK002 Is a mechanical check required that each complete hand-written reference differs from its base only by insertions at container ends, in overlay order? One such check is a diff of base against edited whose hunks are pure additions, each just before a closing tag. Without such a check, a reference written to a different hand edit is trusted rather than caught. [Gap, Spec §FR-017(a), research R-10 (References)]
- [ ] CHK003 What shows that each reference was "written by hand from the base file and never derived from the merge"? T027 commits the references (T016, T017) in the same commit as the splice code (T025, T026), so the commit order cannot show which came first. Is an ordering, a separate earlier commit, or a recorded procedure required? [Assumption, Spec §FR-017, tasks T016, tasks T017, tasks T027]
- [ ] CHK004 Is the list of addition kinds closed, and the same everywhere it appears (FR-003, FR-004, W-1, T016 and T039)? FR-003's "new fields with any type the base loader accepts" can be read as one type or as every type. Is the intended coverage stated? [Consistency, Spec §FR-003, Spec §FR-017, contracts W-1, tasks T016, tasks T039]
- [ ] CHK005 Is the kind coverage each vendored base must carry the same in FR-017's list, research R-10's "Kind coverage", W-2, T017 and T039? Is the FIXT11 row's header-only scope stated to be enough for FR-019's FIXT.1.1 claim? [Consistency, Spec §FR-017, research R-10, contracts W-2, Spec §FR-019]

## The comparator

- [ ] CHK006 Is there an independent check that the comparator's declared store list is complete? W-0 asserts that the expected sets plus the reason-only entries equal the declared list. That compares the list with itself. The recipe that re-derives the list is a header comment, and nothing runs it. Is a test, a census or a named Gate B step required to show that every `table_view` data member, every `Dictionary` query field and every `*Ref` field is on the list? [Measurability, research R-10 §3, contracts W-0, tasks T013]
- [ ] CHK007 Can the reason-only and coupled entries be checked? Each carries a stated reason. Examples are `fixt_framing_*` as a function of `which_session_version()`, and the reverse pair map as the inverse of the forward map. Is it stated who checks, and how, that each reason is still true at the head? [Measurability, research R-10 §4, contracts W-0]
- [ ] CHK008 Does the raw-document census follow the loaders' document rules? The rules are: the first container of each name counts, a second `<field>` with the same name is silently dropped, and a repeated msgtype gives repeated message entries. A census that disagrees with the loader reports false differences or hides real ones. Is it stated which of these rules the census copies and which it deliberately does not? [Clarity, research R-10 §2, research R-3 (Containers), research R-4]
- [ ] CHK009 Is there a non-vacuity floor for the wrap-condition filter? The test works out from census sizes, in `finalize`'s order, which definitions fit in 16 bits. That is a second model of `finalize`'s order, and a definition outside the filter is silently not compared. Is it required that every definition is compared on a base whose table fits, and that the compared count is recorded? [Measurability, research R-10 (side-table index wrap), tasks T013]
- [ ] CHK010 Is it stated that before plan phase 5, W-1/W-2 do not compare the header store? Is it stated that they are re-run after T055 adds the `is_header_tag` entry, and that this re-run is the evidence for SC-001 on that store? [Clarity, research R-10 §3, tasks T055, tasks T058]

## Seeded mismatches and the patch helper

- [ ] CHK011 Does each W-1/W-2 row's seeded mismatch name its expected store in advance, as each W-0 seed does? "MUST give at least one difference naming its store" can be read either way: that store, declared in advance, or any reported store. Which addition or hunk each row removes is also unstated. [Measurability, contracts W-1, contracts W-2, Spec §SC-001]
- [ ] CHK012 For the empty-overlay rows, does a recipe show that every base has a removable field definition before the cells rely on one? It must be a field that no message, component, group, header or trailer references. This applies to each `kRuntimeDicts` file and to the Orchestra file. [Assumption, contracts W-2 (Empty overlay), tasks T018, tasks T040]
- [ ] CHK013 Is it stated what an empty-overlay row's seeded mismatch proves? It compares `load(base)` with an in-test copy, so it proves the comparator can report a difference at that base's scale. It does not prove that the row's overlay side went through the overlay path; that rests on the seam's counter equalling the prediction, and on M-17. [Clarity, contracts W-2 (Empty overlay), contracts arm table]
- [ ] CHK014 Does the patch helper have a positive row as well as the zero-match and two-match rows? In it, a hunk that applies once inserts exactly its lines before the block's last line, checked against a small hand-written expected text. Without that row, the helper could insert at the wrong line while both negative rows pass. [Gap, research R-10 (References), contracts W-2 RED (a), tasks T018]
- [ ] CHK015 Is the patch helper's line matching specified for the MSVC run? The Windows runners check out with `core.autocrlf=true`. `git check-attr text -- dictionaries/*.xml` shows `FIX44.xml` unset (`-text`) but `FIX50SP2.xml` and `FIXT11.xml` unspecified, so those two convert to CRLF there. The new patch fixtures carry no attribute. Is it stated whether matching ignores CR and how trailing whitespace is handled, so that a hunk matches the same places on every platform? [Gap, research R-10 (References), plan Technical Context (Target Platform)]
