## Shape caps

- [ ] CHK001 Does each cap value have a stated source? The values are 4 MiB, 32 levels, and new fields 1024, components 64, messages 64, Orchestra groups 64, code sets 256, enum values 4096 and references 8192. Three come from 2c §4.4.2. Are the others derived, or recorded as chosen? Does the code comment hold a recipe rather than the value? [Traceability, research R-5 (step 5 and the paragraph after the budget), Spec §FR-009]
- [ ] CHK002 Is each cap's boundary stated? Are exactly 4 MiB, depth 32 and an at-cap count of definitions admitted? Does W-3 pair every "cap + 1" row with an at-cap control? Today only the side-table rows have a just-inside control, and only the new-definition counts reach their cap, in SC-005's fixture. [Edge Case, research R-5 steps 1, 4, 5, contracts W-3 (R-5 guards)]
- [ ] CHK003 Is the depth unit defined? Does the root element count as level 1, and do non-element nodes count? [Clarity, research R-5 step 4]
- [ ] CHK004 Is the order of steps 5 and 6 consistent? Step 5 counts "**New** definitions only" in "one flat pass over the overlay document". Whether an overlay definition is new or matches a base definition is decided by step 6's classifier, which runs later. How does step 5 tell new from existing before that classifier runs? [Conflict, research R-5 steps 5–6]
- [ ] CHK005 Does the reference cap count a reference that matches an existing child, such as a Required promotion or an identical redeclaration, which the splice merges in place and does not append? "References added … to new and existing definitions alike" does not settle this. [Ambiguity, research R-5 step 5]
- [ ] CHK006 The depth walk runs on the parsed document, so the parse itself sees unbounded nesting within 4 MiB. Is the assumption recorded that pugixml's parse and its document teardown are not recursive, with a source or a measured case? [Assumption, research R-5 steps 2 and 4]
- [ ] CHK007 FR-009 says "MUST refuse a DOCTYPE or entity declaration". Is that mapped to each input form it covers? A DOCTYPE with an internal subset is refused after parse. What of an undeclared entity reference (`&x;`) with no DTD, and of the five predefined entities and character references? Is it stated which are refused, which are expanded and which are a parse error? [Clarity, Spec §FR-009, research R-5 step 3]
- [ ] CHK008 Is the base's lack of every cap stated on each surface where the base is user input? FR-011 scopes the caps to the overlay. Through the C ABI and TOML the host or operator also chooses the base path. Does L-098-3 say this, not only "the base load paths have no caps"? [Coverage, Spec §FR-011, data-model §D (L-098-3), research R-15]

## Expansion budget, step counter and side-table fit

- [ ] CHK009 Is the boundary of "passes its limit" defined, `>` or `≥`? A legitimate load ends with the counter equal to the prediction, and W-1/W-2 assert that equality, so a `≥` test would refuse every admitted overlay. Is the same boundary stated for the budget comparison ("exceeds the base's own total by more than the budget")? [Ambiguity, research R-5 (the step counter), Spec §FR-009]
- [ ] CHK010 Is "child node" defined the same way for the counter and for step 6? Both count "every child node" `expand_field_list`'s loop visits. Which node types exist depends on the parse flags: the base uses `load`'s flags, the overlay `parse_default | parse_doctype`. The splice also drops annotation, documentation and non-element nodes. Is it stated that both sides count the same node kinds? [Clarity, research R-5 steps 2, 6 and the step counter]
- [ ] CHK011 Is overflow behaviour stated for the arithmetic the bound rests on? The memo is called saturating. Do the requirements also say that the merged total, the base total plus the budget, and the smaller of the two cannot wrap? [Gap, research R-5 step 6 and the step counter]
- [ ] CHK012 Is the budget constant tied to its recipe by a check that can fail? The recipe runs step 6 over every vendored base, takes the largest total and rounds twice that up to a power of two. The code comment holds the recipe and the evidence file holds the value. Nothing stated re-runs it when a vendored dictionary is added or updated, so the constant can drift below the recipe's result. [Measurability, research R-5 (the expansion budget), tasks T024, tasks T028]
- [ ] CHK013 Does the arming rule state why its second term never changes the outcome of an admitted load? The rule is min(prediction, base total + budget). Is the claim that W-1/W-2's equality holds tied to the budget comparison running before the build on every overlay entry point, the string forms and `load_any_with_overlay` included? [Consistency, research R-5 (the step counter), Spec Clarifications (Gate A loop 2 round 1)]
- [ ] CHK014 Is the side-table fit condition defined exactly as the loaders' `static_cast<std::uint16_t>` and `std::min<std::size_t>(…, 65535U)` behave, so the check and the build cannot disagree at the edge? The edge cases are a start of exactly 65535 with a non-zero count, and a zero-entry definition whose start is 65536. [Clarity, research R-5 step 6 (side-table fit), research R-10]
- [ ] CHK015 Is the cycle check's coverage stated for every edge kind the loaders follow recursively? For XML these are component references and held groups; for Orchestra, `componentRef` and `groupRef`. Does the stated set include a group reached through the header or trailer, and an Orchestra group that references itself through a component? [Coverage, Spec §FR-010, research R-5 step 6]

## The whole DoS bound

- [ ] CHK016 Is a cost bound stated for each guard step's own work, not only for the build? Can a reviewer check that no step before step 9 is superlinear in the overlay's size? [Completeness, research R-5 steps 6–8a] The steps are:
  - step 6 walks the base plus the overlay;
  - step 7's level sets are "built only for the parents the overlay extends", which for a QuickFIX-XML header addition is every message;
  - step 8 matches among direct children;
  - step 8a runs the pair detection twice.
- [ ] CHK017 Is a total memory bound stated for the overlay path? [Gap, research R-5 step 7, Spec §FR-009] It would cover:
  - the pugixml DOM of a 4 MiB overlay and of the base;
  - step 6's memo;
  - step 7's level sets: each "no larger than the base's declared field count", times the number of parents;
  - the merged dictionary, whose entries the budget bounds.
- [ ] CHK018 Is the build's recursion depth bounded? `expand_field_list` recurses once per reference it follows. The step counter bounds steps, not stack depth, and the depth cap bounds element nesting, not the length of a reference chain. Is the longest reference chain an admitted overlay can create derived from the definition caps? Is it shown to fit the stack under ASan? [Gap, research R-5, contracts W-3 (expansion bomb)]
- [ ] CHK019 Does the bundle characterise how long an admitted overlay can take? The budget is "a safety bound, not a performance target", SC-003 asserts no wall-clock bound, and US2 names an unbounded document as a start-up DoS vector. Is the load time of an at-budget overlay on the largest vendored base measured once, or stated as unmeasured? [Gap, Spec US2, Spec §SC-003, research R-5 (the expansion budget)]

## Send path (FR-022)

- [ ] CHK020 Is the scope of the "O(1)" claim stated? It covers only the added branch: a bounds check and a bit test after a fixed-set miss. The fixed-set test before it stays a linear find over the fixed array. [Clarity, research R-7 (Decision), plan Technical Context]
- [ ] CHK021 Does the no-allocation argument for `[const §XV.1]` name everything the new branch touches: `inbound_tv_`, the path to it, and `is_header_tag`'s read of `header_bits_`? Is its recipe, the two `git diff` commands in T058, enough to show the branch cannot allocate? Does the record carry W-6's reason for having no counting-resource cell (such a cell cannot report a non-zero without a known positive)? [Measurability, contracts W-6 (Allocation), tasks T058, const §XV.1]
- [ ] CHK022 Is W-12's send-path pass condition consistent with `[const §VIII.2]`? The constitution's budget is a +5% slowdown, measured as a paired same-runner base-vs-candidate run, A-B-A-B, compared min per tree. W-12 says "no regression past the provisional band", which is CI's operational threshold and may be as high as +50%. [Conflict, contracts W-12, const §VIII.2]
- [ ] CHK023 Is it stated that the CI paired gate cannot see FR-022's cost? `bench/session/session_send_bench.cpp` has no row in `bench/ci-suite.txt`, and the paired `engine_send_bench` refuses its payload before a frame is built. That leaves the local verify run as the only evidence. Does the bundle name it as such, and give it the protocol `[const §VIII.2]` requires? [Gap, contracts W-12, tasks T095, const §VIII.2]
- [ ] CHK024 Does the measured case cover the path FR-022 adds? On a vendored dictionary the union equals the fixed set, so the bench runs only the miss, where `is_header_tag` returns false. Is the hit measured, meaning a dictionary-declared header tag beyond the fixed set, or argued not to cost differently? Is `[const §VIII.3]` ("a benchmark in the same PR") recorded as met by the existing bench? [Coverage, contracts W-12, research R-7, const §VIII.3]

## Cost to the existing load path

- [ ] CHK025 Is a before/after measurement of the plain `load` path required? 098 changes three things `XmlLoader::load` and `OrchestraLoader::load` run: the factored pair detection, the counter test at the head of every `expand_field_list` child loop (unarmed), and the new header-store visited-set walk. `bench/dictionary/xml_loader_bench` is a `paired` row in `bench/ci-suite.txt`, so `[const §VIII.2]` gates this cost. W-12 measures only the overlay ratio and the send path. [Gap, Spec §FR-001, research R-1, research R-7, const §VIII.2]
- [ ] CHK026 Is the growth in `table_view`'s memory footprint stated and measured? `header_bits_` adds a bit store to every `table_view`, and `bench/dictionary/table_view_footprint_bench` records footprint in bytes. [Gap, data-model §A.3, research R-7]

## SC-005 load-time ratio

- [ ] CHK027 Is SC-005's fixture specified well enough to reproduce the ratio? "The cap's maximum count of new definitions" covers fields, components and messages. Do the requirements say whether the fixture also saturates the reference and enum caps, which existing definitions it extends, and how its expansion compares with the budget? At present only the expansion count is to be recorded. [Clarity, Spec §SC-005, tasks T017, contracts W-12]
- [ ] CHK028 Is SC-005's denominator defined? Is `load(FIX50SP2)` timed at the same 098 head, which already carries the header walk and the counter test, or at `origin/main`? The two choices measure different things. [Ambiguity, Spec §SC-005, quickstart §6]
- [ ] CHK029 Is the timing method stated so that the ratio can be measured again? It should say whether the file read is inside the timed region, whether the page cache is warm or cold, and how many warm-up runs are discarded. It should also say why the median of five is used, given that the constitution's paired protocol compares min per tree. [Measurability, Spec §SC-005, contracts W-12, tasks T094, tasks T095]
- [ ] CHK030 Is step 7's level-set cost covered by any stated measurement? R-5 step 7 says "SC-005's fixture does not measure this cost", and a header addition builds a level set for every message. If it is not measured, is it recorded as an unmeasured cost with its bound recipe? [Coverage, research R-5 step 7, Spec §SC-005]

## Fuzzing

- [ ] CHK031 Is the `[const §VII.7]` disposition stated as what it is? The clause asks for "≥10 minutes on every PR". The bundle provides a seed replay in CI and one local 600-second verify run. Is that recorded as a residual with an owner, as in 097, and not as meeting the clause? [Consistency, plan Constitution Check, research R-11, const §VII.7]
- [ ] CHK032 Is a per-input time limit stated for the 600-second run, derived from the budget? Is a `timeout-` or slow-unit artifact part of the failure condition? The pipeline's pass is "exit 0 and no `crash-`, `leak-` or `oom-` artifact". libFuzzer's default per-input timeout is longer than the whole run, so a slow admitted input would use up the campaign without failing it. [Gap, tasks (pipeline step 12), research R-11]
- [ ] CHK033 Are `-max_len` and the RSS limit for the run stated against the overlay caps? Without `-max_len`, libFuzzer sizes inputs from the corpus, so mutation may never reach the byte-cap path, the entry caps or deep nesting. [Gap, research R-11, contracts W-11]
- [ ] CHK034 Does "both C++ entry points" in R-11 and T079 say which ones? The string forms of the two loaders skip the path form's bounded reader, which does step 1's cap + 1 read under its "never trust a `stat` size" rule. If only the string forms are fuzzed, that reader is never fuzzed. [Ambiguity, research R-11, tasks T079]
- [ ] CHK035 Does the harness's accepted-exception set name every type the overlay path can throw that is not an `xml_parse_error`? These are `xml_oom_error` (a `std::bad_alloc`) and `unknown_version_error` (a `std::runtime_error`). "Every throw must be one of the `dict::` error types" leaves unclear whether an allocation failure under the RSS limit is accepted. [Completeness, research R-11, contracts W-11]
