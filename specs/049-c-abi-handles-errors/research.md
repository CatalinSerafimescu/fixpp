# Phase 0 Research — C ABI Feature A (handles, errors, version)

All four spec-level scope forks were resolved at `/speckit-clarify` (see spec `## Clarifications`). This file records the remaining design-level decisions surfaced while grounding the plan against the live code + `[2i]`. There are **no open `NEEDS CLARIFICATION` items**.

## D-1 — `translate()` is an audited coalescing decision with explicit overrides (not a transcription)

**Decision**: Implement `fixpp_capi::detail::translate(fixpp::core::error) → fixpp_error_t` as one `switch` over the **116 `fixpp::core::error` enumerators** (highest assigned slot 131, holes at {2–9, 14–19, 70}), mapping each to its audited coalesced C code per the data-model E-3 decision table.
**Rationale**: `error.hpp` *recovers* the intended C code but **not uniformly** — only ~72 enumerators carry an inline `→ FIXPP_ERR_*` arrow; `store_*`/`session_*`/`tls_*` use grouped `← { … }` prose and the cancellation rows say "Joins FIXPP_ERR_CANCELLED". So the map is auditable from `error.hpp`, not a mechanical copy. Several groups are **deliberate Feature-A overrides** of the source annotation: `log_*` (annotated `→ C-ABI 1000–1004`), `otel_*` (`→ 1010–1011`), and `session_*` (grouped `← FIXPP_ERR_SESSION_*`) all map to `UNKNOWN`=2 here, because `[2i §4.3]` publishes **no `#define`** for the 1000–1099 log/otel block nor any session block yet — mapping to a non-existent constant is illegal (deferral L-049-2); `app_*` is annotated `→ reserved (future mapping)` and `out_of_memory` has no inline arrow, both also `UNKNOWN`=2. A `switch` (no `default`) lets `-Wswitch` flag any future un-mapped variant — the same totality discipline `error_message()` already uses (it ships 116 default-less arms today).
**Alternatives considered**: (a) a sparse lookup array indexed by `uint8_t` — rejected: holes (slots 2–9, 14–19, 70) + worse readability vs the documented prose; (b) per-domain translate fns — rejected: the coalescing is global and the single switch mirrors `error_message()`.
**`out_of_memory` (slot 1) decision**: map to `FIXPP_ERR_UNKNOWN (2)` (override — no inline arrow, no producing Feature-A function, and no dedicated cross-cutting OOM code in `[2i §4.3]`). A `switch(error)` cannot be call-site-dependent; domain-specific OOM (e.g. `dict_xml_oom`) already maps to its domain code (`DICT_OOM`). Settled — not an open item.

## D-2 — `translate()` and `strerror` live in `src/capi/`, not exported

**Decision**: `translate()` is engine-internal (`namespace fixpp_capi::detail`) in `src/capi/error.cpp`; only `fixpp_strerror` is exported. `fixpp_strerror` is realized as a `switch` returning static string literals; `default:` → "unknown error". [Realized implementation note: the `[2i §4.4]` "static table" description was superseded by a `switch`; the observable contract (zero-alloc, stable pointer, O(1), null-safe) is identical — `[const §X.1/X.2]` freeze the surface, not the impl body. The sparse 0–1204 layout (e.g. `BINDING_*` at 1200–1204) makes a flat indexed array impractical (~1160 null holes); the `switch` is the better fit.]
**Rationale**: `[2i §4.4]`: zero-alloc static table, returned pointer never freed, lifetime = binary. Keeping `translate()` unexported preserves §X.2 (the C consumer never sees `fixpp::core::error`). The nm gate confirms only `fixpp_*` are exported.
**Alternatives considered**: exposing a `translate` symbol — rejected (would leak an implementation detail + a non-`fixpp_` C++ symbol).

## D-3 — Forward-compat downgrade is a pure function; `engine_create` deferred (ratified)

**Decision**: `translate_for_consumer(fixpp_error_t code, uint16_t consumer_minor) → fixpp_error_t` compares the code's **introducing minor ordinal** (a `uint16_t`) against `consumer_minor`; if `introducing_minor > consumer_minor` it downgrades to `FIXPP_ERR_UNKNOWN (2)`, else passes through. It is unit-tested directly. The point that *records* `consumer_minor` (`fixpp_engine_create`) is **Feature B / `[2j]`** and is declared a named limitation (L-049-1 below).
**Rationale**: `[const §X.4]` keys the downgrade on the consumer's **published ABI minor version** and binds stability only at `MAJOR==1`. So a code born in this feature has **introducing_minor = 2** (the `.2` of C-ABI 0.2.0), **not** "1.0" — the GA major bump is a separate event from a code's introducing-minor ordinal. The downgrade table is "code → the `uint16_t` minor it first appeared in"; in Feature A this is seeded from `error_codes_v1.txt`'s introducing column (every current code = `2`). Since no codes are added in a *later minor* yet, the function is a verified no-op for current minor-2 codes when `consumer_minor=2`, and is exercised with a synthetic fixture: a code introduced at minor **3** is downgraded for `consumer_minor=2` while current minor-2 codes pass through (SC-006).
**Alternatives considered**: pull a minimal `fixpp_engine_create(major,minor)` stub into Feature A (clarify option 2) — **rejected by the user** at `/clarify` (bleeds Feature B / `[2j]` handle lifecycle in).

## D-4 — Decimal error-code re-numbering: mechanism + census (ratified)

**Decision**: Adopt `[2i §4.3]` master values. The provisional `#define`s currently in `include/fix/c_api/decimal.h` are **removed**; `decimal.h` includes `fix/c_api/error.h` so the canonical macros are the single source. `src/capi/decimal.cpp`'s local `map_error()` is replaced by the shared `translate()`. Because `decimal.cpp` references codes **by macro name** (`FIXPP_ERR_DECIMAL_INVALID`, etc.), the value change (10→800, 11→801, 3→6) flows through automatically; the work is moving the definitions + censusing every site that hard-codes the *numbers*.
**Census targets (must all move in lockstep — FR-011)**:
- `include/fix/c_api/decimal.h` (provisional `#define` block — remove).
- `src/capi/decimal.cpp` (`map_error` — delete, route to `translate()`). Note `decimal_overflow` (C++ slot 11) currently also maps to `DECIMAL_INVALID`; preserve that in `translate()`.
- `contracts/c_api_decimal.h` (the "byte-for-byte" contract copy referenced in `decimal.h`'s header comment) — reconcile or annotate.
- Any C-ABI test asserting the literal numbers `3/10/11` (tests/capi, tests/oracle, the Python decimal ctypes oracle). *(Census preview found the test static_asserts pin the C++ `uint8_t` slots — `transport==102` etc. — which are unaffected; the C-ABI numeric asserts must be hunted explicitly per `[[feedback_census_all_handrolled_scanners_before_scoping_parse_fix]]`.)*
**Rationale**: permitted pre-1.0 (codes are "provisional", major still 0); puts decimal in its proper `[800,899]` block and makes `[2i §4.3]` authoritative. **Invisible to the nm `abi-golden` gate** (it sees functions, not `#define`s) — so the renumber's safety net is `error_codes_v1.txt` + the enumerating test, not abidiff.

## D-5 — `export.h` is created fresh (no existing convention)

**Decision**: Add `include/fix/c_api/export.h` defining `FIXPP_API_EXPORT`: `__declspec(dllexport/dllimport)` under `_WIN32` (keyed on a `FIXPP_CAPI_BUILD` macro), `__attribute__((visibility("default")))` on POSIX, empty for the static-archive consumer.
**Rationale**: `[2i §4.3]`/`§4.5` headers `#include <fix/c_api/export.h>` and annotate exports `FIXPP_API_EXPORT`; the symbol does not exist yet. On POSIX the shipped artifact is the static `fixpp_capi.a` + the version-script-filtered test `.so`; on Windows Tier-2 the macro is what makes `fixpp_*` visible (the current test `.so` uses `WINDOWS_EXPORT_ALL_SYMBOLS`, but the *shipped header contract* needs the macro). Keep it minimal — no behaviour, just visibility.
**Alternatives considered**: CMake `generate_export_header` — rejected: it generates a header at build time, but `[2i]` wants a checked-in C-clean header in the public include tree; hand-rolled is simpler and reviewable.

## D-6 — `abidiff` layout-gate upgrade is NOT in Feature A

**Decision**: Keep the per-PR `abi-golden` gate as the **nm symbol-set check** it currently is; update only the golden symbol list (add 3 functions). Do **not** wire the full `abidiff` layout/type diff in this feature.
**Rationale**: the `abi-golden.yml` header comment states the abidiff upgrade is "the Phase-5 upgrade when the C-ABI surface is built out (CA-001..010)" and the suppr/golden/baseline files are retained as that hook. Feature A adds no new *struct layout* on the boundary (`fixpp_decimal_t` frozen; `fixpp_version_t` is new but a trivial PoD). The enum renumber is a `#define` change abidiff would not catch anyway. Defer the abidiff upgrade to the last CA feature / release gate; record here so it is not silently dropped. **(Carries forward as a CA-workstream item, not a Feature-A task.)**

## D-7 — Reentrancy classes are documented in-header + audited, not a runtime gate

**Decision**: Each public symbol carries a doc-comment reentrancy class using the `[2i §4.10]` taxonomy (`thread-safe` / `single-thread` / `requires-session-lock`). Feature A's three functions (`fixpp_strerror`, `fixpp_version`, `fixpp_library_version`) are all `thread-safe` (static table / value PoD). Completeness is a **discrete, independently-runnable** check (NOT folded into `check_capi_occupancy.sh`, which P2-5 re-specifies and which gates a different invariant): for every exported `fixpp_*` symbol it asserts the symbol's **doc-block** — the contiguous comment block immediately preceding the declaration — contains **exactly one** of the three class tokens (0 unannotated, 0 double-classed). "Token present anywhere in the file" is *not* sufficient; it must be the symbol's own doc-block.
**Rationale**: Article X §5 requires documentation per symbol; there is nothing to enforce at runtime for pure-functional accessors. SC-005 says "exactly one of the three" — so a presence-only grep would pass a symbol annotated with two classes, or one whose token is borrowed from neighbouring prose. The discrete exactly-one-per-doc-block check prevents both, and a future symbol landing un-annotated (FR-014 / SC-005).

## D-8 — `session_*` variants have no published C-ABI code → map to `UNKNOWN` now, publish the block in Feature B

**Finding (verified)**: `include/fixpp/core/error.hpp` annotates its ~18 `session_*` variants (slots 66–77, 116–121) as coalescing to `FIXPP_ERR_SESSION_REFUSAL` / `_FATAL` / `_REJECT` / `_LIFECYCLE` — **26 `FIXPP_ERR_SESSION_*` references in error.hpp, 0 in `[2i]`**. The authoritative master layout `[2i §4.3]` publishes **no session block**.
**Decision**: treat `session_*` **exactly like `log_*`/`otel_*`/`app_*`** (which `[2i §4.3]` also leaves unpublished and which this plan already maps to `UNKNOWN=2`): map `session_* → FIXPP_ERR_UNKNOWN (2)` in `translate()` now, with a `// no session-producing fn until Feature B; publish FIXPP_ERR_SESSION_* block there` comment. The `switch` stays **total** (`-Wswitch` satisfied). **No `[2i]` amendment in Feature A.**
**Rationale (the discriminating test)**: *does any Feature-A function produce a `session_*` error?* No — session lifecycle/send are Feature B. So `session_*` is structurally identical to the other unpublished groups, and `→UNKNOWN` is **unobservable** in Feature A (no consumer path reaches it). Publishing a real `FIXPP_ERR_SESSION_*` block (and amending `[2i §4.3]`) belongs to **Feature B**, where the producing functions live — allocating it here is the same scope bleed the user rejected for `engine_create` at clarify Q3. Feature B refining the arm to a real code is purely additive (and we're 0.x). Folding `session_*` into `THREAD_*` would be semantically wrong, so it is **not** done — UNKNOWN-then-publish-in-B is the chosen path.
**"Full enum now" consistency**: publishing exactly the blocks `[2i §4.3]` defines (data-model E-2) *is* the full enum — `[2i]` reserves no session range, so there is no Feature-A hole to fill. The session gap is `[2i]`'s to close in Feature B.
**Carried as**: L-049-2 (below). `/speckit-analyze` should confirm the enumerating test asserts `session_*`/`log_*`/`otel_*`/`app_*` → `UNKNOWN` **explicitly** as documented v1.0 behaviour, so a Feature-B change to those arms trips a test rather than silently shifting the surface.

## Named limitations (carried to the spec + behaviors-and-limitations catalogue at Polish)

- **L-049-1**: The forward-compat downgrade (FR-009) is implemented as a pure function but is **not yet wired to a live `consumer_minor`** — `fixpp_engine_create` (which records it) is Feature B / `[2j]`. CA-004 is "accessors + macros + downgrade rule"; the end-to-end binding lands in Feature B. The completeness audit must read CA-004 against this boundary, not flag it falsely-complete.
- **L-049-2**: `session_*`, `log_*`, `otel_*`, `app_*` C++ error variants map to `FIXPP_ERR_UNKNOWN` at the C ABI in v1.0 (no producing function on the Feature-A surface; `[2i §4.3]` publishes no code for them). Feature B publishes the `FIXPP_ERR_SESSION_*` block; log/otel/app remain reserved per `[2i §4.3]`.
- **(workstream, not L-)**: `abidiff` layout gate upgrade deferred to the final CA feature / release gate (D-6).
