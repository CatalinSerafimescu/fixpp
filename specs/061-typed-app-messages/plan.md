# Implementation Plan: Typed Application Messages — write shape-oracle + witness harness (061-slim)

**Branch**: `061-typed-app-messages` | **Date**: 2026-07-08 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/061-typed-app-messages/spec.md` (re-scoped 2026-07-08 per D3)

## Summary

Deliver a **5-exemplar write shape-oracle** for the typed-application-message workstream: a shared
`wire::body_builder` (group-capable, body-only serializer mirroring the C-ABI `OutboundAccumulator`
LIFO discipline), five hand-written exemplar builders in `fixpp::v44` spanning the hard write axes
(D flat-scalars, 8 flat-scalars, 9 group-free, **E simple+3-level-nested — pivotal**, AS multi-char+nested),
and a table-driven round-trip witness harness anchored to **static checked-in body-only QuickFIX
goldens** (non-tautological). Plus the FR-008 header-install packaging fix. The remaining ~28 OFFICIAL
builders are generated by the follow-on FR-015a feature; 061-slim is its prerequisite (the shape-oracle
+ `body_builder`), not its implementation.

## Technical Context

**Language/Version**: C++23 (fixpp library).
**Primary Dependencies**: existing generated flyweights under `fixpp::v44` (no codegen regen — read path
landed via 062/063); `wire::Framer`/`MessageView`/`OffsetTable`/`Parser<Index>` (5-arg dict-backed);
`wire::group_view` + generated `G_<n>` entry accessors (062/063); `decimal_t`; `core::fix_time`;
`core::expected_t`. Reference (read-only, to mirror): C-ABI `OutboundAccumulator` in `src/capi/message_write.cpp`.
**Storage**: N/A.
**Testing**: GoogleTest under `tests/session/` + a factored `tests/support/` read-scaffold (BeginString-
parameterized) + static goldens under `tests/session/golden/`; golden-diff via `tests/interop/support/golden_diff.hpp`.
QuickFIX-cpp (cloned reference engine) used **offline** to author the goldens, NOT at test runtime.
**Target Platform**: Linux (Tier-1) + Windows (Tier-2).
**Project Type**: single C++ library.
**Performance Goals**: N/A (correctness feature; builders are not on a measured hot path here).
**Constraints**: fail-closed atomic builders (INV-4); caller-provided output span (no per-call arena burn);
`body_builder` internal buffer = **fixed scratch capped at the C-ABI `kFrameCap` (3800 B), no
`memory_resource`** (pinned Gate A round 1; over-cap → fail closed); repeating-group grammar enforced —
non-empty + delimiter-first via author-supplied `delimiter_tag` at `commit()` (INV-5, mirrors the C-ABI
`validate_group_grammar`); canonical decimals (INV-3); body-only output, no framing tags 8/9/34/49/52/56/10
(INV-2).
**Scale/Scope**: 1 new `wire::body_builder` (header+TU) + 5 exemplar builders (3 new: 9, E, AS; 2 refactored: D, 8)
+ 1 witness harness + 5 goldens + 1 CMake install rule. Grouped/nested builders (E, AS) are the LoC-heavy part.

**Structure Decision**: single-library layout. The one architectural choice is placing `body_builder`
in the **wire layer** (`include/fixpp/wire/` + `src/wire/`) — it is a reusable serialization primitive
(FR-015a-generated builders will also call it), and wire→core/dictionary is layer-legal. Exemplar
builders stay in the existing 020 `session/business_messages` TU/header (session→wire is legal).
