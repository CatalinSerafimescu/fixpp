## User Scenarios & Testing *(mandatory)*

### User Story 1 - Build an outbound typed application message body (Priority: P1)

An application developer needs to build the business body of an outbound FIX application message — including group-heavy and nested-group messages — from typed field inputs, with fail-closed validation, producing a body the engine will frame (the engine stamps the session header and checksum trailer). The five exemplars span every hard write axis a codegen writer-emitter (FR-015a) must reproduce.

**Why this priority**: The write side is the gap — there is no codegen writer today and only 2 flat hand-written builders. The exemplars are the *shape-oracle* that pins FR-015a's generated goldens (mirroring how the read emitter is pinned by `contracts/generated_message.hpp`). Without a proven grouped/nested body-only builder, FR-015a has nothing to match.

**Independent Test**: For each exemplar, call its builder with typed field values into a caller buffer and assert the emitted bytes are the expected canonical body (`35=<MsgType>\x01` + business fields, no session header/trailer); assert invalid inputs / undersized buffer return a typed error and leave the caller buffer untouched.

**Acceptance Scenarios**:

1. **Given** valid typed field inputs and a sufficiently sized caller span, **When** the builder runs, **Then** it returns the body-only span leading `35=<MsgType>\x01` then business fields in canonical form, with no `8/9/34/49/52/56` header and no `10=` trailer.
2. **Given** an invalid input (empty required string, control byte in a field value, out-of-range char/side, unformattable decimal, malformed UTCTimestamp) or an undersized buffer, **When** the builder runs, **Then** it returns a fail-closed typed error and does not write to the caller buffer (atomic all-or-nothing, INV-4).
3. **Given** a grouped exemplar (E, AS), **When** the builder emits a repeating group, **Then** the `No<Group>` count precedes exactly that many correctly-ordered per-entry field sequences (delimiter-first), including nested sub-groups at the correct depth and the count-of-zero case.

---

### User Story 2 - Round-trip fidelity anchored to an external golden (Priority: P1)

A developer (and CI) needs assurance that each exemplar body (a) parses back through the inbound typed-read path to the exact seeded field values AND (b) matches independently-authored QuickFIX golden bytes — so the oracle cannot be quietly co-wrong with our own parser.

**Why this priority**: Round-trip alone is tautological; the external golden is what makes the exemplar a trustworthy shape-oracle for FR-015a. This is the load-bearing witness.

**Independent Test**: One table-driven harness per exemplar: seed table → builder → framer → **dict-backed `Parser<Index>::parse` (5-arg)** → typed flyweight → assert every seeded field (incl. nested group entries) reads back at its exact value; AND assert the body matches the checked-in QuickFIX golden (normalized decimal-by-value, non-deterministic tags excluded).

**Acceptance Scenarios**:

1. **Given** an exemplar's constexpr seed table, **When** its builder output is framed, parsed via the dict-backed path, and read via the flyweight, **Then** every read-back field — including E's `orders()[i].parties()[j].party_id()` and trailing-zero-normalised decimals — equals the seeded value.
2. **Given** an exemplar's builder output, **When** it is diffed against the checked-in QuickFIX-authored golden bytes, **Then** the business-field body matches (decimal-by-value, normalized/excluded tags), proving builder ⇄ external reference agreement.

---

### User Story 3 - Parse an inbound typed application message (Priority: P2)

An application developer receives an inbound exemplar message and reads its business fields with exact, correctly-typed values, and is told (fail-closed) when a required field is missing or malformed.

**Why this priority**: The read path is the shipped surface exercised by the round-trip harness; for the exemplars it is proven with an independently hand-authored inbound wire (not builder output) so read and build are cross-checked.

**Independent Test**: For each exemplar, hand-author a wire body, frame it, parse via the dict-backed path, wrap in the typed flyweight, and assert each accessor returns the exact expected value; assert a missing required field yields the correct typed error.

**Acceptance Scenarios**:

1. **Given** a well-formed inbound frame for an exemplar MsgType, **When** parsed and wrapped, **Then** every business-field accessor returns the exact wire value (discriminating, not "parse succeeded").
2. **Given** a grouped exemplar frame, **When** parsed via the dict-backed path, **Then** group entry count and at least one per-entry field (incl. a nested entry for E) read back at their exact wire values.

---

### User Story 4 - Typed message headers consumable by external clients (Priority: P2)

An external consumer of the installed fixpp package needs to `#include` the generated typed application-message headers and use the `fixpp::v44::<Msg>` flyweights — today those generated headers are not on the installed public include path.

**Why this priority**: §XVIII.7 states the typed-message scope "ships in v1.0"; that is only true if the generated headers install. This packaging fix installs the whole `_codegen` tree regardless of builder count, so it belongs here (orthogonal to the 5-vs-33 exemplar count) rather than being deferred into FR-015a.

**Independent Test**: Configure/install the package and, from a consumer outside the build tree, include a typed-message header and construct a flyweight over a parsed view — it compiles and links against the installed tree.

**Acceptance Scenarios**:

1. **Given** an installed fixpp package, **When** an external translation unit includes a typed application-message header, **Then** it resolves from the installed include path (not a build-tree-private path).

---

### Edge Cases

- **Nested repeating groups**: E's `NoOrders(73) → NoPartyIDs(453) → NoPartySubIDs(802)` (3-level) and AS's nested groups — LIFO open/close depth, per-entry field ordering, count-of-zero at each level.
- **Multi-character MsgType**: `AS` — builder emits the 2-char `35=AS`; read dispatch resolves the flyweight (length-first path, 057-unblocked).
- **Decimal canonicalisation**: trailing-zero equality (`190.50` == `190.5`), no scientific notation, locale independence.
- **Buffer-boundary**: builder output that exactly fills, or overflows, the caller span — fail-closed on overflow, buffer untouched.
- **Missing/empty required fields**: read side returns typed error; build side rejects.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The system MUST provide a shared internal **`wire::body_builder`** (new header + TU) that lifts the feature-020 `wfield`/`wchar`/`wdecimal` helpers out of the `business_messages.cpp` anonymous namespace and adds a repeating-group write API **mirroring the C-ABI `OutboundAccumulator` LIFO discipline** (`group_begin(NoXXX)/add_entry/entry_set_*/entry_group_begin/group_end`, accumulate-then-serialize so the `No<Group>` count precedes entries, delimiter-first per INV-4). It MUST NOT reuse `wire::Writer` (which injects `8/9/10`) and MUST NOT invent a third group-write idiom.
- **FR-002**: For each of the **5 exemplars** (D, 8, 9, E, AS — all `fixpp::v44`) the system MUST provide a hand-written typed **builder** emitting the application **body only** (leading `35=<MsgType>\x01` then business fields; NO session header tags `8/9/34/49/52/56`, NO `10=` trailer — INV-2). D and 8 are refactored onto `body_builder` from their existing 020 implementations; 9, E, AS are new. Each builder is a **representative shape-oracle**, not full-field: it sets all required fields + enough optional fields to exercise every field *type* present (string/char/int/decimal/UTCTimestamp) and the full group/nesting *shape* — NOT every optional field (the 020 "minimal fields" precedent).
- **FR-003**: Builders MUST validate inputs fail-closed and be atomic: on any invalid input (empty required string, control byte / out-of-range char, unformattable decimal, malformed UTCTimestamp) or insufficient caller buffer, return a typed error and leave the caller buffer untouched (INV-4). Enum/char domains are **hand-validated per exemplar** (the 020 precedent); generic enum-range tables are out of scope (→ FR-015a).
- **FR-004**: Numeric/decimal fields MUST be serialised canonically via `decimal_t::format`: locale-independent, no scientific notation (INV-3).
- **FR-005**: The grouped exemplars' builders (E, AS) MUST emit repeating groups — `No<Group>` count then the correct number of correctly-ordered per-entry sequences, including nested sub-groups at the correct depth and the count-of-zero case.
- **FR-006**: For each exemplar the system MUST provide a **round-trip witness anchored to an external golden**: (a) builder output → framed → **dict-backed `Parser<Index>::parse`** → flyweight → assert every seeded field (incl. nested group entries) equals the builder input; AND (b) the builder body diffed against **static checked-in body-only QuickFIX-authored golden bytes** (uniform in-submodule mechanism for all 5 exemplars — e.g. `tests/session/golden/`; each golden authored once via QuickFIX-cpp, incl. re-deriving D & 8 as body-only in-submodule files rather than consuming the parent `phase-9-harness/BM-*` full-frame transcripts). The diff is decimal-by-value with non-deterministic tags normalized/excluded, reusing the `tests/interop/support/golden_diff.hpp` precedent; no live-QuickFIX runtime dependency in the unit harness. A pure build→parse round-trip without the external anchor is explicitly insufficient.
- **FR-007**: For each exemplar the system MUST provide an independent inbound **read witness**: a hand-authored wire body (NOT builder output) → framed → parsed via the dict-backed path → flyweight → asserting the EXACT typed value of each read field (incl. ≥1 group entry, and a nested entry for E), plus a missing-required-field → typed-error assertion.
- **FR-008**: The system MUST install the generated typed-message flyweight headers (`_codegen/include/fixpp/{v42,v44,v50sp2}/…`) onto the public installed include path (`_dispatch` and `vt11` excluded), and MUST verify consumability from an external translation unit outside the build tree.
- **FR-009**: The feature MUST NOT modify the codegen writer-emitter path (that is FR-015a) and MUST NOT introduce new wire-format, error-enum, or C-ABI surface beyond the `body_builder` + exemplar builder declarations and the header-install change. (The typed flyweights already exist; the read path needs no codegen change post-062/063.)
- **FR-010**: On completion, the 5 exemplar rows' evidence MUST be recorded in `spec/feature-catalogue.md` / `spec/coverage-index.md` (with the exemplar builder + witnesses as evidence); rows remain `backlog` for *full* coverage until FR-015a closes them. `spec/behaviors-and-limitations.md` MUST record the new B-/L- entries (incl. the v42-no-typed-groups limitation). §XVIII.7 MUST be amended per the D7 decision (drop stale C-/R- v1.0 typed-scope; FR-015a is no longer "post-v1.0").

### Out of Scope

- **The remaining ~28 OFFICIAL builders** (all non-exemplar A/M/P messages) — generated by the follow-on **FR-015a** feature, not hand-written here. 061-slim delivers only the 5 exemplars as the shape-oracle.
- **FR-015a itself** — the codegen writer-emitter. 061-slim is its prerequisite (the shape-oracle + `body_builder`), not its implementation.
- **v42 (market-data) grouped/nested writes** — blocked by the verified finding that v42 codegen emits zero typed groups; expressing grouped market-data messages is an **FR-015a prerequisite** (v42 group codegen), not 061-slim work.
- **FR-015b** — all-version coverage.
- **N-002 / N-003** (`BE/BF`, `BW/BX/BY`) — require session-FSM dispatch; a separate later feature.
- **A-014..A-034** typed accessors — deferred to v1.x per §XVIII.7; runtime `view.get(tag)` already ships.

### Key Entities

- **Exemplar**: one of the 5 fixed messages (D, 8, 9, E, AS in v44) chosen to span the hard write axes; the write shape-oracle for FR-015a.
- **`wire::body_builder`**: the shared, group-capable, body-only serializer (LIFO group API mirroring the C-ABI accumulator) used by all exemplar builders.
- **Typed flyweight**: the already-generated zero-copy `fixpp::v44::<Msg>` wrapper over a parsed dict-backed `MessageView`, exposing typed `expected_t<T>` accessors (incl. `group_view` entry accessors, 062/063).
- **External golden**: checked-in QuickFIX-authored wire bytes an exemplar body is diffed against (the non-tautological anchor).
- **Witness**: a discriminating test (read, round-trip, golden-diff) asserting exact field values.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: All 5 exemplars (D, 8, 9, E, AS in v44) ship a `body_builder`-based builder, an independent inbound read witness, and a round-trip witness; every exemplar builder body matches its checked-in QuickFIX golden.
- **SC-002**: 100% of read and round-trip witnesses are discriminating (exact field values, not "parse succeeded"); E and AS assert nested group-entry fields and the group count at each level; the count-of-zero case is exercised.
- **SC-003**: The grouped exemplars (E, AS) prove a **body-only grouped/nested builder** end-to-end — a capability no builder had before — as a shape-oracle FR-015a can regenerate against.
- **SC-004**: An external consumer translation unit, built against the installed package, includes a typed application-message header and constructs a flyweight — compiling and linking with no build-tree-private path.
- **SC-005**: No regressions — the Tier-1 sanitizer/analysis matrix is green — and no new public wire-format, error-enum, or C-ABI surface beyond the `body_builder` + exemplar declarations and the header install.
