# Phase 0 Research — Strict-Validation-Path Residual Closeout

All decisions below are corroborated against current on-disk source (site map from the 081 Explore pass, file:line cited).

## D-1 — Concern A merge SITE: a validator-private framing surface built in `Dictionary::as_table_view()`

> **Gate A round-1 refinement (2026-07-19):** the `/clarify` decision — "merge the FIXT.1.1 header/trailer into the validation view; single pass against the merged view" — STANDS at the observable level. Gate A round-1 (Opus RC#1 / Codex F1) refuted the *merge target*: the earlier design widened the **shared `valid_` store**, which `table_view::field_valid_for` also feeds into the inbound parser's `unknown_fields()` classification (`parser.hpp:582–584`), so it would have changed parser behavior even with strict validation OFF. Only the merge target moves — from the shared `valid_` store to a **validator-private framing surface** on `table_view` that the parser never reads. This is a refinement of the merge mechanism, not a reversal of `/clarify`.

**Decision**: In `Dictionary::as_table_view()` (`src/dictionary/dictionary.cpp` ~:376–382), for empty-header versions {v50, v50sp1, v50sp2} ONLY, populate **two new validator-private members** on `table_view`:
- `fixt_framing_tags_` — a set of the FIXT.1.1 standard header/trailer tags, consulted by the validator's Step-1 unexpected-tag gate IN ADDITION to `valid_tags_for(msg_type)`.
- `fixt_framing_types_` — a `tag → field_type` map for those framing tags, consulted by the validator's type-check arm for a framing tag before falling back to `field_type_of`.

Both are read ONLY by the validator. The shared `valid_` store, `field_valid_for` (`table_view.hpp:259–263`), `valid_tags_for` (`table_view.hpp:273–276`), `types_`, and `field_type_of` (`table_view.hpp:398–401`) stay **byte-identical**.

**Validator wiring** (accept-only, no `builder_validate.hpp` / hot-path enforcement change):
- Step-1 gate `validator.hpp:170` `if (!valid_tags.contains(fld.tag))` → `&& !dict_.is_fixt_framing_tag(fld.tag)`: a framing tag passes Step-1 instead of `wire_unexpected_tag`.
- enum check `validator.hpp:176` `dict_.enum_valid(fld.tag, …)` is **global-by-tag** — already reached for free once Step-1 accepts (see D-2).
- type check `validator.hpp:183` → `check_field_type` → `field_type_of(tag)` (`validator.hpp:467`) resolves a framing tag's type from `fixt_framing_types_` first, so a malformed numeric header field hits the Int arm (`validator.hpp:501–520`) instead of the String default (see D-2).

**Rationale**:
- **Parser-unchanged — the load-bearing invariant (FR-009/FR-010).** `valid_`, `field_valid_for`, `valid_tags_for`, `types_`, and `field_type_of` are byte-identical. The inbound parser's `unknown_fields()` classification (`parser.hpp:321–347` via `classify_fn_` → `field_valid_for`, `parser.hpp:582–584`) is therefore unchanged **whether strict validation is on or off** — because framing acceptance lives entirely in the separate validator-only members `fixt_framing_tags_`/`fixt_framing_types_`. This is pinned **directly** — `field_valid_for(msg_type, T)`/`valid_tags_for(msg_type).contains(T)` stay false for each framing tag `T` while `validate()` accepts it (a `valid_` re-widening flips `field_valid_for` to true → RED) — NOT by an `unknown_fields()` strict-on-vs-off comparison, which is near-vacuous here (see D-7): `inbound_tv_` is built flag-independently at `session.cpp:992`, so a both-sides `valid_` widening classifies identically on and off. (Corrects the earlier "`as_table_view()` feeds ONLY the runtime validator / sole-consumer" claim: `inbound_tv_` at `session.cpp:992` is *also* the inbound parser's dictionary, `session.cpp:328` `Parser<Index> pd_parser{*inbound_tv_}`, and `field_valid_for`/`valid_tags_for` share the `valid_` store — two consumers, not one.)
- **Golden-safe (FR-009).** No golden consumes `as_table_view` at all (codegen and read/reify goldens read `message_fields()`/`field_ref()` directly). Adding validator-private members changes no golden. Merging instead in `xml_loader::finalize()` (:915–920) would alter `message_fields()` → change the v50sp2/vt11 **read** goldens. Rejected.
- **Perf-safe (Article VIII) — setup-time, not hot-path.** The validator holds `dict::table_view` **by value** (`validator.hpp:112–113`, `dict_{std::move(dict)}`); `as_table_view()` is invoked at **session setup, up to twice** — `session.cpp:992` (`inbound_tv_`, unconditional, feeds the parser; it computes-but-ignores the framing surface) and `session.cpp:1234` (`dictionary_driven_validator`, only when `validate_inbound_messages` is enabled). Never per-`validate()`. The framing-surface population is a bounded setup-time addition at those two construction sites; no `validate()` hot-path delta, no perf-baseline move, no in-PR bench required beyond the existing `validator_bench`.

**Alternative rejected — dual-dictionary at validate time** (resolve a second app dict by `DefaultApplVerID`, validate against FIXT11 + app dict, QuickFIX's literal `Session.cpp:1218` model): rejected at `/clarify` — introduces session/version-resolution plumbing into the validator and a two-dict test harness for no observable benefit over the merged view.

## D-2 — Concern A merge SOURCE: baked FIXT.1.1 framing tag set, census-pinned to FIXT11.xml

**Problem**: `as_table_view()` has only the current `Dictionary` (one XML document); the FIX50SPx documents' `<header/>`/`<trailer/>` are empty. The header/trailer *membership* lives only in `dictionaries/FIXT11.xml` (its `<header>` carries ~32 field rows, `<trailer>` the rest). **SC-001 requires standalone operation**: a consumer that loads only `FIX50SP2.xml` (no FIXT11) must still get accepting behavior.

**Decision**: Bake the FIXT.1.1 **standard header + trailer framing set as a `tag → field_type` table** — a static constant in the dictionary layer (alongside `kVersionTable`/`kFieldTypeTable` precedent) carrying both the tag AND its structural datatype. In `as_table_view()` for versions `v50`/`v50sp1`/`v50sp2`, populate `fixt_framing_tags_` (the tag keys) and `fixt_framing_types_` (the tag→field_type map). A **non-circular census test pins the constant exact-set-equal to `dictionaries/FIXT11.xml`'s `<header>`+`<trailer>` field tags AND each tag's datatype** (mapped through the canonical `field_data_type → field_type` reduction, `field_type.hpp`), so FIXT11.xml stays the single source of truth and drift is impossible without a RED test.

**Rationale**:
- **SC-001 forces an internal source.** A lazy-load of vendored FIXT11.xml is infeasible: the library has no runtime path to `dictionaries/` and the consumer may hold only `FIX50SP2.xml` — so lazy-load cannot satisfy standalone acceptance. Rejected.
- **Drift-safe.** FIXT.1.1 is a frozen protocol (it does not version), so a baked constant cannot go stale; the census pin makes the FIXT11.xml→constant equality a CI-enforced invariant (mirrors the "census pins the shipped artifact" discipline).
- **Full header set, not just 6.** The framing set is the entire FIXT.1.1 header+trailer tag set (8/9/34/49/52/56 + the rest, incl. session-version tags like ApplVerID(1128)/ApplExtID(1156) that a conforming FIXT app frame may legitimately carry in its header, + trailer 10), so no conforming header field is false-rejected. Tags 8/9/10 are **not framer-skipped**: they reach the validator's Step-1 (Step-1 walks from byte 0 and the framer does not strip them from the validated bytes; tag 8 is the pre-fix reject site), so they are genuinely part of the acceptance set — the exact-set census (D-2 above) mandates them.
- **Enum comes for free; TYPE does NOT — must be baked (RC#2/F2).** The two halves are asymmetric:
  - `enum_valid(tag, …)` (`validator.hpp:176`) is **global-by-tag** off the existing enum store — for a framing tag whose codeset the app dict's `<fields>` defines, the enum check applies for free; where it defines none, the empty-codeset accept-floor applies. No extra wiring.
  - `field_type_of(tag)` (`table_view.hpp:398–401`) is populated **only** by walking `message_fields()` (`dictionary.cpp:535–548`). The empty-`<header/>` framing tags are defined in `<fields>` but attached to no FIX50SPx message, so they were **never** `set_field_type`'d → `field_type_of` defaults them to `field_type::String` (`table_view.hpp:398–401`), which imposes no structural constraint. Once accepted at Step-1, `34=abc` / `1156=abc` would then hit the String arm and be **false-accepted** — violating FR-011.
    Fix: `fixt_framing_types_` carries each framing tag's real datatype from the authoritative `<fields>` definition. Verified against source: `34`=SEQNUM→`Int`, `1156`=INT→`Int` (both reject non-digit values at the Int arm, `validator.hpp:501–520`); `52`=UTCTIMESTAMP→`String` (`field_type.hpp` explicitly reduces `UtcTimestamp → String`, so a malformed SendingTime is *structurally undetectable* to the Phase-1 validator — 52 is an accept-only tag, not a malformed-reject tag). The validator's type arm resolves framing tags via `fixt_framing_types_` first (safe: they are never message-attached in these dicts, so no collision with `types_`).
- **Type-resolution precedence.** For a framing tag the validator consults `fixt_framing_types_` before `field_type_of`; for every other tag, behavior is identical to today.

**Gating**: read `version_` from `dict_metadata_handle` (`xml_loader.cpp` `kVersionTable` :157–188; stamped on the handle) inside `as_table_view()`; populate the framing surface iff version ∈ {`v50`,`v50sp1`,`v50sp2`}. FIX40–44/FIXT11/vlatest untouched.

## D-3 — Concern B loader threading: enclosing-group required-ness gates member-record

**Root cause (both loaders)**: the per-group required-member record is gated on `group_scope_component_required` (the 079 component-AND accumulator), **not** the enclosing group's own `required=`. The group's own required-ness (`greq`) is computed at the `<group>`/`<fixr:groupRef>` branch but used only for the message-level count and the outer-group pair; the recurse INTO the group discards it (passes `group_scope_component_required=true`). Sites:
- `xml_loader.cpp` `expand_field_list` (:522) — member record :571–573; recurse drops `greq` (:658–660).
- `orchestra_loader.cpp` `expand_field_list` (:509) — member record :545–547; `greq` at :592, recurse drops it (:634–636).

**Decision**: Thread the **enclosing group's own required-ness** down into the recursion as a new gate on the `group_required_pairs_out.emplace_back(...)` call in both loaders, symmetric (same fix both files, one pass). A direct `required='Y'` member is recorded per-group-required **only if its direct enclosing group is required** — mirroring QuickFIX `addXMLGroup` (`if (required=="Y" && groupRequired) addRequiredField`).

**Ancestor composition — DECIDED NOW: immediate-enclosing gating (not ancestor-AND).** (Gate A round-1 N1: this was previously deferred to the golden, risking a circular oracle.) The rule is not open — QuickFIX `addXMLGroup` documents it: a direct member is required iff `required=="Y" && groupRequired`, where `groupRequired` is the **immediate enclosing group's own** `required=`, reset one level per recursion (mirrored by `xml_loader.cpp`'s `group_scope_component_required` reset-at-boundary precedent from 079 Gate B). So the gate is the direct enclosing group's `required=`, **NOT** an AND across ancestor groups. The reworked census oracle (`required_scope_oracle.hpp`) encodes this rule **independently, computed from the raw XML** — it does not derive the rule from the loaded tables or the parity golden. The quickfix-cpp 1.16.0 parity golden **CORROBORATES** (cross-check), it does not **DEFINE** the rule — keeping the census non-circular ([[feedback_verification_corpus_built_from_the_read_it_checks_is_blind]], [[feedback_noncircular_census_projection_source_stops_pinning_shipped_classes]]). The 24 divergent contexts collapse to 0.

**`consume_group` unchanged (D-3a)**: `validator.hpp:264` `consume_group` consumes the per-group store; relaxing the store (fewer entries) automatically relaxes enforcement with **no `validator.hpp` edit**. The 079 fail-closed dynamic-width mask logic stays. This is a deliberate no-touch of the hot-path validator.

## D-4 — Concern B codegen gating: `emit_builders.cpp` per-entry required checks

**Root cause (Gate A round-1 RC#2/F3 — deeper than "thread a flag into the shared trait")**: group entry plans are **interned by `(no_tag, delimiter, structural-signature)`** (`emit_builders.cpp:648–649` `intern.intern(gm.tag, nested->delimiter_tag, signature, …)`), and `compute_signature` (`emit_builders.cpp:251–282`) folds in each member's **own** `required` bit (line 269) and each nested group's `group_required` bit (line 261) — but **NOT the enclosing-usage required-ness**. So a structural group `G_X` used *optional* in message A and *required* in message B interns to the **same** plan and shares one `writer_traits<G_X>::required_checks` array (emitted once at `emit_writer_traits_for_level`, :723). A single shared trait cannot enforce required members for B and skip them for A — "thread a flag into the shared trait" is structurally incoherent: the axis it needs (enclosing-usage required-ness) does not exist on the plan identity.

**Decision — fork the group-plan identity by effective enclosing-group-required-ness.** Include the enclosing group's own `required=` in the plan interning identity / `compute_signature`, so a mixed-usage structural group forks into two distinct plans: a `required`-usage plan (populated `required_checks`, `group_check.required=true`) and an `optional`-usage plan (empty `required_checks`, `group_check.required=false`). This is the emitter analogue of D-3, using the same immediate-enclosing gating rule so the typed tier agrees with the runtime tier (FR-007). Regenerate the typed **validator** goldens (D-6). Present **nested** groups inside an optional fork still validate via their own forks (each already carries its own `group_required` at signature line 261), so nesting is handled correctly with **zero `builder_validate.hpp` change** — pure codegen + typed-validator goldens, exactly Concern B's declared surface.

**OVERRULED alternative — gate at the parent's `validate_entry_` call site** (skip `validate_required(child[i])` for an optional group): **incorrect** (Opus RC#3/F3). `validate_required` also recurses into *present nested-child instances* (`builder_validate.hpp:80–93`), so skipping it under-validates nested groups inside a present optional group — QuickFIX still validates those, gated on the nested group's own `required=`. It also touches `builder_validate.hpp`, a runtime header this bundle lists as untouched (plan.md) — scope expansion, and unnecessary. The identity-fork location is the **decided** approach; the earlier "confirm-at-implement" hedge on the injection point is removed.

**Bounded dedup impact.** The fork affects only structural groups used in **both** a required and an optional context **and** carrying `required='Y'` members; all other plans are unchanged. Measure the exact plan-count delta at `/implement`. The identity fork affects **validator emission only** — read/reify goldens stay byte-identical (read membership is required-ness-independent).
