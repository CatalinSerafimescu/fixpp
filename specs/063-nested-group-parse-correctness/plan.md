# Implementation Plan: Nested Group-Parse Correctness (063)

**Branch**: `063-nested-group-parse-correctness` | **Date**: 2026-07-07 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification + [research.md](./research.md) (Phase-0, incl. census + codegen-union discovery)

## Summary

Fix two pre-existing, `main`-resident defects that break multi-instance / tag-reused nested repeating-group reads against the **real** dictionary, so grouped typed reads (and feature 061) are correct via `Dictionary::as_table_view()`:

- **Defect A — loader group-membership collision.** The XML loader registers repeating-group membership globally, first-XML-occurrence-wins, keyed by the `NumInGroup` tag (`xml_loader.cpp:486`). A reused tag (e.g. FIX44 295) resolves to the wrong variant → `group_member_fn(295, delim=299)` fails `group()`'s acceptance check (`offset_table.cpp:433`) → group reads empty. **Census (research §Pivotal): systemic — 12 (FIX44) … 22 (FIX50SP2) colliding tags/dict; parent-group key insufficient.**
- **Defect B — non-nesting-aware extent.** `OffsetTable::group()`'s flat `seen_in_instance` boundary heuristic (`offset_table.cpp:450-459`) truncates an outer instance at the 2nd entry of a nested group → multi-entry nested reads return too few entries.

**Chosen approach (Gate A Round-1 resolved):** **Defect A = Option A — exact context-scoped membership**, resolved runtime by the key **`(msg_type, bounded parent-no_tag-path, no_tag)`** (msg_type mandatory: MassQuote vs MassQuoteAck share the full path `root→296→295`). Option B (union-per-no_tag) was **rejected as unsound for the parser**: `OffsetTable::group()` uses membership to define the byte slice (`offset_table.cpp:433`/`:447`), so a union false-positive is swallowed into the slice, and the census cannot bound the risk under order-independent acceptance (B-004-1). **Defect B = an allocation-free, depth-capped (private `K=16`) nesting-aware boundary walk** driven by that exact membership. **062's slicing/caching *algorithm*, its cache keying/eviction, the `G_<no_tag>` union *member sets*, and the generated-accessor *semantics* are unchanged (FR-005)** — the union is a post-slice accessor superset, salvaged unchanged; **BUT the generated nested-group accessor *call site* gains a context argument** (mechanical `emit_messages.cpp:260-270` emitter edit + **forced golden-header regen**), and the `entry_context`/nested-descent **plumbing gains a context field** (`build_nested_subview`/`nested_group_slices` must now carry it). Both are Wire-format + dictionary-layer changes → all four mandatory controls + Gate A/B (the Wire+Codegen mandatory trigger already covers the emitter + golden regen).

**Context-propagation mechanism (Gate A Round-2 — the unifying seam):** the `(msg_type, parent-path)` context rides on the **`OffsetTable` as construction state (a `group_context`)**, NOT on the call arguments — so `group_slices(no_tag)` and the C-ABI signatures stay stable. The **ROOT** `OffsetTable` is constructed with context `{msg_type (from the frame, tag 35), parent-path = []}`; the parser computes it at `MessageView::group<>` (`parser.hpp:271`; `msg_type()` is reachable at `:149`). A **NESTED** sub-`OffsetTable` built by `build_nested_subview` (`offset_table.cpp:552`) is seeded with `{msg_type, parent-path = outer-path + outer-group-no_tag}`. `OffsetTable::group()` evaluates membership using its **stored `group_context`**, passing it into the membership predicate — so only `group_member_fn_t` (`offset_table.hpp:29`) gains the context param (the one sanctioned public-C++, non-ABI change; clarify Q2), while `group_slices(no_tag)` and all three call sites (C++ top-level `parser.hpp:271`, C-ABI top-level `message_read.cpp:358`, nested `offset_table.cpp:613`) keep their `(no_tag)`-only signatures. The only place a new *argument* is unavoidable is the **nested descent** (`build_nested_subview`/`nested_group_slices` gain the context param → the generated accessor call site passes it → FR-005 emitter edit + forced golden regen).

### Round 2 — tasks-pins

*Route to `/speckit-tasks` for emission as tasks — these are implementation-level, NOT Gate-A blockers (per Opus Round-2 triage).*

1. **Loader context-store shape**: `finalize()` dedups by bare `no_tag` (`xml_loader.cpp:801`) and `as_table_view()` does bare-no_tag lookups (`dictionary.cpp:327-338`), so a context variant **cannot** be recovered post-finalize. 2. **entry_context / representative `G_<n>` size+alignment regression test** — guard the enlarged by-value entry object after the `group_context` field is added.
3. **Non-allocating context lookup key + hash strategy** (`string_view` msg_type + inline path span, or an interned message id); a **census-derived table-size report** across all nine dicts; a **no-alloc test** for repeated `group_member_fn` lookups.
4. **K=16 depth-overflow → `err_group_too_large` regression** — assert path/depth overflow (nesting deeper than K=16, or parent-path cannot append) returns the existing group-limit error, observable + fail-closed, and is **distinct** from the nested-count-mismatch validation.
5. **C-ABI last-nested-instance-extent MassQuote witness** — pin the newly-activated delimiter-bounded multi-instance branch (`message_read.cpp:549-591`, `LCOV_EXCL` `:554-562`): a MassQuote-shaped frame with ≥1 outer member **after** a multi-entry nested group, asserting the last nested instance's extent does not absorb trailing outer members (and a small C-ABI extent fix if the witness shows divergence from the C++ membership-bounded path).
