## PIVOTAL FINDING — the collision is systemic and NOT parent-disambiguable

Lightweight census (`scratchpad/census.py`) over all nine runtime XMLs — reused NumInGroup tags with **differing immediate membership**:

| Dict | # colliding tags | Examples |
|---|---|---|
| FIX40 | 1 | 73 |
| FIX41 | 1 | 73 |
| FIX42 | 7 | 73, 78, 146, 268, 295, 296, 420 |
| FIX43 | 9 | +552, 555 |
| FIX44 | **12** | 73, 78, 124, 146, 268, 295, 296, 420, 552, 555, 711, 936 |
| FIX50 | 13 | +386 |
| FIX50SP1 | 14 | +1351 |
| FIX50SP2 | **22** | +702, 1310, … |

**Two conclusions:**
1. **Systemic** — 12–22 colliding tags per modern dict, not the single tag-295 the finding named. Any per-context fix must be general, and the FR-002 census + guards span a broad set.
2. **`(parent_group_no_tag, no_tag)` is INSUFFICIENT** — every collision is PARENT-AMBIGUOUS (still multiple membership variants under the same parent), most at parent=0 (top-level of different messages/components). Membership is genuinely **message/component-path-scoped** — the same tag (e.g. 146 NoRelatedSym: 12 variants in FIX50SP2) legitimately carries different fields in different messages. This mirrors how QuickFIX resolves groups by walking the message-definition tree, not a global tag→members map.

**Census verified with component expansion** (`census2.py`, mirrors the loader's `<component>`-ref expansion): the systemic + parent-ambiguous conclusion HOLDS (FIX44 12 tags all parent-ambiguous; FIX50SP2 22→21, negligible). Ground-truth on the trusted case now matches the finding exactly — FIX44 tag 295: parent=0 variant lacks 299 (QuotCxlEntriesGrp), parent=296 variant has 299 (QuotEntryGrp) — **and even `(parent=296, 295)` still carries ≥2 variants** (MassQuote vs MassQuoteAck), confirming membership is message-scoped, not merely parent-scoped. (Conclusions (1)/(2) are decisive for the chosen design: they prove membership is genuinely `(msg_type, parent-path, no_tag)`-scoped — **msg_type is MANDATORY**, since MassQuote and MassQuoteAck share the *entire* structural path `root→296→295` and differ only by message type. This is the context key **Option A** must compute; it is *not* sidesteppable by a parent-key or a union — see the codegen-union reframing below, which shows the union model applies ONLY to post-slice accessors, never to runtime slicing.)

## Codegen's UNION model — proves ACCESSORS need not change, NOT a slicing oracle

Verified in `tools/codegen/fixpp-codegen/emit_messages.cpp` (comments `:126-139,383-394`; keying `:390-406`): codegen emits **one shared `G_<no_tag>` per no_tag** in `namespace groups`, whose member set is the **UNION of all member tags** seen under that no_tag across every message (keyed by `FieldRef::group_no_tag`, deduped first-encounter — explicitly "what tames FIX50SP2"). Confirmed on the wire: the single `v44 groups::G_295` (generated `Messages.hpp:2999`) bakes 299/132/133 (`quote_entry_id`/`bid_px`/`offer_px`) — the union includes MassQuote's QuotEntryGrp fields, so **MassQuote typed reads are already correctly accessored**; MassQuote references it at `:23130` (`group<295,G_295>()`), and `G_296` nests `group_view<G_295>` (`:3440`).

**What the union model actually proves — and what it does NOT.** The generated `G_<no_tag>` is a **post-slice accessor superset**: it reads bytes that `OffsetTable::group()` has *already sliced*, and a field absent from a given message's wire simply returns not-found (harmless). So the union proves exactly one thing: **063 does NOT need to touch generated accessors** — FR-005's generated-accessor clause is satisfied *for free*. It does **NOT** transfer to slicing. The runtime `group_member_fn_` at `offset_table.cpp:433` (acceptance) / `:447` (extent) **defines where the bytes are**: a union false-positive — a trailing field that is a member of *some other* same-tagged variant — is swallowed into the last instance's byte span (`:447` breaks the instance only on a *non-member* tag), and the same false-positive can trigger a false nested-count recursion. A superset is safe for *reading already-correct bytes* and **unsound for *deciding* the byte boundary**. Treating the accessor union as an oracle for slicing membership is a **category error** (Gate-A Root cause #1); the runtime parser needs **exact, context-scoped** membership. The generated-accessor **semantics + `G_<n>` union member sets stay untouched**; but the emitter's **nested-accessor call site gains a context argument** (`emit_messages.cpp:260-270`) → **forced golden-header regen** (FR-005 Round-2 re-scope). The runtime slicing predicate changes.

## `OffsetTable::group()` mechanics (verified `offset_table.cpp:402-482`)
Membership (`group_member_fn`) does two things: (1) **acceptance** — `:433` rejects the group if `delim` (first field after the count) isn't a member (THE Defect-A symptom: first-seen-wins picked QuotCxlEntriesGrp whose members lack 299 → `group_member_fn(295,299)=false` → empty); (2) **outer extent** — `:447-448` a non-member tag ends the instance/group. The `seen_in_instance` repeat heuristic (`:450-459`) is the Defect-B truncation. So the loader's membership drives both acceptance and extent.

## Design decisions (Phase 0)

### D-A · Group-membership fix (Defect A) — Option A (exact context-scoped membership)
The finding proposed full per-context membership. Gate-A Round 1 resolved the Option-A/Option-B fork **decisively to Option A**. Option B (union-per-no_tag membership) was proven **unsound for the runtime parser**: because `OffsetTable::group()` uses membership to define the byte-slice boundary (`offset_table.cpp:433` acceptance, `:447` extent), a union false-positive trailing field is swallowed into the slice; and because the engine accepts out-of-order body fields (B-004-1) a declaration-order "trailing-neighbour census" **cannot bound** the set of fields that may legally follow a group on the wire, so no census discharges the risk (Root cause #2). The codegen-union model applies only to *post-slice accessors*, not to slicing (Root cause #1). Therefore Option A is **the design**, not a fallback:

- **Option A — exact context-scoped membership** (ADOPTED): runtime group membership resolved by the key **`(msg_type, bounded parent-no_tag-path, no_tag)`** — unique by FIX structure (a message cannot head two groups with the same count tag under the same parent-path). **msg_type is MANDATORY** (census: MassQuote vs MassQuoteAck share the full path `root→296→295`; only the message type distinguishes them). Threaded through: loader registration (per-referencing-message component expansion + full path accumulation) → `Dictionary`/`table_view` membership store (re-keyed from bare `no_tag`) → `group_member_fn_t` signature (gains context — clarify Q2 sanctions this public-C++, non-ABI change; now **exercised**) → `parser.hpp:484-494` bound predicate → `OffsetTable::group()` (`:433`/`:447`) + `validator.hpp:219` → `entry_context` (`group_view.hpp:31-47`, gains a context field, **must stay trivially-copyable**) → **and 062's nested descent `build_nested_subview`/`nested_group_slices` (`offset_table.cpp:552`/`:582`) MUST now carry the context** (they carry neither msg_type nor parent-path today; the sub-`OffsetTable` at `:572` is msg-type-agnostic).
- **Option B — union-per-no_tag membership** (REJECTED, unsound): accumulating the union of members per no_tag fixes the `group_member_fn(295,299)` symptom with no signature change, but the union false-positive corrupts extent (`:447`) and nested-count detection, and the census-gated safety argument is invalid under order-independent acceptance (B-004-1). Recorded here so the rejection is traceable; not shippable for the parser.
- **Load-time vs parse-time coordinate systems.** The two ends agree only on the **parent no_tag chain**. The loader's natural key `component_index` (`xml_loader.cpp:479`) is invisible on the wire (components flatten away); `expand_field_list` threads only the *immediate* `enclosing_group_no_tag` (`:529`), not the full path, and msg_type is out of scope at registration (`:212` `GroupDef.parent_group_no_tag` is set from the immediate parent only). So the loader must register membership under the reconcilable key — expanding shared components **per referencing message** and accumulating the full parent-no_tag path — and the parser recomputes the same key from `(msg_type at MessageView::group<>, wire parent-no_tag chain, no_tag)`.
- **Context-propagation mechanism (Round 2 — OffsetTable carries the context):** the `(msg_type, parent-path)` context is stored on the **`OffsetTable` as construction state (a `group_context`)**, NOT passed on the call args. Root: `MessageView::group<>` (`parser.hpp:271`; `msg_type()` reachable at `:149`) constructs the root table's context `{msg_type from the frame (tag 35), path=[]}`. Nested: `build_nested_subview` (`offset_table.cpp:552`) seeds the sub-table's context `{msg_type, outer-path + outer-group-no_tag}`. `OffsetTable::group()` reads its stored `group_context` and passes it into `group_member_fn_`. This keeps `group_slices(no_tag)` and the C-ABI signatures **stable** — only `group_member_fn_t` (`offset_table.hpp:29`) gains the context param, and the nested-descent call site (`nested_group_slices`, emitted at `emit_messages.cpp:260-270`) gains the context argument (→ FR-005 emitter edit + forced golden regen). This is the single seam that subsumes the parser top-level, the C-ABI top-level (`message_read.cpp:358`), and the nested descent.
- **Clarify note**: the "public C++ API may gain a context param" allowance (clarify Q2) is now **exercised** — `group_member_fn_t` gains the context param (public C++, non-ABI). Still within the sanctioned envelope; recorded in plan.md Complexity Tracking.

### D-B · Nesting-aware boundary walk (Defect B), allocation-free — driven by EXACT (Option-A) membership
- **Decision**: in `OffsetTable::group()`'s per-instance walk, when a member tag is itself a **NumInGroup count present as a nested group in this context** (determined via the now-**exact** Option-A membership predicate — Option B could not answer this: a union member is not a nested count "in this context"), read its count value from `entries_` and **consume that nested group's extent** (its count × per-entry span, honoring its own delimiter) before resuming outer-boundary detection — replacing the flat `seen_in_instance` heuristic. Note that field *type* (`NumInGroup`) is a context-free per-field property (295 is `NumInGroup` in every context), so nested-count *identification* is context-free; only nested-group *presence in this context* needs Option-A membership.
- **Algorithm contract (nested walk, per level)**:
  - Parse the nested count value from `entries_`; consume **exactly `declared` instances** or **fail closed** (return the existing group error — no new `fixpp_error_t`).
  - **Fail-closed on**: malformed/non-numeric count, short group (fewer instances present than declared), count overflow.
  - **Zero-count nested group consumes no extent** — the outer boundary walk resumes immediately after the count tag (preserve B-004-7; do not regress count-of-zero).
  - Apply `cfg_.max_group_entries_per_instance` (`offset_table.cpp:476`) **per level** (currently applied only at top level).
  - Preserve the structural, **don't-trust-the-count posture** for count-*mismatch* validation: count-mismatch remains the validator's job (B-004-7); the walk uses the count only to bound consumption, not to re-report mismatch.
- **Allocation-free + depth cap**: recursion over `entries_` indices via a depth-bounded helper (explicit index cursor, no heap). **There is NO nesting-depth field in `OffsetTable::Config` today** — it exposes only `max_offset_entries` and `max_group_entries_per_instance` (`offset_table.hpp:33-36`; codegen's `kMaxGroupDepth=16` at `emit_messages.cpp:137` is a codegen constant, not an `OffsetTable` cap). Decision: **add a private compile-time constant depth cap** (mirror codegen's `kMaxGroupDepth = 16` — real FIX nesting is shallow), NOT a `Config` field. Rationale is coupled to the context key: `entry_context` carries the bounded parent-no_tag path **by value** as a fixed inline `std::array<std::uint16_t, K>` + length (a runtime `Config` field cannot size a compile-time array, and a heap/vector path would break the `is_trivially_copyable_v<entry_context>` static_assert at `group_view.hpp:47` and the alloc-free budget). **One constant `K` = 16 simultaneously bounds recursion depth, sizes the by-value path (FR-004 trivially-copyable), and keeps the walk heap-free (SC-005).** Guarded by `group_entry_alloc_gate_test.cpp` + `wire_alloc_guard_test.cpp`. **Depth/path overflow disposition (Round 2):** nesting deeper than `K=16`, or a parent-path that cannot append, returns the **existing group-limit error** (`err_group_too_large`, `offset_table.cpp:477`) — observable + fail-closed, and **distinct** from the nested-count-mismatch validation (which stays the validator's job, B-004-7). A depth-overflow regression is a Round-2 tasks-pin.
- **Ordering**: B depends on A — the walk must know which member tags are nested groups *in context*, which requires exact context-correct membership first.

## Risks / Gate-A questions (Round-1 resolutions)
1. **Defect-A fork RESOLVED → Option A (exact context-scoped membership)**. Option B (union-per-no_tag) was proven unsound for the parser (byte-slice corruption at `offset_table.cpp:447`; census cannot discharge the risk under order-independent acceptance). The remaining design work is the *threading* of the `(msg_type, bounded parent-no_tag-path, no_tag)` key — see D-A.
2. **Census reframed — completeness/correctness aid, NOT a safety gate**. The reused-tag census still enumerates every colliding tag across all nine dicts so each collision gets a discriminating guard (FR-002 coverage). It is **no longer** the Option-B over-extension "safety gate": a declaration-order census cannot bound the order-independent, hostile-frame wire (B-004-1), so it never proved slicing soundness (Root cause #2). Option A makes membership exact, so over-extension does not arise.
3. **Defect-B allocation-free recursive walk** on the hot read path — depth-bounded (private `K=16` compile-time cap) index recursion over `entries_`, no heap; per-level fail-closed count/short/overflow/zero semantics (D-B contract); prove via `group_entry_alloc_gate_test.cpp` + `wire_alloc_guard_test.cpp`. Driven by the exact Option-A membership.
4. **FR-005 nuance (Round-2 re-scope — NOT "no codegen change")**: codegen's superset `G_n` proves the generated-accessor **semantics + `G_<n>` union member sets** need not change (they read already-sliced bytes). FR-005's *algorithm* clause (062's slicing/caching algorithm + cache keying/eviction + accessor semantics + flyweights unchanged) holds. **BUT the generated nested-group accessor *call site* DOES change**: threading Defect-A context into nested descent adds a context argument to the emitted `nested_group_slices(...)` (`emit_messages.cpp:260-270`) → **emitter edit + forced golden-header regen**. The `entry_context`/nested-descent **plumbing also gains a context field** under Option A — the caching *algorithm* is unchanged; the cache key `(slice_data, nested_no_tag)` stays valid because context (msg_type + path) is constant within one message parse and the ROOT-owned cache lives exactly one parse.
5. **Scope vs finding**: Defect A is *systemic* (12–22 colliding tags/dict); Option A's fix is the context-key threading (multi-surface), and the *census + guards* are the broad coverage part. User-owned scope (all-nine census; 063-first) already decided.
6. **C-ABI freeze**: **Top-level** `fixpp_msg_get_group` sits atop `group_slices` → `OffsetTable::group()` (`message_read.cpp:358`), which reconstructs context internally from its stored `group_context` — no exported symbol/header changes; outputs legitimately correct. The **nested** C-ABI read (`fixpp_group_get_nested_group`, `message_read.cpp:462-609`) is **POSITIONAL** (delimiter = first tag after the count) and uses **NO dictionary membership**, so it needs no cursor/ABI change and corrects **transitively** via the Defect-B extent fix (count + per-tag reads are tag-addressed). Qualification (Round-2 tasks-pin, NOT a Gate-A blocker): Defect B activates the previously-dead delimiter-bounded multi-instance branch (`message_read.cpp:549-591`, `LCOV_EXCL` `:554-562`) whose last instance runs to the end of the outer slice (`:587-590`), so trailing outer members can be absorbed into the last nested instance's extent → pin a C-ABI MassQuote last-instance-extent witness. **Codex's `fixpp_group` cursor-field redesign is rejected** (positional path needs no ABI change). Symbols/headers frozen (`abi_symbol_golden` + `capi_freeze.sha256` unchanged). The `group_member_fn_t` widening is public **C++** only, not C-ABI. Threading msg_type + a fixed-size by-value path adds no per-parse heap allocation (SC-005 / N5).
