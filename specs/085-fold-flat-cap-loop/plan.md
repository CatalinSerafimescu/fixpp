## Summary

`OffsetTable::group()` answers two questions about a repeating group — where its extent ends, and whether any instance breaches `max_group_entries_per_instance` — using **two walks over the same entries**. The first, `consume_group_extent`, is nesting-aware and *already applies the cap* (`:521-524`). The second (`:584-595`) re-walks the same range with a flat, wire-derived boundary test and applies the same cap again.

Phase 0 re-verified (per A-001) that on the dictionary path the second walk is **unreachable as an error return**: both walks derive `delim` from the same entry, the flat partition strictly refines the nesting-aware one, and the nesting-aware walk returns first on breach. Removal is therefore a no-op on observable behaviour.

It cannot simply be deleted: the **dict-free** branch never calls `consume_group_extent`, so the loop is that path's only cap enforcement. Per `/clarify` Q1 the loop is relocated into the `else` branch **without semantic change** — mechanical re-indentation only, against C-3's nine-item preservation checklist. `consume_group_extent` is not touched.

Net change: one loop deleted from the dictionary branch, the same lines moved into the dict-free branch, one justification comment added (its content pinned by SC-005a), **three** new test cases in the `wire_pure_tests` bucket — the red-first structural pin `WireOffsetTable.FR001_SingleTraversalSourceInspection` (FR-001b, Article VII §3's failing-test-first artifact) plus `WireOffsetTable.DictFreeDoSCapPerInstanceRejectsOversizedInstance` + `…AllowsWhenCapRaised` — **one** build line (`FIXPP_SRC_DIR` on the `wire_pure_tests` bucket, `tests/wire/CMakeLists.txt`), **two** mutation transcripts (dict-free site, FR-005a(i); `consume_group_extent:521-524`, FR-005b), one limitation row, one stale coverage waiver repaired.
