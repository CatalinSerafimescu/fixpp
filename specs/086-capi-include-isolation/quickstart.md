## 3. Read the delivered interface — FR-003 / FR-011b

> **`-A7`, not `-A4` — measured, `research.md` R3.** CMake emits a **blank line** between `add_library()` and
> `set_target_properties()`. Counting from the comment, `-A4` reaches only the first property line, so the
> `$<LINK_ONLY:…>` line below it falls outside the window. `-A7` reaches the closing `)`.

```bash
grep -A7 'Create imported target fixpp::capi$'    /tmp/fixpp-stage-086/lib/cmake/fixpp/fixppTargets.cmake
grep -A7 'Create imported target fixpp::service$' /tmp/fixpp-stage-086/lib/cmake/fixpp/fixppTargets.cmake
```

Expected:

```cmake
set_target_properties(fixpp::capi PROPERTIES
  INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include/capi"
  INTERFACE_LINK_LIBRARIES "\$<LINK_ONLY:fixpp::capi_objects>"
)
set_target_properties(fixpp::service PROPERTIES
  INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include/service-iface"
  INTERFACE_LINK_LIBRARIES "fixpp::capi"
)
```

Now capture the **whole** `fixpp::capi` property block at both stages — FR-009a(i) / C-3 leg 2.

> ### ⚠️ The extraction terminator is load-bearing, and the obvious one is a guaranteed false green
>
> An `awk` range anchored on the `# Create imported target` comment and terminated on `/^$/` stops at the blank
> line CMake emits after `add_library()`. It captures **only the comment and the `add_library` line** — which
> are byte-identical at both stages — so `diff` exits **0 with no output whatever the isolation did**,
> including if the isolation were never applied. This bundle carried exactly that command until Gate A r2;
> it was run against both staged prefixes and returned rc=0 (`research.md` R3, which pastes the generated text
> the range must span). Anchor on the `set_target_properties(` line and terminate on the closing `)` instead.
> The trailing ` PROPERTIES$` is what excludes `fixpp::capi_objects`; do **not** substitute a range ending on
> the `capi_objects` comment, because nothing guarantees CMake emits the two targets adjacently.

```bash
# Reads the two STAGED PREFIXES from §1 and §2 — not the baseline worktree, which may already be retired.
B="$FIXPP_086_EVIDENCE/capi-props-base.txt"      # explicit filenames, never a glob: a stale third file in a
A="$FIXPP_086_EVIDENCE/capi-props-after.txt"     # reused evidence dir makes `diff` take 3 args and error on usage
awk '/^set_target_properties\(fixpp::capi PROPERTIES$/,/^\)$/' \
    /tmp/fixpp-stage-086-base/lib/cmake/fixpp/fixppTargets.cmake > "$B"
awk '/^set_target_properties\(fixpp::capi PROPERTIES$/,/^\)$/' \
    /tmp/fixpp-stage-086/lib/cmake/fixpp/fixppTargets.cmake      > "$A"

# PIN THE EXTRACTION ITSELF — an empty capture must fail loudly, not diff empty against empty.
for F in "$B" "$A"; do
  [ -s "$F" ] || { echo "FR-009a(i) FAIL: empty capture from $F — the awk range did not match"; exit 1; }
  grep -q 'INTERFACE_LINK_LIBRARIES' "$F" \
    || { echo "FR-009a(i) FAIL: $F has no INTERFACE_LINK_LIBRARIES — extraction is wrong"; exit 1; }
done

# POSITIVE, NAMED assertions on the isolated block — these survive formatting changes; "no diff" does not.
grep -Fq 'INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include/capi"' "$A" \
  || { echo "FR-009a(i) FAIL: isolated include root absent"; exit 1; }
grep -Fq 'INTERFACE_LINK_LIBRARIES "\$<LINK_ONLY:fixpp::capi_objects>"' "$A" \
  || { echo "FR-009a(i) FAIL: LINK_ONLY wrapper absent"; exit 1; }

# CLOSED ENUMERATION — COMPARED, not printed. Printing the two name sets and reading them by eye
# is not a gate: an unexpected THIRD changed property scrolls past and the step still "passes".
# The two maps below are the closed enumeration FR-009a(i) requires:
#   OFF = {INTERFACE_LINK_LIBRARIES}                                   measured on the real
#         pre-feature artifact (research.md R3)
#   ON  = {INTERFACE_INCLUDE_DIRECTORIES, INTERFACE_LINK_LIBRARIES}    contracts/include-interface.md §2
# Note what the delta IS: the include property is GAINED and INTERFACE_LINK_LIBRARIES is REWRITTEN.
# "Loses only INTERFACE_INCLUDE_DIRECTORIES" is false of the delivered design and never was satisfiable.
props() { sed -nE 's/^  ([A-Za-z_]+) .*/\1/p' "$1" | sort; }
diff <(props "$B") <(printf '%s\n' INTERFACE_LINK_LIBRARIES) \
  || { echo "FR-009a(i) FAIL: OFF-side property set is not exactly {INTERFACE_LINK_LIBRARIES}"; exit 1; }
diff <(props "$A") <(printf '%s\n' INTERFACE_INCLUDE_DIRECTORIES INTERFACE_LINK_LIBRARIES) \
  || { echo "FR-009a(i) FAIL: ON-side property set is not exactly {INTERFACE_INCLUDE_DIRECTORIES, INTERFACE_LINK_LIBRARIES}"; exit 1; }
# Record both name sets in the verify record as well — the assertion above is the gate, the record
# is the evidence.
for F in "$B" "$A"; do props "$F"; echo "--- ^ $F"; done

# The two blocks MUST differ. Identical blocks mean the isolation is absent or the extraction is wrong —
# which is exactly the false green this step used to report. (`if` is used so `set -e` does not abort on
# diff's expected rc=1.)
if diff "$B" "$A"; then
  echo "FR-009a(i) FAIL: capi property block identical at both stages"; exit 1
fi
```

> ⚠️ **This step is necessary but NOT sufficient — in two ways.**
>
> 1. It reads the target properties, the same method that reported `fixpp::capi` "clean" in 084 while the
>    transitive path was wide open. The reachability tests in §4 are what establish the contract.
> 2. It is **blind to compile definitions**. Those reach a C-ABI consumer through
>    `fixpp_capi_objects` → `fixpp_log` (`src/capi/CMakeLists.txt:29-38`) and never appear in `fixpp::capi`'s
>    own block, which reads identically whether they propagate or not. FR-009a(ii) / C-3 leg 3 measures that
>    at a probe target inside the configured consumer instead — it runs as part of §4's witness, not here.

Asserts the full `contracts/include-interface.md` §1 matrix. Three rules govern how (§4/§4a of that contract):

- they are **not build targets**. The driver `FATAL_ERROR`s on any non-zero build exit

- a passing positive assertion **never** establishes a negative one, because `<fix/c_api.h>` resolves from

## 5. Demonstrate the witness RED — FR-007 / FR-011e / SC-002

**Mandatory.** A gate never observed failing proves nothing. Revert one isolation at a time and confirm the
witness fails; restore and confirm it passes. Record, per demonstration: the command, the **exit code**, and
the **first diagnostic line**, in `.specify/decisions/086-capi-include-isolation-verify.md`.

> ### ⚠️ The two reverts are NOT interchangeable, and the asymmetry is directional
>
> `fixpp_service` links `fixpp_capi` (`src/service/CMakeLists.txt:16`). Reverting
> `src/capi/CMakeLists.txt:46` to `PUBLIC` restores the un-wrapped
> `INTERFACE_LINK_LIBRARIES "fixpp::capi_objects"`, and `fixpp::service` then inherits
> `${_IMPORT_PREFIX}/include` **transitively through it** — so the C-ABI revert reds **both** probes. A
> verifier who reverts capi and sees both go red has recorded service-leg evidence that proves nothing about
> `src/service/CMakeLists.txt:12`. **The service demonstration MUST revert `src/service/CMakeLists.txt:12`
> alone, with the C-ABI isolation intact**, and MUST capture `fixpp::capi`'s properties from that same run
> (§3) as proof the C-ABI leg was not the cause (FR-011e).
>
> **Use a reversible patch, never `git checkout <file>`** — at `/speckit-implement` time the isolation edit is
> uncommitted, and `git checkout` would discard it.
>
> **Ergonomic hardening is a `/speckit-tasks` item, not a precondition** (Gate A r2, R2-4): redirect each
> demonstration's CTest output into `$FIXPP_086_EVIDENCE/` and assert non-zero rather than printing `rc=$?`,
> and wrap both demonstrations in a `trap` that restores the two saved `CMakeLists.txt` copies on any exit.
> As written below the procedure is a human-driven demonstration whose restore point already exists (the two
> `cp` lines), so this is a strengthening, not a gap.

```bash

cp src/capi/CMakeLists.txt    "$FIXPP_086_EVIDENCE/CMakeLists.txt.capi"      # same basename — keep them apart
```

>

> `consumer_capi_witness` is covered by the single `cmake --build` at `:96-104` and by nothing else, which is

## 8. Package contents — FR-010 / FR-010a / SC-005 / C-5

```bash
ctest --test-dir build/linux-clang-release -L packaging --no-tests=error --output-on-failure
```

`--no-tests=error` matters most here: `tests/packaging/` is added only under `if(FIXPP_PACKAGING_ENABLED)`
(`CMakeLists.txt:389`), so on an OTel-OFF build this selector matches **zero** tests and, without the flag,
reports green having asserted nothing.

Beyond presence (FR-010), the witness must assert **containment** (FR-010a / C-5): every installed path under
`include/capi/` matches `^include/capi/fix/`, every path under `include/service-iface/` matches
`^include/service-iface/fixpp/service/`. The existing gates cannot cover this — the denylist is anchored on
`^include/fixpp/…` (`run_package_contents_witness.cmake:484-487`) and the exact-set generated-tree check on
`^include/fixpp/(v[A-Za-z0-9]+)/…` (`:508`); neither regex can ever match a path under the new roots.

Assertions must be **prefix-normalised**: Linux DEB/RPM/TGZ carry a `usr/` component, the Windows ZIP does not.
A `usr/`-anchored glob finds nothing on Windows and reports "the package carries no C-ABI headers" — a defect
claim about the product manufactured by the test (`package-layout.md` §2).

## 9. In-tree regression — FR-005 / SC-007 / C-4

> ### ⚠️ A test-NAME diff cannot see a failure — assert the RESULT
>
> The name-set comparison this section carried until Gate A r2 is structurally incapable of observing what
> SC-007 claims ("no test newly fails"), and it is close to vacuous by construction: this feature registers
> **no new ctest test** (the probes are targets and configure-time `try_compile` inside the existing consumer
> sub-project), so the name sets are expected identical whatever happens. Neither `ctest` exit status was
> captured either — `> file` discards it silently. All four legs below are required; the name diff is kept
> only for leg (d), "no test disappears".

```bash

ctest --test-dir build/linux-clang-release --no-tests=error --output-on-failure \
  > "$FIXPP_086_EVIDENCE/ctest-after.txt" 2>&1
echo $? > "$FIXPP_086_EVIDENCE/ctest-after.rc"
set -e

# Normalise a ctest log to sorted "<name> = <status>" lines. Verified against real ctest output:
#   "1/3 Test #1: name .......   Passed" and "2/3 Test #2: name .....***Failed".
ctest_status() {
  sed -nE 's@^ *[0-9]+/[0-9]+ +Test +#[0-9]+: +([^ ]+) +[.]+[* ]*([A-Za-z][A-Za-z ()]*[A-Za-z)]) +[0-9.]+ sec$@\1 = \2@p' "$1" | sort
}

# (a) the after-run MUST be green
[ "$(cat "$FIXPP_086_EVIDENCE/ctest-after.rc")" = 0 ] || { echo "SC-007 FAIL: after-run red"; exit 1; }

# (b) the baseline MUST be green too — "unchanged" against an equally-red baseline is not a pass.
#     If it is not 0, STOP: enumerate its failures in the verify record per §2 and compare
#     ctest_status sets against that enumeration instead of taking this shortcut.
[ "$(cat "$FIXPP_086_EVIDENCE/ctest-before.rc")" = 0 ] \
  || { echo "SC-007: baseline NOT green — enumerate its failures per §2 before proceeding"; exit 1; }

# (c) per-test statuses and the pass/fail summary line must match
[ -s "$FIXPP_086_EVIDENCE/ctest-before.txt" ] || { echo "SC-007 FAIL: empty baseline log"; exit 1; }
[ "$(ctest_status "$FIXPP_086_EVIDENCE/ctest-before.txt" | wc -l)" -gt 0 ] \
  || { echo "SC-007 FAIL: ctest_status matched no lines — the log format changed, fix the sed"; exit 1; }
diff <(ctest_status "$FIXPP_086_EVIDENCE/ctest-before.txt") \
     <(ctest_status "$FIXPP_086_EVIDENCE/ctest-after.txt") \
  || { echo "SC-007 FAIL: a per-test status changed"; exit 1; }
diff <(grep -E '^[0-9]+% tests passed, [0-9]+ tests failed out of [0-9]+$' "$FIXPP_086_EVIDENCE/ctest-before.txt") \
     <(grep -E '^[0-9]+% tests passed, [0-9]+ tests failed out of [0-9]+$' "$FIXPP_086_EVIDENCE/ctest-after.txt") \
  || { echo "SC-007 FAIL: the pass/fail summary moved"; exit 1; }

# (d) no test disappears
diff <(grep -oE 'Test +#[0-9]+: [^ ]+' "$FIXPP_086_EVIDENCE/ctest-before.txt" | sed 's/.*: //' | sort) \
     <(grep -oE 'Test +#[0-9]+: [^ ]+' "$FIXPP_086_EVIDENCE/ctest-after.txt"  | sed 's/.*: //' | sort) \
  || { echo "SC-007 FAIL: the test-name set moved"; exit 1; }

# --quiet, NOT --stat: `git diff --stat` exits 0 whether or not it prints, so a "MUST be empty"
# comment beside it asserts precisely nothing. --quiet exits 1 when there is a difference.
git diff --quiet "$(cat "$FIXPP_086_EVIDENCE/baseline-commit.txt")" -- \
  '*.cpp' '*.hpp' '*.h' ':!tests/consumer/*' \
  || { echo "SC-007 FAIL: production source edited"; \
       git diff --stat "$(cat "$FIXPP_086_EVIDENCE/baseline-commit.txt")" -- \
         '*.cpp' '*.hpp' '*.h' ':!tests/consumer/*'; exit 1; }
```

Record both `.rc` files, both logs and the summary lines in the verify record — they are SC-007's evidence.

> The `:!tests/consumer/*` exclusion is deliberate and matches what SC-007 actually claims: this feature adds
> witness translation units under `tests/consumer/`, and it changes **no production C/C++ source or public
> header**. A bare `git diff --stat main -- '*.cpp' …` would report the new probe TUs and read as a violation
> of its own success criterion.

## 10. What local runs cannot cover

- **MSVC** — CI-only. The `usr/`-prefix asymmetry and archive naming (`libfixpp_capi.a`/`.o` vs
  `fixpp_capi.lib`/`.obj`) both differ there.
- **gcc-release** — `/speckit-verify` is clang-only locally; gcc-release is a CI job.
- **Off-host consumability** — the consumer tier is green under the *producing build's* environment only
  (`tests/consumer/CMakeLists.txt:33-38`). It cannot fail on a dependency a third-party consumer would have to
  supply; that property belongs to `tests/packaging/`.
