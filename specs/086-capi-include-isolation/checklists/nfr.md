## Evidence Quality (the feature's own gates)

- [x] CHK063 - Does every gate this feature adds have a stated way to fail, or is any of them capable only of passing? [Measurability, Coverage] — **WAIVED (orchestrator, 2026-08-04): the residual is real but belongs to a different owner.** The deciding fact, verified after the audit escalated: **086 registers no new ctest test at all.** `grep -c add_test specs/086-capi-include-isolation/tasks.md` → 0; every probe rides the single pre-existing `fixpp::consumer::install-witness` registration (`tests/consumer/CMakeLists.txt:71-74` states this by design — "covered with no new `add_test`"), and the packaging assertions extend the existing packaging witness. So each gate *this feature adds* is an assertion **inside** an already-registered test: if that test runs, the assertion runs and can fail — demonstrated red per FR-007/T015/T022/T030/T031/T036. The zero-selection hazard the auditor identified is about whether those **pre-existing** tests are *registered* at all, which is a property of the option-guard structure (`CMakeLists.txt:349`, `:389`, `:401`) and the project-wide absence of `--no-tests=error`, both inherited from 084 and affecting every feature that has ever added a test under those guards. 086 cannot bind a flag on an invocation it does not own. What 086 *can* do, it already does: its own procedure mandates `--no-tests=error` on every invocation it prescribes and requires the selected-test **count** in the verify record (CHK066, PASS). Tags are `[Measurability, Coverage]` — neither Completeness, Clarity nor Consistency — so a waiver is permissible. **Residual accepted, not closed**: a CI lane with the guards off would run neither witness and report green. Tracked for a follow-up issue against the shared test-registration infrastructure rather than absorbed into 086's scope, where it would sit outside the 6-file change Gate A reviewed. *(Original audit escalation retained below for the record.)* **ESCALATED, not dispositioned —** Every gate this feature specifically adds *does* have a demonstrated or stated failure mode when it actually executes (compile failure for the two positive probes; `FATAL_ERROR` on an unexpected TRUE for the three `try_compile` negatives, demonstrated red for the fixture in R9/R4 and required to be demonstrated red in the real tree by T015/T022/T030/T031/FR-007; the required driver comparison for the usage-requirement probe, FR-009a(ii); the demonstrated-failing packaging assertions, T036/SC-005; the explicit non-zero exit on the additive-superset check, quickstart §2; build/link failure for `consumer_capi_witness`, FR-009). But the question as posed is broader than "does the assertion, once run, have a way to fail" — it is whether the gate is *capable only of passing*, and there is a real path to that: the established, pre-existing, project-wide absence of `--no-tests=error`/`CTEST_NO_TESTS_ACTION` in `CMakePresets.json`/`.github/` means a `ctest -L consumer`/`-L packaging` invocation that omits the flag, against a build where the option guards (`FIXPP_BUILD_CODEGEN_TOOL`, `FIXPP_PACKAGING_ENABLED`) are off, selects **zero** tests and exits 0 — a run that observed nothing and reports green. Nothing in this feature's own artifacts binds that flag at a level a future runner (in particular a CI job outside `quickstart.md`'s human-run procedure) cannot omit; the only guard is the documented procedure. Closing this durably would mean either (a) a spec requirement obligating a CI-config change, which is outside 086's declared file-edit scope (`.github/workflows/`, `CMakePresets.json` are not in plan.md's Scale/Scope or Structure Decision) and was not covered by Article X §6's Gate A sign-off, which reviewed a specific 6-file CMake change — or (b) a new fail-closed CMake mechanism inside the existing `add_test`/option-guard structure, which is itself a new, unreviewed design decision this audit should not make unilaterally. Neither PASS (the residual is real and this item's own dimensions, `[Measurability, Coverage]`, are technically waivable but the concern is too central to this feature's evidence chain to silently waive) nor WAIVED (same reason) nor SPEC-FIXED (no minimal, already-reviewed edit closes it) nor DD-DECIDED (not a Gate A carry-forward item — T045–T053 do not cover it) fits cleanly. **Escalated to the orchestrator**, per the audit's own escalation rule.
