## Requirement Clarity

- [x] CHK006 Is the return-value (non-throwing) contract stated unambiguously — accept, reject, and veto are ALL return values, never exceptions, and an unexpected throw is a fatal user-contract violation (not a normal signal)? [Clarity, Spec §FR-005/§FR-011/§FR-015] — PASS: FR-015 is dedicated to this contract: "the library MUST NOT require user callbacks to throw to signal any normal outcome (accept, reject, or veto), and MUST define every callback's outcome as an explicit return value"; FR-011 calls a throw "an **unexpected fatal user-contract violation**"; FR-005 states "Rejection MUST be signaled by the callback's **return value** … never by a thrown exception"; contracts G4 guarantee restates it. Refs: spec.md §FR-005/§FR-011/§FR-015, contracts/application-interface.md G4.
- [x] CHK007 Is the `toApp` veto distinguished from a `toApp` other-error (veto = `app_do_not_send` sentinel ⇒ drop; other error ⇒ abort + surface to caller) rather than collapsed into one "veto" outcome? Refs: spec.md §FR-007, data-model.md reject/veto table, research.md D2, contracts/application-interface.md.
