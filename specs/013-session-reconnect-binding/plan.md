3. **T-039 second half — TLS validation outcome → `SessionEvent`** — surface the actual master-enum `error::tls_*` code (6 cells per shipped `include/fixpp/core/error.hpp:403-429`: `tls_handshake_failed` GROUPING + 5 specifics) PLUS the thread-local `last_handshake_sub_reason()` diagnostic string as a single `SessionEvent::tls_validation_failed{code, sub_reason, peer_endpoint, reason_string}` on the NEW 013-introduced `Session::recent_events()` ring-buffer; the event channel is bound to the `Listener` / `Session` config (no Session instance need exist), so handshake-fail-before-Logon still surfaces. - **Recovery throughput** (per SC-005): replay 1000-message inbound gap (mixed app + admin span) within 2× the wall-clock the peer took to send those messages, measured against the slowest of the three reference engines. CI fails on > 5 % regression on the hot-path rows (Heartbeat emit ≤ 2 µs p99; CompID authorize lookup ≤ 5 µs p99); > 2× on the cold-path rows (`reload_credentials` ≤ 50 µs p99).

**Constraints**:
