# Quickstart / Validation Guide: FIX Latest Typed Codegen (`fixpp::vlatest`)

Run from the library submodule root. These scenarios prove the feature end-to-end; they reference [contracts/](./contracts/) and [data-model.md](./data-model.md) rather than duplicating detail.

## Prerequisites

- The pinned `dictionaries/orchestra/OrchestraFIXLatest.xml` (EP303, 181 messages) — already vendored by 074.
- A configured build tree; standard toolchain (clang/gcc Linux, MSVC Windows).

## Scenario 1 — Generate the tier (option ON, the default)

```bash
cmake --preset <preset>            # FIXPP_CODEGEN_FIX_LATEST defaults ON
cmake --build --preset <preset>
```

**Expected**: `${CMAKE_BINARY_DIR}/_codegen/include/fixpp/vlatest/{Fields,Messages,Validator,Reify,Builders}.hpp` exist and compile; `fixpp::vlatest` symbols present. (Contract B-1 ON.)

## Scenario 2 — Completeness census (the load-bearing gate)

```bash
ctest --preset <preset> -L codegen   # runs the vlatest completeness census
```

**Expected**: PASS — raw-`OrchestraFIXLatest.xml` message+field set (all depths) is exactly equal to the emitted `fixpp::vlatest` set (181==181, per-message field-sets equal). (Contract V-1.)

**Discrimination check (once, to prove it can fail)**: apply a temporary emitter mutation that drops one message and, separately, one field → the census MUST go RED both times. Revert. (V-1 mutation-tested witness.)

## Scenario 3 — 181-message typed round-trip

```bash
ctest --preset <preset> -L codegen -R vlatest_roundtrip
```

**Expected**: PASS — every one of the 181 messages constructs via `build_<Msg>`, serializes, and reads back field-for-field; zero skips. (Contract V-2.)

## Scenario 4 — Build option OFF is additive-clean

```bash
cmake --preset <preset> -DFIXPP_CODEGEN_FIX_LATEST=OFF
cmake --build --preset <preset>
```

**Expected**: build succeeds; no `fixpp::vlatest/` output; the v42/v44/v50sp2/vt11 generated bytes are byte-identical to a `main` build. (Contract B-1 OFF / INV-1.)

## Scenario 5 — Dispatch-exclusion + injective map

```bash
ctest --preset <preset> -R vlatest_dispatch_exclusion
```

**Expected**: PASS — a FIX-Latest-only MsgType routed via **either** `dispatch_application` **or** `reify_dispatch_application` does NOT land on a `vlatest` class (fail-loud default / deferred mis-resolve, pinned as the ApplExtID regression anchor); exactly one `application_version::v50sp2` case exists in each switch. (Contract V-3.)

## Scenario 6 — Frozen surfaces unchanged

```bash
ctest --preset <preset> -R 'abi_golden|capi_symbol'   # existing gates
```

**Expected**: PASS with zero diff — C-ABI/Python/link-ABI untouched. (Contract V-6.)

## Scenario 7 — Determinism golden

```bash
ctest --preset <preset>            # FULL run — determinism test is not a narrow target
```

**Expected**: the `vlatest` codegen output matches the checked-in golden byte-for-byte; a stale/non-deterministic emit fails. (Contract V-4.)
