# Quickstart / Validation Guide: FIX Latest Typed Codegen (`fixpp::vlatest`)

Run from the library submodule root. These scenarios prove the feature end-to-end; they reference [contracts/](./contracts/) and [data-model.md](./data-model.md) rather than duplicating detail.

## Prerequisites

- The pinned `dictionaries/orchestra/OrchestraFIXLatest.xml` (EP303, 181 messages) — already vendored by 074.
- A configured build tree; standard toolchain (clang/gcc Linux, MSVC Windows).

## Scenario 1 — Generate the tier (option ON, the default)

```bash
cmake --preset <preset>            # FIXPP_CODEGEN_FIX_LATEST defaults ON
cmake --build --preset <preset>
```

**Expected**: `${CMAKE_BINARY_DIR}/_codegen/include/fixpp/vlatest/{Fields,Messages,Validator,Reify}.hpp` exist and compile; `fixpp::vlatest` symbols present. **No `Builders.hpp`** — the typed `build_<Msg>`/`validate_<Msg>` builder tier is DEFERRED to a follow-up feature (see spec.md Clarifications → Session 2026-07-16); `emit_builders` stays v44-only. The completeness census's `Manifest.txt` is emitted instead (Scenario 2). (Contract B-1 ON.)

## Scenario 2 — Completeness census (the load-bearing gate)

```bash
ctest --preset <preset> -L codegen   # runs the vlatest completeness census
```

**Expected**: PASS on **both** legs (completeness is two-leg — the census alone pins only the projection/builder surface, not the shipped read classes):
- **V-1 (census)**: raw-`OrchestraFIXLatest.xml` message+field set (all depths) is exactly equal to the emitted projection **manifest** (181==181, per-message occurrence-path field-sets equal) — pins the projection + app-subset builder surface at occurrence-path granularity. (Contract V-1.)
- **V-1b (manifest↔class consistency)**: the projection-sourced manifest's per-message field set equals the actually-reachable field set of the **shipped read/reify/args class** (181==181, class-reachable-field granularity) — so `class ≡ manifest ≡ raw-XML` pins the universal read surface non-circularly. (Contract V-1b.)

**Discrimination checks (once each, to prove they can fail)**:
- *V-1*: apply temporary mutations that (i) drop one message, (ii) drop one field, (iii) mis-parent a field (wrong-parent / wrong-depth), and (iv) reuse a tag under a different parent → the census MUST go RED on each. Revert. (Occurrence-path key is what makes (iii)/(iv) detectable.)
- *V-1b (its OWN witness, not folded into V-1)*: apply a temporary **class-side** mutation on `emit_messages`/reify — drop one field or one message from the shipped class — → V-1b MUST go RED (the manifest still carries it, so `class ≠ manifest`). Revert. This is the leg the circular FR-007 round-trip cannot substitute (round-trip is blind to an absent field).

## Scenario 3 — 181-message typed reify round-trip

```bash
ctest --preset <preset> -L vlatest_roundtrip
```

**Expected**: PASS — all 181 FIX Latest messages round-trip via the universal reify/read-back path (`owning_<Msg>::from_view()/view()`), field-for-field, zero skips. **Descoped 2026-07-16:** the typed `build_<Msg>` → serialize construction leg is deferred to a follow-up (see spec.md Clarifications → Session 2026-07-16); this scenario now validates the delivered read/reify surface (FR-007(b), contract V-2 leg (b)).

## Scenario 4 — Build option OFF is additive-clean

```bash
cmake --preset <preset> -DFIXPP_CODEGEN_FIX_LATEST=OFF
cmake --build --preset <preset>
ctest --preset <preset> -L codegen   # includes the V-7 OFF-path byte-diff gate
```

**Expected**: build succeeds; no `fixpp::vlatest/` output; the v42/v44/v50sp2/vt11 generated bytes + `_dispatch/` are byte-identical to the checked-in legacy golden (V-7 asserts this against the golden, not against a live `main` checkout), and `vlatest/` is absent. (Contract B-1 OFF / INV-1 / gate V-7.)

## Scenario 5 — Dispatch-exclusion + injective map

```bash
ctest --preset <preset> -L vlatest_dispatch_exclusion
```

**Expected**: PASS — a raw FIX-Latest-only wire message routed through the single generated `dispatch_application` surface (in `_dispatch/reify_dispatch_application.hpp`, the reify application switch) does NOT land on a `vlatest` class (deferred mis-resolve-to-v50sp2 / fail-loud, pinned as the ApplExtID regression anchor); exactly one `application_version::v50sp2` case exists in that switch. (Contract V-3.)

## Scenario 6 — Frozen surfaces unchanged

```bash
ctest --preset <preset> -L abi   # existing C-ABI/link-ABI/Python surface gates
```

**Expected**: PASS with zero diff — C-ABI/Python/link-ABI untouched. (Contract V-6.)

## Scenario 7 — Determinism golden

```bash
ctest --preset <preset>            # FULL run — determinism test is not a narrow target
```

**Expected**: the `vlatest` codegen output matches the checked-in golden byte-for-byte; a stale/non-deterministic emit fails. (Contract V-4.)
