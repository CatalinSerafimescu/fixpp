## R1 — How `build_ir` selects `OrchestraLoader` vs `XmlLoader`

**Decision**: Route by **root-element sniff**, not a CMake-supplied flag. `build_ir` peeks the input XML's root element: `<fixr:repository>` → `dict::OrchestraLoader`; `<fix>` → `dict::XmlLoader` (today's hardcoded path). The loader choice is intrinsic to the file's schema.

**Rationale**: The loader is unambiguously determined by the file, so auto-detection cannot be misconfigured by a CMake wiring mistake (pairing the wrong loader with a file would be a silent, hard-to-diagnose bug). It also keeps the `cmake/Codegen.cmake` invocation uniform — every version is still just `--xml <file> --out <dir>`; no per-file loader flag to keep in sync.

**Alternatives considered**: (a) an explicit `--orchestra` driver flag — simpler to implement but reintroduces the misconfiguration risk and asymmetry in the invocation list; kept as a fallback if the root-sniff proves awkward. (b) Path/extension heuristic (`*orchestra*`) — brittle, rejected.

**Fail-closed**: an unrecognized root element MUST throw (reuse the existing `dict::xml_parse_error` family), never silently pick a default loader.

**Critical scope note (this is the dominant change, NOT the loader swap):** swapping the loader is necessary but far from sufficient. `build_ir` populates the IR's declaration-order group plan, header/trailer set, and `is_application` via a **second, `<fix>`-schema-hardcoded reparse** — `populate_group_order` (`ir.cpp:145-197`): it calls `doc.child("fix")` (`:158`), indexes `root.child("components")` (`:45`), iterates `root.child("messages").children("message")` (`:168`), and reads the `msgcat` attribute (`:186`). Against an Orchestra root (`<fixr:repository>`, with `<fixr:message>`/`<fixr:structure>`/`fixr:fieldRef`/`groupRef`/`componentRef` and **zero `msgcat`** — verified 0 matches in `OrchestraFIXLatest.xml`), every one of those lookups returns empty and the per-message loop hits `continue` (`:174`) for all 181 messages. Result with the loader swapped but nothing else: `group_order` empty, `header_trailer_tags` empty, `is_application` stuck at its struct default `false` for all 181 — so `emit_builders` would emit an EMPTY builder set (see R6) and header/trailer fields would leak into the typed body (nothing left but the 8-tag `kFramingTags` floor). The real work is the **Orchestra-native IR projection** (R2b), not the loader branch.

## R2b — Orchestra-native IR projection phase in `ir.cpp` (RC-A — the dominant logic change)

**Decision**: Add an **Orchestra-native projection** paralleling `populate_group_order` for the `fixr:` schema. `build_ir` dispatches on root element: `<fix>` → the existing `populate_group_order`; `<fixr:repository>` → the new projection, which walks the Orchestra declaration order (`<fixr:messages>`/`<fixr:message>`/`<fixr:structure>`, resolving `<fixr:componentRef>`/`<fixr:groupRef>`/`<fixr:fieldRef>` against `<fixr:components>`/`<fixr:groups>`) and produces **four load-bearing outputs**, each currently unpopulated for Orchestra:

1. **Per-message declaration-order `group_order`** — the delimiter + member order the write emitter needs (`emit_builders` group plans), walked from each `<fixr:structure>` in declaration order (mirrors `walk_level`, `ir.cpp:59-100`, but over `fixr:` refs).
2. **`header_trailer_tags`** — the top-level header/trailer tag set, so header/trailer fields are excluded from the typed body (`top_level_synthetic_members`, `emit_builders.cpp:700`). Orchestra carries these as the standard header/trailer components; resolve them transitively.
3. **category→`is_application` mapping** — Orchestra has **no `msgcat`**; it carries `category=` (30 message-level values). **Verified against `OrchestraFIXLatest.xml` (message-level `<fixr:message ... category=...>`):** the session/admin frames are exactly the **8 `category="Session"` messages** — Heartbeat(0), TestRequest(1), ResendRequest(2), Reject(3), SequenceReset(4), Logout(5), Logon(A), XMLnonFIX(n). NB `category="Testing"` (9 messages: AlgoCertificate*/TestSuiteDefinition*/TestAction*) is an **application** business category, NOT session admin — do not confuse the two. So the mapping is a **single-category rule**: `category="Session"` → `admin` (`is_application=false`); every other category → `app` (`is_application=true`). The projection MUST **fail closed** on an unmapped/absent category (mirroring the existing `msgcat` fail-closed at `ir.cpp:192-195`), never default-guess. The app-subset is not pinned to a count; it is the complement of the `category="Session"` set. **Gate (closes the silent-misclassification gap):** a witness MUST assert the derived admin complement equals the exact set `{0,1,2,3,4,5,A,n}` — because the census (FR-006) checks the manifest (emitted for all 181, ungated by the app filter) and V-2's build-leg only exercises whatever is already in the app-subset, a message silently misclassified as admin would drop its `build_<Msg>` with no RED test unless this exact-set pin exists.
4. **Lossless occurrence list** `(MsgType, full group_path, tag, rule, datatype)` per occurrence — the manifest source for the census (R5). This CANNOT come from `MessageIR.fields` (dictionary-derived, tag-deduped; `FieldRef.group_no_tag` is a single `std::uint16_t` = immediate parent only, `field_ref.hpp`; `collect_top_fields` dedups on `f.ref.tag`, `ir.cpp:238-245`), so it cannot express a multi-level `group_path` or a tag reused under different parents at depth > 1. The projection's declaration-order walk (it already carries the full `parent_path`, cf. `GroupOrderEntry.parent_path`, `ir.cpp:87-96`) is the only place this lossless data exists; the manifest MUST derive from THIS occurrence list, populated into a dedicated manifest-only occurrence model, not from `MessageIR.fields`.

**Rationale**: The four outputs are each consumed by an existing emitter path that silently degrades (empty/false) on an Orchestra root. This is the highest-risk touch point of the feature. The Orchestra parse itself is a solved problem (074's `OrchestraLoader` already walks this schema); the projection is a mechanical declaration-order walk, not open research.

**Alternatives considered**: (a) extend `OrchestraLoader` to surface group_order/category on the runtime `Dictionary` — rejected: that is a runtime API change (FR-009 bars it) and would put occurrence-path data on a runtime surface it deliberately omits. (b) reuse `populate_group_order` with a schema flag — rejected: the two schemas' node shapes differ enough (`fixr:` refs vs inline `<field>`/`<group>`) that a shared body would be a tangle; a sibling projection is cleaner and keeps the census-walker-independence argument (R5 / N-1) honest.

## R2 — `kCodegenVersions` row + version identity

**Decision**: Add one row to `kCodegenVersions` (`ir.cpp:212`): `{.s = session_version::vlatest, .a = application_version::v50sp2, .ns = "vlatest"}`.

**Rationale**: The emitter matches `vm.s == ir.session` (`ir.cpp:258`); with `session_version::vlatest` already distinct (074), this row is all that is needed to make `build_ir` map (instead of throw at `:265-270`) and emit into `namespace fixpp::vlatest`. `.a = v50sp2` mirrors 074's `session_to_application(vlatest) → v50sp2` and is truthful (FIX Latest's wire application version is v50sp2 / ApplVerID 9); it is inert for namespace selection (the emitter keys on `ir.ns`) but kept consistent for any `.a` consumer.

**Namespace collision**: none — `ir.ns = "vlatest"` is distinct from `"v50sp2"`; `emit_messages`/`emit_validator` produce `fixpp::vlatest{,::groups,::validator}` with no overlap (spec Context fact 1). **But note** (RC-A): only `emit_messages`/`emit_validator`/reify are `ir.ns`-keyed and therefore free; `group_order`/`header_trailer_tags`/`is_application`/occurrence-list are NOT free — they come from the R2b projection.

## R2c — vlatest builder coverage scope (RC-B — Option A, per 067/069 precedent)

**Decision**: **Option A** — emit typed **read/reify/args classes for ALL 181** messages (universal, `ir.ns`-keyed, no app filter — `emit_messages`/`emit_validator`/reify), but emit typed **`build_<Msg>`/`validate_<Msg>` builders for the application subset only**, exactly the split the merged 067/069 emitter already implements (read/reify/args universal; `emit_builders` app-scoped). The app-subset is derived from the R2b category→`is_application` mapping — NOT pinned to a count.

**vlatest coverage predicate**: widen the `emit_builders.cpp:646` gate to include `vlatest`, and for `ir.ns == "vlatest"` use a **vlatest-specific in-scope predicate** = `m.is_application` (from R2b), which **does NOT reuse** the FIX44-specific `kOfficial33` / `kN002N003Excluded = {BE,BF,BW,BX,BY}` sets (`emit_builders.cpp:58-76`). Those sets are verified "against FIX44.xml specifically" (`emit_builders.cpp:12-14`); BE/BF/BW/BX/BY are **legitimate FIX-Latest application messages**, so reusing the exclusion would silently drop 5 app messages from the vlatest builder set. The `CoverageMode::All` path's `!is_n002_n003_excluded(...)` filter (`emit_builders.cpp:689`) MUST NOT apply to `vlatest`.

**Completeness is preserved**: the 181-message completeness claim rides the census manifest (R5 / FR-006), which is emitted for **all 181** ungated by the app filter. Builder scope (app-subset) is orthogonal to the 181-message completeness of the read/reify/args + manifest surface.

**Sign-off flag**: this app-subset builder scope is a **precision correction** to the earlier "typed builder for all 181" wording (SC-001/FR-001/V-2). It is anchored on the spec's own "same scope 067/069 emit" language (`spec.md` AC-2) and the 069 precedent, but because it flips the literal "181/181 builder" count it MUST be **confirmed by the user at Gate A sign-off**. The only thing that would force a re-`/plan` is the user rejecting the app-subset and demanding typed builders for admin/session frames (which no tier has ever had, and which the session engine — not the typed API — owns).

## R3 — `app_version_enum("vlatest")` special-case (the generated `version_v`)

**Decision**: In `gen_util.hpp:248-253`, special-case `ns == "vlatest"` → `application_version::v50sp2` (NOT `Unknown`).

**Rationale**: Without a special-case, `app_version_enum` would emit `application_version::vlatest`, which does not exist (enum caps at `v50sp2`; 074 added no such member) — a compile error in generated code (spec Context fact 5). Mapping to `v50sp2` is **truthful**: a FIX Latest message's application version on the wire is v50sp2 (ApplVerID 9). This differs from the `vt11`→`Unknown` case (FIXT is a session-transport layer with no application version); FIX Latest *does* have one. The resulting `version_v = application_version::v50sp2` on `vlatest` classes creates no dispatch ambiguity because `vlatest` is excluded from `dispatch_application` (R7) — `version_v` is an identity tag, not a dispatch key.

**Alternative considered**: `→ Unknown` (literal vt11 mirror) — rejected as less truthful; it would erase the real application-version identity FIX Latest carries.

## R4 — Build option: name, default, CMake wiring

**Decision**: Add `FIXPP_CODEGEN_FIX_LATEST` (BOOL, CACHE, **default ON**) in `cmake/Codegen.cmake`. When ON, append a fifth codegen invocation `--xml <...>/OrchestraFIXLatest.xml --out <OUT>` to the existing four (`ir.cpp`/`main.cpp` need no driver change — the loader is auto-selected per R1). When OFF, the fifth invocation and the `vlatest/` output are omitted entirely.

**Rationale**: Mirrors the `FIXPP_CODEGEN_V44_FAMILIES` precedent (CACHE STRING, default `all`). Default ON satisfies the v1.0 "ship FIX Latest" obligation without a manual flip (spec Clarifications 2026-07-15), while the option gives downstream consumers and WSL2 devs an escape hatch. CI runs both paths: the ON path through the full sanitizer/preset matrix; a dedicated OFF-path job asserts the legacy-only output is byte-identical to today (FR-004/SC-003).

**Naming note**: a dedicated boolean (not folding into `FIXPP_CODEGEN_V44_FAMILIES`) — the families knob is a *within-version* family filter; this is a *whole-version-tier* toggle. Distinct concerns → distinct options.

**OFF-path stale-output lifecycle (P2-5 — required CMake behavior)**: with configure-time codegen, toggling `FIXPP_CODEGEN_FIX_LATEST` ON→OFF can leave `${build}/_codegen/include/fixpp/vlatest` on disk (and a stale include path / interface target), which would spuriously pass a "vlatest present" build or spuriously fail V-7's "assert `vlatest/` absent." The CMake wiring MUST therefore: (1) **track the last-used option value** (e.g. an internal `FIXPP_CODEGEN_FIX_LATEST_LAST_USED` cache var) and **force reconfigure/regeneration when it changes**; (2) on OFF, **remove `${FIXPP_CODEGEN_OUT_DIR}/vlatest`** (the generated dir) so no stale headers survive; (3) ensure no `fixpp::vlatest` interface target / include path is exported when OFF. V-7 then asserts BOTH filesystem absence of `vlatest/` AND the absence of any `fixpp::vlatest` target/include path.

## R5 — Non-circular completeness census (FR-006, the load-bearing check)

**Decision**: A census test that builds its **ground-truth set by parsing the raw `OrchestraFIXLatest.xml` directly** (independent pugixml walk, NOT via `OrchestraLoader`/`Dictionary`), transitively resolving `<component>` references and recursing `<group>` to enumerate, per message, the **full member-field set at all depths** as a multiset of **occurrence-path keys** `(MsgType, group_path/no_tag_path, tag, presence/rule, datatype)`. It then asserts **exact-multiset equality** (symmetric difference empty — not subset, not a flat per-message tag set) against the **emitted per-message set**. A flat tag set is rejected: it cannot distinguish a top-level tag from an in-group tag, catch a field moving between groups, or catch a tag reused under different parents — precisely the errors the census must discriminate.

**Non-circularity argument (N-1 — re-argued, two independent walkers).** This is subtler than "loader vs raw" and MUST be stated precisely, because the RC-A fix changes the provenance of the emitted manifest. The emitted manifest is **projection-sourced on ALL dimensions** — it derives entirely from the R2b Orchestra projection's raw declaration-order walk (message membership *and* nesting alike), NOT from `OrchestraLoader`→`Dictionary` (the occurrence-path / nesting data is not even present there — tag-deduped / immediate-parent-only, R2b output 4). So the census-vs-manifest non-circularity is **uniform across every dimension**: both the message-membership dimension (does message M exist; does tag T belong to M at all) AND the nesting/occurrence dimension (`group_path`, depth, tag-reused-under-different-parents) are compared as **double-entry: two INDEPENDENTLY-IMPLEMENTED raw declaration-order walkers**, not loader-vs-raw on any dimension. A shared Orchestra-read bug in a single walker (dropped message, dropped / mis-nested / wrong-depth occurrence) then appears on one side only → the census fails. (Scope note: this census-vs-manifest double-entry pins the **projection** — and the app-subset builder surface that consumes `group_order`, the same projection output. The **shipped universal read/reify/args classes** derive from a *different* `MessageIR`/Dictionary path and are pinned by the separate manifest↔class consistency leg V-1b — see "Emitted-set source ↔ shipped-class consistency" below.)

**Hard constraint (else the census is blind):** the census's raw-XML walker MUST share **no code** with the `ir.cpp` R2b Orchestra projection — it is a separate, independently-implemented declaration-order walk. If the census reused the projection walk (the DRY default), a bug in that one walk would corrupt BOTH sides identically and pass green — landing precisely the project's "corpus built from the same read it checks is blind" anti-pattern, as the final rewrite. Two independent implementations are the double-entry check that makes the nesting dimension non-circular. Directly addresses the "corpus built from the read it checks is blind" and "exact-SET not subset" anti-patterns.

**Emitted-set source**: a dedicated **per-message manifest emitted from the R2b lossless occurrence list** (per message, its ordered field occurrences as `(MsgType, full group_path, tag, rule, datatype)` — every one of the five occurrence-path key dimensions). It MUST derive from the R2b projection's occurrence list, NOT from `MessageIR.fields` (which is dictionary-derived, tag-deduped, and carries only `FieldRef.group_no_tag` = immediate parent — lossy against the multi-level `group_path` key). This is a **new deterministic codegen output** (a per-version `Manifest` file, emitted by the codegen tool alongside the headers — mirroring how `main.cpp:91` already writes a per-version `NormativeReferences.md`), so it is a codegen touch-point (adds one `emit_manifest` function + a `write_file` line in `main.cpp`, and is **golden-guarded** by the determinism gate R8/V-4 like every other emitted artifact). The census (a separate test binary) reads that emitted manifest as text — it cannot reach the in-process IR — which is why a machine-readable emitted artifact is required, not runtime reflection of the typed structs. The manifest MUST be genuinely **per-message**; it MUST NOT be sourced from the read-side group flyweights `fixpp::<ns>::groups::G_<no_tag>`, which the emitter produces **once per version** as the **deduped UNION** of members across every message using that `group_no_tag` (`emit_messages.cpp:403-419`) — comparing a per-message raw-XML membership against a version-wide union would either spuriously mismatch or mask a real per-message drop. The bare typed-`Args` structures are also insufficient as the sole source (their fields are all `std::optional`, so they carry group-path + datatype via nesting/type but not the presence/rule dimension). The manifest is thus **projection-sourced** (the R2b raw declaration-order walk) — the same independent walker whose double-entry against the census raw-XML walker makes N-1 non-circular; it does NOT derive from `MessageIR`/Dictionary.

**Emitted-set source ↔ shipped-class consistency (V-1b — the read-surface non-circular leg).** The manifest being projection-sourced has a consequence that MUST be closed: the census pins *manifest ≡ raw-XML*, but the **shipped universal read/reify/args classes** (all 181) are NOT emitted from the manifest — they come from the *unchanged* `emit_messages`/`emit_validator`/reify path off `MessageIR`/Dictionary (research row summary: "Deliberately NOT touched"), a **different derivation** the manifest is explicitly forbidden from sourcing. So the census alone pins only the **projection + app-subset builder** surface (`group_order`, the same projection output, feeds `emit_builders`); it does not prove *shipped read class ≡ raw-XML*. The only other leg touching those classes — the FR-007 differential round-trip — is **circular** (spec US2: the runtime path and the typed classes both consume the same `vlatest` Dictionary; round-trip also cannot detect an *absent* field). A Dictionary-path completeness drop in a shipped read class would therefore pass BOTH green. To close this, add a **manifest↔emitted-class consistency gate (V-1b, `contracts/build-and-verification.md`):** assert the emitted per-message manifest's field set **==** the actually-reachable per-message field set of the **shipped typed read/reify/args class** (extracted from the emitted `fixpp::vlatest` artifacts) — message set for all 181, and per-message field set at the granularity the read classes carry. Because the manifest is projection-sourced and the class is `MessageIR`/Dictionary-sourced, V-1b is a cross-check of **two different derivations** (not a self-comparison), so composing `class ≡ manifest` (V-1b) ∘ `manifest ≡ raw-XML` (census) yields **`class ≡ raw-XML`** for the read surface *non-circularly*. V-1b MUST be proven RED under a synthetic dropped-field/dropped-message on the `emit_messages`/reify (class) side (a class-side mutation, distinct from N-1's manifest/raw-XML-walker mutations).

**Per-surface granularity (state honestly — do NOT overclaim occurrence-path for the read classes).** The census pins the **projection/builder** surface at full **occurrence-path** granularity `(MsgType, group_path, tag, presence, datatype)`. The **universal read/reify/args** surface is pinned (via V-1b ∘ census) at the coarser **class-reachable-field** granularity — tag-deduped top-level fields + version-wide union group flyweights `G_<no_tag>` (`emit_messages.cpp:403-419`) — because that is what the shipped read classes physically carry; a faithful class-side check is necessarily coarser than the manifest's occurrence-path granularity. For the V-1b comparison the manifest is projected DOWN to class-reachable granularity; the class side is not lifted up to occurrence-path. Occurrence-path completeness is proven for the projection/builder surface; class-reachable-field completeness for the read surface.

**Discrimination proof**: the census MUST be shown to go RED under synthetic dropped-message, dropped-field, **wrong-parent / wrong-depth**, AND reused-tag-under-different-parents mutations (mutation-tested witness, per the project's false-green discipline) — an observing-but-not-asserting census, or one that only catches dropped message/field, is a false-green against path errors.

**Group-member resolution**: the raw-XML walker must match the emitter's flattening exactly — resolve components transitively, recurse nested groups (depth-7 max per the 074 spike), and include reused group tags under each parent context. This is the census's core complexity.

## R6 — Build-cost measurement (owed by the spec; informs the ON default)

**Decision**: Treat the precise cost as a **measured quantity captured as the first `/implement` task**, not an ex-ante guess baked into the plan. The measurement records: configure-time delta, clean-compile wall-time delta (ON vs OFF, per preset), and binary-size delta (`libfixpp` + test binaries). The ON default (R4) **holds** unless the measurement is surprising — concretely, if the ON build materially risks a CI-job timeout or the binary-size delta is disproportionate — in which case it is re-raised with the user before merge.

**Ex-ante bound (not a substitute for measurement)**: the `vlatest` tier is **181 messages**, comparable in scale to the existing `v50sp2` tier (156 messages) that every build already compiles. So enabling `vlatest` is expected to add roughly **one v50sp2-sized tier's** compile/binary cost — a known, already-tolerated order of magnitude, not a novel blow-up. This bound is why default-ON is a reasonable starting posture; the T1 measurement confirms or refutes it. (Ex-ante vs measured discipline: predictions here are ex-ante; the lcov/'time'/size numbers are captured at `/implement`.)

## R7 — Dispatch exclusion (the single generated surface) + injective-map preservation (FR-009 / SC-005)

**Verified precondition (World A — code-read this session, grade-1)**: the generated `validate`/`reify` paths acquire their dictionary **caller-supplied**, not via a version-keyed registry — so generating the vlatest typed classes with correct typed validate + reify + round-trip is **INDEPENDENT of the deferred `version_registry` re-keying**, and R3's `version_v = v50sp2` is genuinely inert. Evidence: the generated validator emits only `constexpr static` rule tables (`emit_validator.cpp:24-88`) — there is no generated `validate_<Msg>` runtime lookup; the runtime `dictionary_driven_validator` takes its `table_view` as a **ctor argument** (`include/fixpp/wire/validator.hpp:111-112`). Generated reify (`emit_reify.cpp`) is a **dict-free** deep byte copy (`:328-345`); `version_v` (`:151-153`) is only returned by `which()` (`:184-185`), never a lookup key. `version_registry::get()` is a session/engine-config artifact, never called by generated code. **⇒ The deferral holds; this feature does not need the re-keying.**

**One generated application-dispatch surface, excluded (no emitter change needed)**: there is exactly **one** generated `application_version`-keyed surface — `emit_dispatch_application` (`emit_dispatch.cpp:174`) emits the function `dispatch_application(...)` (`:210-211`) into the header file `_dispatch/reify_dispatch_application.hpp` (`:179`), an inline helper **called by `dict::reify`** (`:203-206`) to type a raw inbound wire message. Its outer switch iterates `kAppVersions` (`emit_dispatch.cpp:61-65`), which lists only v42/v44/v50sp2, matched by `ns` (`:224-232`); no `vlatest` case is produced. (`dispatch_application` = the function name; `reify_dispatch_application.hpp` = its header-file name — the **same** single surface, not two. There is no separate validator application-dispatch switch: the generated validator emits only `constexpr` rule tables — `emit_validator.cpp:24-88` — and the runtime `dictionary_driven_validator` takes its `table_view` directly, with no version dispatch.) `resolve_application_version(...)` can only return `v50sp2` for FIX Latest (no `application_version::vlatest`), so a raw inbound Latest message routed through it would mis-type to v50sp2 — the deferred path.

This is the desired behavior: FIX Latest classes generate/validate/round-trip via the **direct typed API + caller-supplied dict**, but are unreachable via the auto-dispatch surface, and the wire-ApplVerID map stays injective (no duplicate `case application_version::v50sp2`).

**Witnesses (required by SC-005)**: assert (a) `dispatch_application` for a raw FIX-Latest-only wire message → does NOT produce a `vlatest`-typed owner (it either mis-resolves to v50sp2's default or fails loud — pin the *actual* deferred behavior so the ApplExtID feature has a regression anchor when it fixes it); (b) exactly one `application_version::v50sp2` case exists in the generated switch (no duplicate). These pin the deliberate exclusion so the future ApplExtID feature adds reachability + re-keys consciously, not by a silent `kAppVersions` edit that breaks injectivity.

## R8 — Codegen determinism golden

**Decision**: Regenerate and check in the codegen golden extended with the `vlatest` tier **and the new per-message census manifest** (R5); the existing codegen determinism test MUST cover both so a non-deterministic or stale emit fails CI (byte-diff against the checked-in golden). The golden regen is a first-class task, run under the full ctest (narrow-target verify misses the determinism hang — established lesson). *[superseded 2026-07-16 — see contracts/build-and-verification.md V-4/V-7: golden = Messages.hpp only + relative byte-diff; `Manifest.txt` is NOT goldened (correctness pinned by V-1/V-1b instead)]*

**Golden location + inventory (RC-C / P2-4)**: goldens live under **`specs/<id>/contracts/golden/`** (verified: `specs/003-dictionary-codegen/contracts/golden/` holds the four `*_Messages.golden.hpp`; `specs/069-v44-all-families/contracts/golden/` holds `v44_Builders_official.golden.hpp`). There is **no `tools/codegen/golden/`**. The existing golden covers only `Messages.hpp` (4 versions) + one v44 `Builders.hpp` — it does NOT yet cover `Fields/Validator/Reify/_dispatch`. Because V-7 diffs the legacy `v42/v44/v50sp2/vt11` tiers + `_dispatch/` against the checked-in golden, this feature MUST **extend the checked-in golden to that full tier + `_dispatch/` inventory** (an explicit task) so V-4 and V-7 cite one consistent inventory and path. If the extension is not done, V-7 MUST be narrowed to only the artifacts actually goldened — but the extension is preferred (it is what makes the "byte-identical" claim executable). *[superseded 2026-07-16 — see contracts/build-and-verification.md V-4/V-7: golden = Messages.hpp only + relative byte-diff]*

**Rationale**: The codebase already ships checked-in codegen goldens and a determinism gate; omitting `vlatest` from the golden would leave the largest new tier unguarded against non-deterministic ordering (e.g., unordered map iteration in the emitter) and against stale-tool regeneration. ## R9 — Fail-closed on unknown Orchestra datatypes (FR-010)

**Decision**: Inherit 074's datatype gate — no new codegen-side gate. `OrchestraLoader` already fails closed (`orchestra_parse_error : xml_parse_error`) on a datatype outside the mapped set; codegen consuming that loader therefore never sees an unknown-datatype field (EP303 has none — 074's Deliverable #1 catalogue). Add a small witness: codegen over a synthetic Orchestra fragment carrying an unmapped datatype MUST fail closed (thrown, non-zero exit), not emit a mis-typed field.

**Rationale**: Reuses the proven fail-closed path rather than adding a parallel one (mirror an existing fail-closed disposition; don't invent a second). The witness proves the path is live for the codegen entry point, not just the runtime loader.
