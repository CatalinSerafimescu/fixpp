# Contract: `fixpp::vlatest` Generated Typed API

**Nature**: this feature exposes no *hand-written* public API. Its contract is the **shape of the generated typed surface**, which MUST match the legacy tiers' shape exactly (067/069) so callers use FIX Latest identically to FIX 4.4.

## C-1 — Namespace & artifacts

- All FIX Latest typed classes live under `namespace fixpp::vlatest` (groups under `fixpp::vlatest::groups`, validators under `fixpp::vlatest::validator`), disjoint from every other tier.
- **Surface scope (Option A, per 067/069):** for **all 181** EP303 messages the emitter produces the universal artifacts — a typed args struct, readback accessors, and `dict::reify()` participation; for the **application subset** of the 181 (per the R2b `category→is_application` mapping) it additionally produces `build_<Msg>` + `validate_<Msg>`. This is the exact split the merged 069 emitter implements (read/reify/args universal; `emit_builders` app-scoped). No new artifact kind, no missing kind. Admin/session frames having no `build_<Msg>` is by design. **[DEFERRED 2026-07-16 — see spec.md Clarifications → Session 2026-07-16]** The `build_<Msg>` + `validate_<Msg>` app-subset leg above is deferred to a follow-up feature (`emit_builders` stays v44-only; no `vlatest/Builders.hpp` is emitted). What ships in this PR is the universal all-181 read/reify/args/readback tier only.
- Each class carries `version_v == application_version::v50sp2` (truthful; FIX Latest wire app-version is v50sp2).

## C-2 — Behavioral parity with legacy tiers

- **[DEFERRED 2026-07-16 — see spec.md Clarifications → Session 2026-07-16]** `build_<Msg>` → serialized wire bytes that parse and read back field-for-field (round-trip fidelity), for the **application subset**. **[DELIVERED]** all 181 round-trip via the universal reify/read-back path.
- `validate_<Msg>` → same **required/group-presence** semantics and diagnostics a legacy typed validator gives — a thin wrapper over `wire::validate_required<T>` operating on the typed `Args`, **dict-free, with no enum/type/domain check** (identical scope to 067/069). Enum/type/domain validation is a **separate runtime surface**: the `dictionary_driven_validator` constructed with a caller-supplied `vlatest` `table_view` (`validator.hpp:111-112`), run over the parsed wire bytes → `wire_field_value_out_of_range` (40) on an enum violation (075). It is NOT `validate_<Msg>`, and it is reachable independent of the deferred dispatch (caller supplies the dict).
- Field membership (incl. nested group members at all depths, resolved components) matches the raw `OrchestraFIXLatest.xml` exactly — enforced two-leg: the census (V-1) pins the projection/builder surface at occurrence-path granularity, and the manifest↔class consistency gate (V-1b) pins the shipped read/reify/args classes at class-reachable-field granularity, so `class ≡ manifest ≡ raw-XML` non-circularly.

## C-3 — Reachability boundary (deliberate)

- FIX Latest typed classes are reachable **via the direct typed API with a caller-supplied FIX Latest dictionary only** (verified World A: the runtime validator takes its `table_view` as a ctor argument; reify is dict-free — no version-keyed registry lookup, so the typed path is independent of the deferred `version_registry` re-keying).
- They are **NOT** reachable via the generated application-version auto-dispatch surface — the single `dispatch_application(...)` helper emitted into `_dispatch/reify_dispatch_application.hpp` (the reify application switch called by `dict::reify` to type a raw inbound wire message). There is exactly **one** such surface — the generated validator emits only `constexpr` rule tables (no application-dispatch switch), so there is no separate "validator dispatch." `dispatch_application` keys on `application_version` (`kAppVersions` = v42/v44/v50sp2), which would collide `vlatest` onto v50sp2. A raw FIX-Latest-only inbound message routed through it does NOT land on a `vlatest` class. This boundary is intentional (FR-009) and is the seam owned by the deferred ApplExtID(1156)=303 / `version_registry` re-keying feature.

## C-4 — Non-regression (frozen surfaces)

- **Zero** change to: the C ABI (frozen 1.5.0), the Python surface, the link-ABI, and the generated bytes of the v42/v44/v50sp2/vt11 tiers — whether the FIX Latest option is ON or OFF.
