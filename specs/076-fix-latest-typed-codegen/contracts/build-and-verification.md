# Contract: Build Option & Verification Gates

## B-1 — `FIXPP_CODEGEN_FIX_LATEST` (CMake BOOL, CACHE, default ON)

| State | Guaranteed behavior |
|-------|---------------------|
| **ON** (default) | The codegen emits the `fixpp::vlatest` tier from `OrchestraLoader` over `OrchestraFIXLatest.xml`; the tier is compiled and available. |
| **OFF** | No `vlatest` generation or compilation. The build succeeds and produces output for the legacy tiers **byte-identical** to a `main` build without this feature. |

- **Invariant**: with the option ON *or* OFF, the v42/v44/v50sp2/vt11 generated bytes are unchanged (additive-only).
- **Toggle lifecycle (P2-5, required CMake behavior)**: with configure-time codegen, an ON→OFF toggle MUST NOT leave stale `vlatest` output behind. The CMake wiring MUST (1) **track the last-used option value** and **force reconfigure/regeneration when it changes**; (2) on OFF, **remove `${FIXPP_CODEGEN_OUT_DIR}/vlatest`** so no stale headers survive. **[gate-b/r2 correction]** (3) is NOT a separate `fixpp::vlatest` interface-target/include-path export gate — per T015 there is no dedicated `fixpp::vlatest` CMake INTERFACE target in the first place (every tier shares the single `_codegen/include` root), so "no vlatest export when OFF" reduces to, and is fully satisfied by, (2)'s filesystem-absence removal. V-7 asserts that filesystem absence; there is no separate target/include genex to witness (see V-7 for the full accounting).
- **CI**: the ON path runs the **full sanitizer/preset matrix** (identical coverage to legacy tiers); a dedicated **OFF-path** job asserts the byte-identical legacy-only output.

## V-1 — Completeness census (FR-006) — MUST assert, not observe

- Ground truth = messages+fields enumerated **directly from raw `OrchestraFIXLatest.xml`** (components resolved, groups recursed to all depths), by a walker **independently implemented from the `ir.cpp` Orchestra projection** (N-1 — shares no code), as a multiset of **occurrence-path keys** `(MsgType, group_path/no_tag_path, tag, presence/rule, datatype)`.
- Emitted side = a dedicated **per-message manifest emitted from the Orchestra IR projection's lossless occurrence list** (research R2b; carrying all five key dimensions); **NOT** from `MessageIR.fields` (tag-deduped, immediate-parent-only — lossy) and **NOT** the read-side group flyweights `fixpp::<ns>::groups::G_<no_tag>`, which are a version-wide deduped UNION (`emit_messages.cpp:403-419`) and cannot express per-message equality. Emitted for **all 181** (ungated by the app-subset builder filter).
- **Non-circularity (two independent walkers, N-1):** because the emitted manifest's nesting data is itself a raw declaration-order walk (the projection), non-circularity on the nesting/occurrence dimension is a **double-entry cross-check of two independently-implemented walkers**, not "loader vs raw." The census walker sharing code with the projection would land the "corpus built from the same read it checks is blind" anti-pattern.
- Assertion = **exact-multiset equality** (symmetric difference empty) at message level (181==181) **and** per-message occurrence-path level. A flat per-message tag set is insufficient (cannot catch top-level-vs-in-group, cross-group movement, or reused-tag-under-different-parents).
- **Discrimination**: proven RED under synthetic dropped-message, dropped-field, **wrong-parent / wrong-depth**, AND reused-tag-under-different-parents mutations (mutation-tested witness). A census that cannot go red is a false-green and fails this contract.
- **Surface pinned**: V-1 non-circularly pins the **projection + app-subset builder** surface at **full occurrence-path granularity** (the manifest is the projection serialized, and `group_order` — the same projection output — feeds `emit_builders`). It does NOT, by itself, pin the shipped universal read/reify/args classes: those are emitted from a **different, unchanged derivation** (`emit_messages`/`emit_validator`/reify off `MessageIR`/Dictionary), and the manifest is explicitly forbidden from sourcing them. That surface is pinned by **V-1b composed with V-1** (below).

## V-1b — Manifest ↔ emitted-class consistency (FR-006 read-surface leg) — MUST assert, not observe

- **Why this gate exists**: V-1 proves *manifest ≡ raw-XML*, and FR-007/V-2's differential round-trip is **circular** (spec.md US2 — the runtime path and the typed classes both consume the same `vlatest` Dictionary; round-trip also cannot detect an *absent* field). Neither leg non-circularly pins the **shipped universal read/reify/args classes** (all 181), which derive from `MessageIR`/Dictionary, not from the projection. A Dictionary-path completeness drop in a shipped read class — a whole message or a top-level field dropped by `emit_messages`/`collect_top_fields`, or a latent `OrchestraLoader` drop — would otherwise pass V-1 (a separate, still-correct derivation) AND the round-trip (circular / blind to omission) green. V-1b closes that hole.
- **Assertion**: the **emitted per-message manifest's field set** (projection-sourced) **==** the **actually-reachable per-message field set of the shipped typed read/reify/args class** (extracted from the emitted `fixpp::vlatest` artifacts — the deliverable), at two levels: (a) the **message set for all 181**, and (b) the **per-message field set at the granularity the shipped read classes carry** — i.e. tag-deduped top-level fields + the set of version-wide union group flyweights (`G_<no_tag>`) the message reaches. The manifest (finer, occurrence-path) is projected DOWN to that class-reachable granularity for the comparison; the class side is NOT lifted up to occurrence-path (the read classes physically do not carry per-message occurrence paths — see granularity note).
- **Non-circularity of the composition**: the manifest is **projection-sourced** (independent of the class's Dictionary derivation), so V-1b is a genuine cross-check between **two different derivations** (projection vs `MessageIR`/Dictionary), NOT a self-comparison. Composing the legs: `class ≡ manifest` (V-1b) ∘ `manifest ≡ raw-XML` (V-1) ⟹ **`class ≡ raw-XML`** for the universal read surface — non-circularly, at **class-reachable-field granularity**. No leg is both circular and load-bearing (the circular round-trip is now redundant for completeness, retained only for value-fidelity).
- **Granularity (stated honestly, per-surface)**: the projection/builder surface is pinned at **occurrence-path granularity** (V-1); the universal read/reify/args surface is pinned at the coarser **class-reachable-field granularity** (V-1b ∘ V-1). This is because the shipped read classes carry **tag-deduped top-level fields + version-wide union group flyweights** (`emit_messages.cpp:403-419`), so a faithful class-side check is necessarily coarser than the manifest's occurrence-path granularity. Occurrence-path completeness is NOT claimed for the read classes; class-reachable-field completeness IS.
- **Discrimination**: proven RED under a synthetic **dropped-field / dropped-message on the `emit_messages`/reify (class) side** (mutation-tested witness — distinct from V-1's mutations, which target the raw-XML/manifest walkers). A V-1b that cannot go red under a class-side drop is a false-green and fails this contract.

## V-4 — Determinism golden (R8)

- **Golden inventory (as landed — gate-b/r2 correction):** the checked-in golden under **`specs/076-fix-latest-typed-codegen/contracts/golden/`** (goldens live under `specs/<id>/contracts/golden/`, cf. `specs/003-dictionary-codegen/contracts/golden/`, `specs/069-v44-all-families/contracts/golden/` — there is **no `tools/codegen/golden/`**) is **`vlatest_Messages.golden.hpp` ONLY** — matching the 003/069 per-tier `Messages.hpp`-only precedent (`golden/README.md`). There is **no** extended golden for `Fields/Validator/Reify/NormativeReferences.md/Manifest.txt/_dispatch/`; that extension was an earlier design note (RC-C / P2-4) superseded by the shipped inventory — do not re-introduce it without re-opening the golden README's rationale.
- The freshly generated `vlatest/Messages.hpp` is byte-identical to `vlatest_Messages.golden.hpp` under the **full** ctest run (not a narrow target) — a non-deterministic or stale emit fails CI. Asserted by `DeterminismTest.VlatestGeneratedMatchesGolden` (`tests/codegen/determinism_test.cpp:430`) and re-asserted on the ON leg of `AdditiveOffOnByteDiff` (`:517-522`). Because every CI run must independently match the SAME fixed golden, this transitively pins `vlatest/Messages.hpp`'s run-to-run byte-stability (a passing golden-anchor gate across successive runs already *is* the run-to-run identity claim for that one file).
- **Run-to-run determinism, vlatest tier (`DeterminismTest.VlatestByteIdenticalAcrossRuns`, `tests/codegen/determinism_test.cpp`).** `ByteIdenticalAcrossRuns` (AC-T1) drives two runs via `run_codegen()`, which invokes the tool over `kXmls` — the 4 legacy XMLs only (`FIX42/44/50SP2/FIXT11`) — and never the Orchestra XML, so it gives no run-to-run coverage for `vlatest/`. `VlatestByteIdenticalAcrossRuns` closes that gap directly: it mirrors `ByteIdenticalAcrossRuns`'s pattern (two independent runs into separate temp dirs, every file produced in run 1 compared byte-for-byte against the same relative path in run 2) but drives both runs via `run_codegen_vlatest_only()`, so the whole `vlatest/` tier (`Fields.hpp`, `Messages.hpp`, `Validator.hpp`, `Reify.hpp`, `NormativeReferences.md`, `Manifest.txt`) is pinned for run-to-run byte-stability — the same class of coverage the legacy tiers already have via `ByteIdenticalAcrossRuns`. `vlatest/Messages.hpp` is additionally pinned to the checked-in golden by `VlatestGeneratedMatchesGolden` above.

## V-7 — Additive OFF-path byte-diff gate (FR-004, SC-003)

- **Baseline (as landed — gate-b/r2 correction) = the EXISTING checked-in 003/069 goldens** (`specs/003-dictionary-codegen/contracts/golden/v42/v44/v50sp2/vt11_Messages.golden.hpp` + `specs/069-v44-all-families/contracts/golden/v44_Builders_official.golden.hpp`) — **NOT** a newly-extended 076 golden (there is no extended golden; see V-4). CI obtains these from the repo (checked-in goldens), NOT by re-comparing to a `main` checkout.
- **OFF job (leg a1/a2, `AdditiveOffOnByteDiff`, `determinism_test.cpp:494-515`)**: build with `FIXPP_CODEGEN_FIX_LATEST=OFF` and byte-diff the generated `v42/v44/v50sp2/vt11` `Messages.hpp` against those existing 003/069 goldens → MUST be identical; assert `vlatest/` is **absent** on the filesystem.
- **ON job (leg a3, `:517-522`)**: build with the option ON and assert `vlatest/Messages.hpp` matches the 076 golden (`vlatest_Messages.golden.hpp`, V-4).
- **Additivity of everything else (leg b, the relative/additive discriminator, `:524-548`)**: `Fields/Validator/Reify/NormativeReferences.md/Manifest.txt/Builders.hpp` per legacy version, plus the shared `_dispatch/*.hpp`, have **no checked-in golden at all** (neither a 003/069 golden nor a 076 golden) — their additivity is proven by a recursive walk asserting EVERY file the OFF-run produced is byte-identical to the SAME relative path under the ON-run. This is the only gate covering those files' additivity; it is a relative (OFF-vs-ON) comparison, not an absolute golden anchor.
- **"No `fixpp::vlatest` target/include exported when OFF" (P2-5):** per T015, there is **no separate `fixpp::vlatest` CMake INTERFACE target** in the first place — every tier (including `vlatest`) shares the single `fixpp::dict::{v42,v44,v50sp2,vt11}` / shared `_codegen/include` root (`cmake/Codegen.cmake`). So "no vlatest export when OFF" reduces to "no `vlatest/` subdirectory under that shared include root when OFF" — satisfied entirely by the OFF-leg filesystem-absence assertion above (leg a2); there is no separate target/include genex to witness.
- This makes the "byte-identical to `main`" claim of FR-004/SC-003 an executable gate rather than an observational note.
