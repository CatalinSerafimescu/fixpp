# Feature Specification: C-ABI Python-readiness — dictionary loader, transport-endpoint config, inbound field iteration

**Feature Branch**: `052-c-abi-python-readiness`
**Created**: 2026-06-25
**Status**: Draft
**Input**: User description: "C-ABI Python-readiness: close the three gaps the pre-Python C-ABI completeness audit found blocking a pure-C/Python consumer from the happy path, as an ADDITIVE MINOR (0.4.0 → 0.5.0). Dictionary loader (GAP-001), transport endpoint configuration (GAP-002), inbound field iteration (GAP-003). Unblocks PY-001."

> **Workstream context.** The three C-ABI engine features (A/049, B/050, C/051) shipped a surface that is *internally* round-trip-complete, but a **pre-Python C-ABI completeness audit** (`research/findings/capi-python-completeness-audit-2026-06-25.md`; Codex wrote the minimal pure-C happy-path client against `include/fix/c_api/` only, each finding Opus-source-verified) proved a **pure-C — therefore pure-Python — consumer cannot complete the happy path**: it cannot construct the `Dictionary` that `fixpp_session_config_set_dictionary` requires, cannot tell an initiator *where to connect*, and cannot enumerate an inbound message's fields without knowing every tag a priori. The 050/051 tests only worked through **test-only internal-cast seams** (L-050-1 dict seam, L-050-5 endpoint seam in `tests/capi/capi_loopback_support.hpp`) that a real consumer cannot use. This feature closes the three gaps so **PY-001 — the first real C-ABI consumer and the freeze validator — can be built**. It lands **before** the `0→1` ABI freeze deliberately: every addition here is purely additive (free now, breaking after `MAJOR>=1` per `[const §X.1]`), AND building PY-001 on the completed surface may force a *breaking* refinement to a shipped signature while it is still free. **Authoritative C-ABI shape contract:** `.specify/2i-capi.md` (`[2i]`). **The three gaps have three different `[2i]` provenances** (recorded in Clarifications) — this is the crux Gate A must review.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Load a real FIX dictionary from pure C (Priority: P1)

A C consumer (or a binding author) needs to obtain the `fixpp_dict_t` that `fixpp_session_config_set_dictionary` requires — by loading a bundled FIX XML data dictionary from a file path — entirely through `extern "C"`, with a stable numeric code on failure and no C++ exception crossing the boundary, and to release it when done.

**Why this priority**: Without it a pure-C/Python consumer **cannot configure a session at all** — the dictionary is a required, validated field of the session config and the only producer today is a test-only seam. It is the precondition for every other session operation.

**Independent Test**: A pure-C program calls `fixpp_dict_load_from_xml("dictionaries/FIX44.xml", &dict)`, gets `FIXPP_ERR_OK` and a non-null owning handle; passes it to `fixpp_session_config_set_dictionary` (which returns OK); `fixpp_dict_destroy(dict)`; confirms a non-existent / malformed path returns `FIXPP_ERR_CAPI_CONFIG_INVALID` with a non-empty `fixpp_strerror`, a NULL out-pointer returns `FIXPP_ERR_NULL_HANDLE`, and destroy is idempotent/NULL-safe — all without linking any C++ header.

**Acceptance Scenarios**:

1. **Given** a readable FIX XML dictionary file, **When** the consumer calls `fixpp_dict_load_from_xml(path, &out)`, **Then** `FIXPP_ERR_OK` and a non-null owning `fixpp_dict_t` whose underlying `shared_ptr<const Dictionary>` the subsequent `fixpp_session_config_set_dictionary` copies (so the dict outlives the handle via the config's own copy, per `[2i]` line 1344).
2. **Given** a path that does not exist or whose XML is malformed, **When** the consumer loads it, **Then** `FIXPP_ERR_CAPI_CONFIG_INVALID` (the construction-thunk fallback, `[2i]` line 652), a NULL out-handle, and a non-empty `fixpp_strerror` string — never a thrown C++ exception, never a crash.
3. **Given** a NULL path or NULL out-pointer, **Then** `FIXPP_ERR_NULL_HANDLE`.
4. **Given** any dict handle or NULL, **When** the consumer calls `fixpp_dict_destroy`, **Then** it is NULL-safe (NULL → no-op), releases the consumer's `shared_ptr` reference, never throws; a **second `fixpp_dict_destroy` on the same handle is a safe no-op** (the handle is tombstoned `tag_ = FIXPP_HANDLE_TAG_DEAD`, mirroring `fixpp_engine_destroy`); the dict's storage persists as long as any session still references it.

### User Story 2 - Configure where a session connects, from pure C (Priority: P1)

A C consumer needs to tell an **initiator** session which peer `host:port` to connect to (and an **acceptor** which port to bind, including reading back an OS-assigned ephemeral port) — through `extern "C"`, without any transport-level handle.

**Why this priority**: Without it a pure-C/Python initiator **cannot connect to anything** — the peer endpoint is set only via the test-only L-050-5 internal-cast seam. Together with US1 it is the minimum needed to stand up a live session, which PY-001 must do.

**Independent Test**: A pure-C program configures an initiator via `fixpp_session_config_set_tcp_endpoint(cfg, "127.0.0.1", 9878)`, opens + starts, and establishes against an acceptor; an acceptor configured with port 0 is read back via `fixpp_session_acceptor_bound_endpoint(session, &port)` to obtain the OS-assigned port; confirms a NULL cfg/host → `FIXPP_ERR_NULL_HANDLE`, and that the consumer never references `transport_send` or any transport handle.

**Acceptance Scenarios**:

1. **Given** a session-config builder, **When** the consumer calls `fixpp_session_config_set_tcp_endpoint(cfg, host, port)`, **Then** `FIXPP_ERR_OK` and the under-construction config's `reconnect_endpoint` is set to `{host, port}` (initiator peer / acceptor bind), with the internal `transport_send` placeholder set by the C-ABI layer (not the consumer).
2. **Given** a NULL cfg or NULL host, **Then** `FIXPP_ERR_NULL_HANDLE`; **Given** an empty host or an otherwise unusable endpoint, **Then** `FIXPP_ERR_CAPI_CONFIG_INVALID`.
3. **Given** an acceptor session configured with port 0 that has run at least one accept-loop step, **When** the consumer calls `fixpp_session_acceptor_bound_endpoint(session, &port_out)`, **Then** `FIXPP_ERR_OK` and the OS-assigned bound port (non-zero); **Given** a session not yet bound, **Then** a documented not-yet-bound result (port 0 / a stable code) the consumer can poll on.
4. **Given** a complete config (comp-ids, begin-string, role, security, **dictionary via US1**, **endpoint via US2**, **reset-policy via FR-005b**), **When** the acceptor is opened+started on one C-ABI engine (port-0 bind → `fixpp_session_acceptor_bound_endpoint` readback) and the initiator is opened+started on a **second** C-ABI engine dialing that read-back port, **Then** they establish over plaintext TCP loopback and exchange an application message — the first fully-public-C-ABI live round-trip. (Two engines: the port-0 readback requires the acceptor bound *before* the initiator config is knowable, and `fixpp_session_open` is register-before-start — the quickstart NOTE shows this canonical shape.)

### User Story 3 - Enumerate the fields of an inbound message without knowing tags a priori (Priority: P2)

A C consumer (or a binding exposing a Pythonic `for tag, value in msg`) needs to iterate the fields present in an inbound message — learn the field count and read each field's tag, value bytes, and length by index — rather than guessing every tag in advance.

**Why this priority**: Field iteration is what a binding needs to expose a message as an iterable/mapping; without it the consumer must know every tag a priori. It is P2 because the happy path (US1+US2 + the existing typed getters) is byte-functional without it — it is the ergonomic capability Python certainly needs but that does not block standing up a session.

**Independent Test**: Inside a receive callback, a pure-C program calls `fixpp_msg_field_count(msg, &n)`, then for each `i ∈ [0,n)` calls `fixpp_msg_field_at(msg, i, &field)` and reads `field.tag`/`field.value`/`field.len`; confirms every tag a scalar typed getter can read appears in the enumeration with matching **first-occurrence** value bytes — while repeated tags (repeating groups) make the enumeration a **superset** of the scalar-getter-readable set (no bi-directional equality) — that `field.value` aliases the wire buffer (zero global-heap), and that `i == n` returns `FIXPP_ERR_INDEX_OUT_OF_RANGE` — all without linking any C++ header.

**Acceptance Scenarios**:

1. **Given** an inbound `fixpp_msg_t` in the dispatch window, **When** the consumer calls `fixpp_msg_field_count(msg, &count_out)`, **Then** `FIXPP_ERR_OK` and the number of readable fields.
2. **Given** a field index `i ∈ [0, count)`, **When** the consumer calls `fixpp_msg_field_at(msg, i, &field_out)`, **Then** `FIXPP_ERR_OK` and a `fixpp_msg_field_t { tag, value, len }` whose `value` pointer aliases the wire buffer (no allocation) and is valid for the dispatch window; **When** `i >= count`, **Then** `FIXPP_ERR_INDEX_OUT_OF_RANGE`.
3. **Given** a NULL handle / NULL out-pointer, **Then** `FIXPP_ERR_NULL_HANDLE`; **Given** a destroyed/expired handle, **Then** `FIXPP_ERR_INVALID_HANDLE` — never undefined behaviour.
4. **Given** the same inbound message, **When** the consumer enumerates via iteration vs reads a known tag via `fixpp_msg_get_string`, **Then** the value bytes for that tag agree.

---

### Edge Cases

- **Dict file readable but not a valid FIX dictionary** → `FIXPP_ERR_CAPI_CONFIG_INVALID` (construction thunk catches the `XmlLoader` throw), NULL out-handle, fatal-level engine-internal log; no abort.
- **Dict handle destroyed while a session still uses it** → safe: the session holds its own `shared_ptr`; `fixpp_dict_destroy` releases only the consumer's reference (`[2i]` line 1344).
- **`fixpp_dict_destroy` called twice on the same handle** → safe no-op on the second call: the first rewrites the handle's `tag_` to `FIXPP_HANDLE_TAG_DEAD` and retains the shell in an allocation-free intrusive tombstone list (mirrors `fixpp_engine_destroy`; growth is O(load/destroy cycles), NOT O(live dicts) — see L-052-4); no double-free / post-destroy UAF (`[2i §4.2.1]`).
- **`set_tcp_endpoint` with port 0 on an initiator** → an initiator dialing port 0 is a config error surfaced at open/start, not at set-time (set-time validates host non-empty + stores; the engine rejects an undialable endpoint) — documented; the port-0 OS-assign semantics apply to **acceptor bind** only.
- **`acceptor_bound_endpoint` before the accept loop has run** → not-yet-bound (port 0); the consumer polls (same shape as the L-050-5 `wait_for_bound_port` seam, now public).
- **`field_at` value pointer used after the parent handle's lifetime** → a documented use-after-invalidation the consumer must avoid (same flyweight lifetime contract as the typed getters, `[2i §4.6]`); the window is the *handle's own* lifetime — the dispatch window for an inbound message, until `fixpp_msg_destroy` for a 051 view-backed clone; not enforced on the hot path.
- **Iteration over a 051 view-backed clone handle** → works: a clone's `view` points into its `owned_view_` (Index-mode), so `field_count`/`field_at` enumerate it the same way, with the **clone's** (destroy-bounded, session-independent) lifetime rather than the inbound dispatch window.
- **Iteration over an outbound (not-yet-committed) message** → out of scope for v1.0 (iteration is specified over inbound/parsed messages; behaviour on an outbound accumulator is unspecified/`INVALID_HANDLE` — confirm at plan).
- **Exception escaping a steady-state thunk** (`set_tcp_endpoint`, `acceptor_bound_endpoint`, `field_count`, `field_at`) → invariant violation → fatal log + `std::abort`, not translated (`[2i §5.2]`); only the construction-time `fixpp_dict_load_from_xml` translates.

## Requirements *(mandatory)*

### Functional Requirements — Group 1: dictionary loader (GAP-001 — implements the `[2i §2]` commitment-2 / §4.2 symbol)

- **FR-001**: The C ABI MUST expose `fixpp_dict_load_from_xml(const char* path, fixpp_dict_t** out_dict)` (the `[2i §2]`/§4.2-named symbol) in a new public header `include/fix/c_api/dict.h` (the `[2i]`-reserved name — line 281 / §3.10 commitment 5; it **coexists** in the same header with the 2c-owned `FIXPP_APPL_VER_*` constants — no collision, shared header — so the header name is NO `[2i]` deviation), loading a FIX XML data dictionary from a filesystem path via the production `fixpp::dict::XmlLoader::load`, producing an **owning** `fixpp_dict_t` that wraps a `std::shared_ptr<const fixpp::dict::Dictionary>` (the exact ownership model of `[2i]` line 1344, already realised by the L-050-1 seam). It is a **construction-time thunk** (`[2i §5.2]` whitelist): it catches `std::exception` and translates to `FIXPP_ERR_CAPI_CONFIG_INVALID` (`[2i]` line 652), never letting an exception cross `extern "C"`.
- **FR-001a**: The `[2i §2]` sketch writes the signature as `fixpp_dict_load_from_xml(path, error_out) → fixpp_dict_t*` (return-pointer style). The as-built 049/050/051 convention is `fixpp_error_t fn(…, T** out)` (error-return + out-param). FR-001 adopts the **as-built convention** (consistent with every shipped symbol); this signature-shape reconciliation is a **recorded LOCAL deviation in this feature's spec/contracts** and does NOT reopen `[2i]` (the v0.1 §2 sketch predates the convention solidifying — analogous to 051's FR-008a `fixpp_msg_commit` reconciliation).
- **FR-002**: The C ABI MUST expose `void fixpp_dict_destroy(fixpp_dict_t* dict)` (`[2i §4.2]`-named) — NULL-safe (NULL → no-op), releasing the consumer's `shared_ptr` reference, never throwing. The dictionary's storage persists while any session still holds a reference (refcounted; `[2i]` line 1344). Per the `[2i §4.2.1]` owning-handle discipline destroy is **idempotent double-destroy-safe via a handle tombstone**: `fixpp_dict` carries a `tag_` liveness token; `fixpp_dict_destroy` checks it, rewrites it to `FIXPP_HANDLE_TAG_DEAD`, and retains a bounded dead shell (dicts are O(few) per process — a binding loads a handful — so engine-style retention is bounded), making a second same-pointer destroy a safe no-op. The **tombstone mechanism mirrors `fixpp_engine_destroy`** (tag→DEAD + retained shell), but because `[2i §4.2.1]` (line 415) mandates every `*_destroy` be thread-safe, the symbol stays `FIXPP_THREAD_SAFE` and a process-global mutex MUST cover the **entire critical section as one atomic unit** — `{ check tag_ != DEAD, release the shared_ptr ref, rewrite tag_ = DEAD, insert into the bounded dead-shell registry }` — NOT merely the registry insert (the race is on the non-atomic `tag_` + `shared_ptr`, which sit OUTSIDE the registry); so concurrent same-pointer destroy is serialized (the second caller sees `tag_ == DEAD` under the lock and no-ops) — whereas `fixpp_engine_destroy`'s registry is unsynchronized under its as-built `FIXPP_SINGLE_THREAD` annotation. This is NOT the single-destroy-only `fixpp_msg_destroy` discipline.
- **FR-003**: `fixpp_dict_load_from_xml` MUST return `FIXPP_ERR_NULL_HANDLE` on a NULL `path` or NULL `out_dict`, and MUST set `*out_dict = NULL` on every failure path.

### Functional Requirements — Group 2: transport endpoint configuration (GAP-002 — `[2i §2]` non-goal #7 / §7.8, recorded LOCAL Gate-A deviation)

- **FR-004**: The C ABI MUST expose `fixpp_session_config_set_tcp_endpoint(fixpp_session_config_t* cfg, const char* host, uint16_t port)` writing `SessionConfig::reconnect_endpoint = {host, port}` (initiator peer endpoint / acceptor bind endpoint). The C-ABI layer MUST also set the internal `SessionConfig::transport_send` placeholder (the no-op the engine's auto-derived plaintext factory replaces at connect/accept) so the consumer never references it. Returns `FIXPP_ERR_NULL_HANDLE` (NULL cfg/host), `FIXPP_ERR_CAPI_CONFIG_INVALID` (empty/unusable host). Reentrancy: single-thread (a config setter, per the existing `fixpp_session_config_set_*` family).
- **FR-005**: The C ABI MUST expose `fixpp_session_acceptor_bound_endpoint(fixpp_session_t* session, uint16_t* port_out)` returning the acceptor's OS-assigned bound port (wrapping `Engine::acceptor_bound_endpoint(id).port`), for the port-0 ephemeral-bind workflow. Returns `FIXPP_ERR_NULL_HANDLE` (NULL session/out), `FIXPP_ERR_INVALID_HANDLE` (destroyed session); a not-yet-bound session yields `*port_out = 0` with `FIXPP_ERR_OK` so the consumer can poll. The host is the consumer-known bind host (no host-string out-param — avoids a host-string lifetime contract; the C++ surface exposes only `.port`). Reentrancy: thread-safe (atomic read of the engine snapshot, like `fixpp_session_is_established`).
- **FR-005a**: This feature adds **no** transport-level handle (`fixpp_transport_t` …) and does **not** use the deferred `fixpp_endpoint_t` PoD type — only a primitive `(host, port)` session-config setter and a `uint16_t` readback. **DECIDED (/speckit-clarify 2026-06-25): recorded as a LOCAL Gate-A deviation that does NOT reopen `[2i]`** (the 051 `fixpp_msg_commit`/FR-008a precedent) — the primitive-only setter sidesteps non-goal #7's transport-*accessor* scope and the §7.8 *PoD* deferral. `[2i §7.8]`'s deferral of the transport *handles* + `fixpp_endpoint_t` PoD is **unchanged** — those stay v1.x. Gate A reviews the recorded deviation but no Article XX amendment / `[2i]` co-update is performed.
- **FR-005b**: The C ABI MUST expose `fixpp_session_config_set_reset_seqnum_policy(fixpp_session_config_t* cfg, fixpp_reset_seqnum_policy kind)` (header `session.h`) writing `SessionConfig::reset_seqnum_policy_field`. The C11 enum `fixpp_reset_seqnum_policy { FIXPP_RESET_SEQNUM_BILATERAL_STRICT=0, FIXPP_RESET_SEQNUM_BILATERAL_LENIENT=1, FIXPP_RESET_SEQNUM_UNILATERAL=2 }` mirrors the C++ `enum class reset_seqnum_policy : uint8_t` (`session_config.hpp:92-95`, same enumerator values). Returns `FIXPP_ERR_NULL_HANDLE` (NULL cfg), `FIXPP_ERR_CAPI_CONFIG_INVALID` (out-of-range enum). Reentrancy: `FIXPP_SINGLE_THREAD` (a config setter). **Pinned preemptively (Gate-A r1 user decision)** so the reviewed ABI surface is deterministic at the freeze: SC-001 sets the policy explicitly (or confirms `bilateral_strict` establishment directly) rather than leaving a +1 contingency to an implement-time test. This brings the feature to **7** new exported symbols.

### Functional Requirements — Group 3: inbound field iteration (GAP-003 — net-new additive)

- **FR-006**: The C ABI MUST expose a PoD field-view struct `fixpp_msg_field_t { uint16_t tag; const uint8_t* value; size_t len; }` (in `include/fix/c_api/message.h`) and the accessors `fixpp_msg_field_count(const fixpp_msg_t* msg, size_t* count_out)` and `fixpp_msg_field_at(const fixpp_msg_t* msg, size_t index, fixpp_msg_field_t* field_out)`, enumerating **every `OffsetTable` entry of the parsed message in wire/document order** — one entry per wire occurrence (a tag repeated across N repeating-group instances yields N enumerated entries), including session header/trailer framing tags `8/9/35/49/56/34/52/10` when the inbound view holds them (no engine-maintained app-body filter — clarified 2026-06-25). This is an **operational** definition (the offset table = a multiset), NOT a bi-directional "== the typed-getter-readable set" claim — the scalar typed getters read only a subset (FR-007). `field_out->value` MUST **alias the wire buffer** (flyweight rule `[2b §6.4]`; no caller-buffer copy, **zero global-heap**), valid for the **parent handle's own lifetime** (the dispatch window for an inbound message; until `fixpp_msg_destroy` for a 051 view-backed clone).
- **FR-007**: The iteration accessors MUST return distinct documented codes: `FIXPP_ERR_NULL_HANDLE` (NULL handle / out-pointer), `FIXPP_ERR_INVALID_HANDLE` (destroyed/expired/type-mismatched handle), `FIXPP_ERR_INDEX_OUT_OF_RANGE` (`index >= count` — the existing group-cursor code, reused; no new error code). No C++ exception may cross the boundary. The enumerated field set MUST be **one-directionally** consistent with the typed getters: any tag a scalar typed getter (`fixpp_msg_get_string`) can read appears in the enumeration with matching value bytes **for its first occurrence** (getter-readable tags ⊆ enumeration). The reverse does NOT hold — under repeated tags the enumeration is a strict superset of the scalar-getter-readable set.

### Functional Requirements — Cross-cutting (versioning, reentrancy, allocation, gates)

- **FR-008**: Each new public C-ABI symbol MUST carry exactly one reentrancy class per `[2i §4.10]` (the 049 reentrancy CI gate extends to cover them, 0 unannotated): `fixpp_dict_load_from_xml` → `FIXPP_SINGLE_THREAD` (construction-time, per `[2i]` line 1187); `fixpp_dict_destroy` → `FIXPP_THREAD_SAFE` (tombstone tag rewrite + `shared_ptr` release + dead-shell insert all under one **full-critical-section** process-global lock — not a registry-only lock, since the race is on the non-atomic `tag_`/`shared_ptr` outside the registry — THREAD_SAFE per the `[2i §4.2.1]` line-415 mandate that every `*_destroy` be thread-safe); `fixpp_session_config_set_tcp_endpoint` → `FIXPP_SINGLE_THREAD` (config setter); `fixpp_session_config_set_reset_seqnum_policy` → `FIXPP_SINGLE_THREAD` (config setter); `fixpp_session_acceptor_bound_endpoint` → `FIXPP_THREAD_SAFE`; `fixpp_msg_field_count` / `fixpp_msg_field_at` → `FIXPP_REQUIRES_SESSION_LOCK` (the single conservative class the shared inbound read accessors carry, matching `[2i §4.6]`). As with the 051 `fixpp_msg_get_*` read-accessor family (051 FR-018; shipped `message.h:109-112`), detached-clone iteration is a **documented runtime handle-state guarantee OUTSIDE the per-symbol gate, NOT a second annotation**: on a 051 view-backed clone handle (which owns its own arena and survives session/engine teardown) the `field_count`/`field_at` reads are **`THREAD_SAFE`** — callable off the session strand from any thread — with the caller serializing concurrent access to the *same* clone handle. The static `check_capi_reentrancy.sh` gate checks one annotation per declaration and cannot distinguish an inbound-flyweight read from a clone read on the same shared symbol, so the gate stays unchanged and `[2i §4.6]` is NOT edited.
- **FR-009**: The published C-ABI version MUST receive an additive **MINOR** bump `0.4.0 → 0.5.0` (new exported symbols, no shipped-signature change, ABI layout untouched, `MAJOR` stays 0). The new symbols MUST be added to the ABI golden list (`tests/abi/golden/fixpp_capi_symbols.txt`) and `abidiff` MUST report the change as **additive** (no breaking re-definition).
- **FR-010**: The feature MUST mint **no** new `fixpp_error_t` codes and MUST keep the occupancy-drift gate (`tools/check_capi_occupancy.sh`) green **unchanged** (no `EXPECTED`/`EXPECT_COUNT` edit) — all failure modes reuse existing codes (`CAPI_CONFIG_INVALID`, `NULL_HANDLE`, `INVALID_HANDLE`, `INDEX_OUT_OF_RANGE`).
- **FR-011**: Construction-time thunk (`fixpp_dict_load_from_xml`) MUST translate caught C++ errors to `FIXPP_ERR_CAPI_CONFIG_INVALID` (`[arch §5.3]` carve-out); steady-state thunks (the endpoint setter, the bound-endpoint readback, the iteration accessors) MUST treat an escaping exception as an invariant violation → fatal log + `std::abort`, never a translated code (`[2i §5.2]`).
- **FR-012**: The feature MUST add the corresponding `[2i §9]`-style seams to the C-ABI test corpus: a **fully-public-C-ABI live round-trip** seam (US1 dict-from-XML + US2 endpoint setter → established initiator/acceptor pair → app message, replacing the L-050-1 + L-050-5 seams in a new pure-public-header test), a **zero-global-heap** allocation guard on the iteration path (counting-resource + mallocnesia dual gate), and the `acceptor_bound_endpoint` port-0 readback. The existing seam-based tests (`capi_loopback_support.hpp`) MAY remain for the internal suites, but the new SC-001 witness MUST use only public headers.
- **FR-013**: The feature MUST fix the stale `include/fix/c_api/session.h:190` doc comment ("app_payload_malformed → `FIXPP_ERR_UNKNOWN`") to reference the now-published `FIXPP_ERR_APP_PAYLOAD_MALFORMED` (051). Comment-only; no behaviour change.
- **FR-014**: The umbrella header `include/fix/c_api.h` MUST `#include <fix/c_api/dict.h>` so a consumer (and PY-001) including the single `<fix/c_api.h>` entry point (`[2i §2]` commitment-1 single-umbrella) sees the new `fixpp_dict_load_from_xml` / `fixpp_dict_destroy` symbols. The umbrella edit MUST NOT propagate the pre-existing stale `FIXPP_VERSION_*` / "0.2.0" version comment already in that file (out of 052's scope — just don't carry it forward).

### Key Entities

- **`fixpp_dict_t`** — opaque, owning (refcounted `shared_ptr<const fixpp::dict::Dictionary>`) handle, now **constructible from pure C** via `fixpp_dict_load_from_xml(path)` and released via `fixpp_dict_destroy` (idempotent, NULL-safe; the dict outlives the handle while any session references it). Implements the `[2i §4.2]` dict-handle discipline that was previously seam-only.
- **TCP endpoint configuration** — a primitive `(host, port)` session-config field (`reconnect_endpoint`), set via `fixpp_session_config_set_tcp_endpoint`; NOT a transport handle and NOT the deferred `fixpp_endpoint_t` PoD. The acceptor's OS-assigned port is read back via `fixpp_session_acceptor_bound_endpoint` (`uint16_t` only).
- **`fixpp_msg_field_t`** — a PoD `{ uint16_t tag; const uint8_t* value; size_t len }` field view aliasing the wire buffer, returned by `fixpp_msg_field_at`; lifetime bounded by the parent `fixpp_msg_t` handle's own lifetime (the dispatch window for inbound; until `fixpp_msg_destroy` for a 051 clone). The unit of the net-new field enumeration — emitted one per `OffsetTable` entry (a multiset; repeated tags yield repeated entries).
- **`fixpp_reset_seqnum_policy`** — a C11 enum (`STRICT=0/LENIENT=1/UNILATERAL=2`, mirroring the C++ `reset_seqnum_policy`) set via `fixpp_session_config_set_reset_seqnum_policy` into `SessionConfig::reset_seqnum_policy_field`; pinned so the SC-001 ABI surface is deterministic (FR-005b).

## Out of Scope

Reserved for a PY-001-driven follow-up.

(The **`reset_seqnum_policy` enum setter**, previously deferred here, is now **pinned into this feature** — FR-005b — so the SC-001 ABI surface is deterministic at the freeze.)

- **New `fixpp_error_t` codes / `[2i §4.3]` amendment** — none; all failure modes reuse existing codes.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A pure-C program (no C++ headers linked, no test seams) loads a bundled FIX dictionary from XML, configures an initiator + acceptor with comp-ids/begin-string/role/security/dictionary/**endpoint**/**reset-policy**, stands the acceptor up on one C-ABI engine (port-0 bind, read back via `fixpp_session_acceptor_bound_endpoint`) and the initiator up on a **second** C-ABI engine (dialing the read-back port), establishes over plaintext TCP loopback, and exchanges an application message — the **first fully-public-C-ABI live round-trip** (today impossible without L-050-1/L-050-5 seams). The two-engine port-0 shape is canonical (the quickstart NOTE), not a brevity simplification.
- **SC-002**: A pure-C program enumerates every field of an inbound message via `fixpp_msg_field_count` + `fixpp_msg_field_at`; for every tag a scalar typed getter can read, that tag appears in the enumeration with a byte-for-byte-matching value **for its first occurrence** (the one-directional FR-007 invariant; the enumeration is a superset under repeated tags, never claimed equal). **The witness MUST exercise a repeating-group message** (≥1 tag occurring multiple times) — a flat message masks the superset/first-occurrence relationship exactly as the 051 STRING-only test dict masked the group-grammar validation gap (the 051 Gate B lesson).
- **SC-003**: The iteration path is verified **zero global-heap** under the allocation guard (counting-resource + mallocnesia LD_PRELOAD dual gate); each `field.value` is confirmed to alias the wire buffer. A **clone-iteration cross-strand witness** iterates a detached 051 clone **off the session strand** (a different thread, after the source dispatch window closed) and asserts correct reads — exercising the runtime-`THREAD_SAFE` clone guarantee (FR-008 / 051 FR-018).
- **SC-004**: `fixpp_dict_load_from_xml` returns a usable dict for every bundled `dictionaries/FIX*.xml`, and returns `FIXPP_ERR_CAPI_CONFIG_INVALID` (with a non-empty `fixpp_strerror`, no abort) for a missing path and for a syntactically-malformed XML. A **TSan concurrent-double-destroy witness** (two threads racing `fixpp_dict_destroy` on the **same** handle) confirms no data race on `tag_`/the `shared_ptr` and exactly-once teardown (the full-critical-section lock, FR-002).
- **SC-005**: The ABI-golden symbol gate passes with the new symbols; `abidiff` reports the change **additive**; the occupancy-drift gate passes **unchanged** (no new error codes); the per-symbol reentrancy gate passes with every new symbol annotated.
- **SC-006**: The version is `0.5.0` (`FIXPP_C_ABI_VERSION_MINOR == 5`), and a consumer recording minor 4 still works against the 0.5 engine (additive forward-compat; the new symbols are link-time, not behavioural downgrades).

## Behaviors & Limitations (proposed — finalised at Polish per `[[project_behaviors_limitations_catalogue]]`)

- **B-052-1** — A pure-C / Python consumer can now load a real FIX dictionary from XML, configure a session's TCP endpoint and seqnum-reset policy, stand up a live two-engine initiator/acceptor pair, and enumerate inbound fields — entirely through public `extern "C"` headers; PY-001 unblocks on this surface.
