# Data Model: Grouped Typed-Read Path Fix (062)

Not a persistent data model — the runtime read-path types the fix touches.

## Entities

### group_slice (`include/fixpp/wire/view.hpp:77-80`)
One repeating-group occurrence's bytes: `{ std::byte const* data; std::size_t len; }`. Points into the parent frame buffer; owned/borrowed via the parent OffsetTable arena. **Constraint (fix, RC1 — `len` is NOT widened)**: `group_slice.len` stays **unchanged**, exclusive of the last field's trailing SOH (`offset_table.cpp:501-504`). It feeds the shared C-ABI group cursor (`offset_table.hpp:134-139`) and the equivalence-test `TestLeg`, so widening the shared output is out of bounds. The trailing-SOH hazard is instead handled per read path:
- **one-level scalar reads** via `field_iterator` already **tolerate** a missing final SOH (`end == size` falls through and yields the field, `parser.hpp:399,405-406`) — no change needed;
- the **nested sub-view build** reads a **slice-scoped `data, len+1`**: the terminal SOH is provably already present in the parent frame buffer at `data + len` (the slice is interior to a well-formed, checksum-terminated frame in which every field is SOH-terminated), so the slice-scoped builder ends the counted value at `end < n && buf[end] == SOH` and the whole-frame `OffsetTable::build()` guard (`offset_table.cpp:264-268`, intentional — rejecting `end == n` prevents swallowing the checksum tail) is **NOT** relaxed.

### entry read context `entry_context` (NEW, wire)
A by-value entry built from `{span}` alone structurally **cannot** carry out its own read contract (no handle to the parent cache, no stable occurrence identity, no token to mint views). `entry_context` therefore carries — all borrowed/copied from the parent OffsetTable/MessageView, trivially copyable, no alloc:
- `std::span<const std::byte> span` — the entry's slice bytes (scalar reads scan this).
- `std::pmr::memory_resource* mr` — parent per-message PMR arena (nested build + decimal decode).
- `void const* opaque_dict` — dictionary handle (the nested slicer needs it).
- `OffsetTable::group_member_fn_t group_member_fn` — dict-driven group-membership predicate.
- `detail::generation_token gen` — **REQUIRED (N1)**. Minting a scalar `field_view` needs a token (`field_view_access::make(ptr,len,token())`, `parser.hpp:218`); building the nested sub-frame needs one (`frame_view` ctor **requires** `generation_token`, `framer.hpp:95-99`; `group_view` ctor takes one, `group_view.hpp:27`). `group_view` already holds this token via its `View` base, so it threads it into the ctx. Omitting it forces a default `{}` token that silently **disables** the `[2b §6.4]` lifetime/generation trap for every entry read — a quietly-weakened invariant this repo forbids.
- `OffsetTable* parent_cache_owner` — handle to the **root** `OffsetTable` that **owns the single flat nested sub-view cache** (**RC2**: the by-value entry cannot own it, and existing per-table metadata is only `{no_tag,start,count}`, `offset_table.hpp:169-173` — no sub-view cache exists yet). **This handle is threaded UNCHANGED at every nesting depth**: it always points at the one root `OffsetTable` that owns the flat cache; nested sub-`OffsetTable`s own **no** cache of their own. (Do NOT re-point `parent_cache_owner` per level — that would silently reintroduce a per-sub-table cache and contradict the single-flat-cache model.)
- `outer_occurrence_id` — a **globally-unique slice identity** for this occurrence within the parent frame: **the entry slice's `data` pointer** (`group_slice.data`, canonical), equivalently its root-relative byte offset from the frame start (`data - frame_base_`, secondary). This is unique per occurrence **at every nesting depth** because every occurrence's slice is carved **in place** from the single contiguous parent frame buffer (`group_slices` sets `.data = frame_base_ + fs`, `offset_table.cpp:495-505`; a sub-`OffsetTable`'s `frame_base_` IS the slice's `data`, no copy is made), so every occurrence's `data` is a distinct address for the message lifetime. The pointer is the canonical key (robustly unique regardless of re-basing); the root-relative offset is unique only if always measured root-relative. `operator[](i)` and `iter()` (which delegates to `operator[]`, `group_view.hpp:42`) BOTH derive the identity from the same `i` → the same slice `data` → the same identity, preserving **seam-#8** for free. **The `(parent group no_tag + ordinal i)` alternative is DELETED**: an ordinal-`i` key collides across distinct outer occurrences (e.g. `QuoteSets[0].QuoteEntries[0]` and `QuoteSets[1].QuoteEntries[0]` both key `((NoQuoteEntries,0), NoLegs)`) → the second occurrence silently reads the first's cached sub-view (wrong values, no error). Slice-`data` identity never collides.

**Recursive threading (N2):** a nested sub-view built over an entry slice is itself dict-aware and yields its own entries with their own `entry_context` (its `group_view` carries a fresh ctx over the sub-`OffsetTable`). At each descent the child sub-view's entries carry a ctx whose `outer_occurrence_id` is **THAT child slice's own `data`-pointer identity** (globally unique per the paragraph above), while `parent_cache_owner` stays the root cache owner. The chain `root OffsetTable(owns flat cache) → group_view.ctx → entry.ctx → sub-OffsetTable(dict-aware ctor, frame_base_ = entry slice data) → sub group_view.ctx → nested entry.ctx` threads recursively, so the key `(unique_slice_identity, nested_no_tag)` composes correctly to depth-N — required for the depth-3/4 nesting pervasive across the in-scope grouped messages (MassQuote `NoQuoteSets → NoQuoteEntries → NoLegs → NoLegSecurityAltID`, NewOrderList, AllocationInstruction/Report, MultilegOCR, QuoteRequest) and correct 2-level inner extents. Carried by `group_view`, handed to each entry by `operator[]`/`iter()` with the occurrence identity.

### span-scan field accessor (NEW, wire helper)
The one wire primitive that **does not exist yet** (N1): `get(std::span<const std::byte> span, std::uint16_t tag, detail::generation_token) -> core::expected_t<field_view>`. `field_iterator` walks `{tag, span}` over a bare slice (`parser.hpp:157-161`) but yields **no** token-bearing `field_view`; this helper reuses `field_iterator` to find the tag within the slice and mints a `field_view` carrying the ctx generation token (mirrors `MessageView::get`, `parser.hpp:212-219`, minus the OffsetTable). The entry's scalar / `field_value` accessors call it — no sub-index, zero alloc (FR-004a).

### group_view<GroupT> (`include/fixpp/wire/group_view.hpp`)
Enumerable view over a group's instance slices. **Change**: additionally carries the entry read context; `operator[]`/`iterator::operator*` construct `GroupT` from `{slice_span, context}` (was: from `span` alone, incompatible with the generated ctor). `size()` = occurrence count. Seam-#8: `operator[]` and `iter()` enumerate identical slices — unchanged.

### Entry flyweight `G_<no_tag>` (generated, `fixpp::<ns>::groups`)
**Change**: stores `{ entry_context ctx_; }` (carries the slice span + context; was `MessageView<Index> const* view_`). Read surface unchanged for callers:
- scalar `field() -> expected_t<T>` (string/char/int) and `field(mr) -> expected_t<decimal_t>`: implemented via the **span-scan field accessor** over `ctx_.span` (finds the tag, mints a token-bearing `field_view`) then `decode_field`/`decimal_t::parse`. No sub-index, zero alloc.
- `field_value(tag) -> expected_t<field_view>`: span-scan over `ctx_.span`. **Limitation (N3):** an entry slice includes its nested group's bytes, so a raw `field_value(tag)` returns the FIRST occurrence in the slice — a tag that lives ONLY inside a nested group would be returned as if it were an outer-entry field. Typed accessors are codegen-scoped to the entry's own members, so this only reaches through the `field_value(tag)` escape hatch, and it mirrors whole-message `field_value` first-occurrence semantics. Documented as an explicit limitation (future `spec/behaviors-and-limitations.md` B-*/L-* row at close-out), not silently accepted.
- nested `group<c, G_c>() -> group_view<G_c>`: builds a **dict-aware sub-view over `ctx_.span` lazily**, keyed + cached by `(ctx_.outer_occurrence_id, nested_no_tag)` — where `ctx_.outer_occurrence_id` is this entry slice's globally-unique `data`-pointer identity — in the root OffsetTable's single flat cache (see below), returns its `group<c>()` with a recursively-threaded ctx whose own `outer_occurrence_id` is the child slice's `data` identity.

### Nested sub-view cache (NEW, wire — root OffsetTable arena)
A **single flat cache** owned by the **root** `OffsetTable` (via `ctx_.parent_cache_owner`, threaded unchanged at every depth), **NOT** the by-value entry and **NOT** a per-sub-table cache. Keyed by **`(unique_slice_identity, nested_no_tag)`** where `unique_slice_identity = outer_occurrence_id` = the outer entry slice's `data` pointer — NOT `(nested_no_tag, instance_index)` and NOT `(parent no_tag + ordinal i, nested_no_tag)`: an ordinal-`i` key collides across distinct outer occurrences (two `NoQuoteSets` each descending into their own inner `NoQuoteEntries` instance 0 both key `(0, nested_no_tag)`). **Because the slice identity is the occurrence's globally-unique `data` pointer, keys never collide regardless of nesting depth** — every occurrence at every depth is carved in place from the one parent frame buffer and so has a distinct `data` address (see §entry read context). On first nested descent, build the sub-view via the **dict-aware `OffsetTable` ctor** (threads `ctx_.opaque_dict` + `ctx_.group_member_fn`, `offset_table.hpp:68-77`) over the slice-scoped `data, len+1` bytes. The dict-aware path is **MANDATORY**: the dict-free fallback sets `group_end = entries_.size()` (`offset_table.cpp:436-439`), swallowing any outer-entry fields that follow the nested group and skipping delimiter-membership validation (correct-by-luck only when the nested group is last, e.g. MassQuote `NoQuoteEntries`, `NoPartySubIDs` — a latent trap for any layout where it is not last). Store in the per-message arena, return it; subsequent descents reuse it. Lifetime = parent message. Ensures FR-004b (one bounded build per stable occurrence; zero on repeat) while entries remain by-value temporaries.

## Invariants
- **INV-G1**: entry borrows the parent parsed message; valid only while the parent MessageView is alive (documented, matches existing flyweight lifetime model).
- **INV-G2**: one-level scalar read builds no sub-index and allocates nothing (FR-004a); it reads via the span-scan field accessor, which tolerates a missing final SOH.
- **INV-G3**: nested descent builds at most one sub-view per **`(unique_slice_identity, nested_no_tag)`** where `unique_slice_identity` is the outer entry slice's globally-unique `data` pointer, cached in the **single flat cache** owned by the **root** OffsetTable (`ctx_.parent_cache_owner`, threaded unchanged at every depth); repeat descents on the same occurrence allocate zero. Because the slice `data` identity is globally unique across **all** nesting depths (each occurrence is carved in place from the one parent frame buffer), the key is **collision-free at every depth** — including the depth-3/4 nesting that is the norm across the in-scope grouped messages (MassQuote, NewOrderList, AllocationInstruction/Report, MultilegOCR, QuoteRequest, TradeCaptureReport). The `(no_tag + ordinal i)` key is forbidden (it collides across repeated outer occurrences).
- **INV-G4**: `operator[]` and `iter()` enumerate identical entries in identical order (seam-#8); both hand the entry the same `ctx` + `outer_occurrence_id` (the same slice `data` identity, derived from the same `i`).
- **INV-G5**: no change to top-level (non-group) message field reads, to `group_slice.len`, or to the C-ABI/error enum (FR-007).
- **INV-G6**: every entry read (scalar `field_view` mint + nested sub-frame build) uses the parent `generation_token` threaded through `ctx_.gen`; no read is performed under a default `{}` token (the `[2b §6.4]` trap stays armed).
- **INV-G7**: nested sub-views are built with the dict-aware `OffsetTable` ctor; the dict-free fallback is never taken on the nested-descent path.
