## Problem

`OffsetTable::group_slices_status` derives the instance boundary from **the wire**: `std::uint16_t const delim = entries_[first].tag` (`src/wire/offset_table.cpp:656`) — the first entry after the count field — and starts a new instance at every reappearance of that tag inside the extent. Two failure modes follow:

1. if the wire's first entry is not the context's true delimiter, the split is wrong from the first instance;
2. if the same tag legitimately occurs *inside a nested group* within an instance, the scan splits mid-instance.

Validation resolves the same boundary from the dictionary. Two producers, two rules (`data-model.md` Entity 6).

**C-8.0c — The extent walk descends at the instance-opening delimiter: C-4.1's symmetric twin.** *(NEW — Gate A round 3, 2026-07-31, user scope amendment on N23. Satisfies **FR-021e**; pins **SC-016**; unblocks FR-021b / SC-010 on the 262-context majority of the affected set.)*

**Why this clause lives here and not in `consume_group.md`.** The mechanism is C-4.1's, but the *site* is `src/wire/offset_table.cpp`, which this contract owns; this contract also owns the clause being withdrawn (C-8.0b's first bullet), the witness that has to be re-stated (W-10), and the two criteria that were at risk (FR-021b / SC-010). **The defect, at source.** `consume_group_extent` (`src/wire/offset_table.cpp:438-503`) opens each instance at `:473` and consumes the delimiter with a bare `++k` at `:475`. The nested-group descent it already performs (`:485-488`) sits inside the **inner** loop at `:476`, so it reaches only members scanned *after* the delimiter. On the shape `quickstart.md` §2 names — `35=X | 100=2 | 200=1 201=A | 200=1 201=B`, outer group `100` whose delimiter is nested count `200` — `:475` consumes the count field alone, `:478`'s outer-membership test fails on `201` (a member of group `200` under the **child** context, not of group `100`), the inner loop breaks, the outer loop sees `201 != 200` and exits with **one** instance. This is verbatim the asymmetry this bundle's own `consume_group.md` diagnoses in `include/fixpp/wire/validator.hpp` (`:362`'s bare `++i` versus `:376`'s post-delimiter descent) and repairs there via C-4.1.

**C-8.0c.1 — Descend before the bare increment.** Before consuming the instance-opening delimiter at `:475`, the walk MUST probe whether `delim` is itself a group **in the child context** and, if so, advance via the existing `consume_group_extent` recursion rather than by `++k`, resuming one past the nested group's extent. The probe MUST be the **same shape** the post-delimiter descent already uses at `:485-486` — `group_member_fn_(opaque_dict_, child, delim, entries_[k + 1U].tag)` under the `k + 1U < entries_.size()` bound — and MUST use the **same `child`** the walk already computes at `:466` (`ctx.pushed(group_no_tag)`), for the same reason: a nested group's own members are registered under its container's pushed path. Otherwise `++k` exactly as today. No new local, no new context construction, no new callback.

**C-8.0c.2 — Depth stays bounded by the existing guard.** The recursion MUST pass `static_cast<std::uint8_t>(depth + 1U)` and MUST be bounded by the existing `kMaxGroupDepth` check at `:442-445` (FR-009). No new recursion limit is introduced and behaviour at and beyond the cap is unchanged.

**C-8.0c.3 — The `overflow` early-return is load-bearing for TERMINATION-IN-BOUNDED-TIME, not only for diagnostics.** *(Anti-pattern guard, stated as a requirement.)* The new descent MUST mirror `:489-491` — `if (overflow) { return k; }` — immediately after the recursive call. This is not defensive symmetry: `consume_group_extent`'s depth-cap branch returns `count_idx` (`:444`), i.e. the **same** index it was given. Every other return path returns `first = count_idx + 1U` or greater, so forward progress **per iteration** is guaranteed only if the overflow return is honoured. A descent that swallows `overflow` at the *delimiter* position assigns a non-advancing `k` and the outer loop at `:473` re-tests the identical entry.

**The failure mode, corrected — it is unbounded no-op iteration (a DoS), NOT a hang.** *(Corrected at Gate A fresh loop round 1.)* The round-3 wording of this clause said the walk *"would spin — a hang"*. That is **false at source**. `consume_group_extent`'s outer loop is `while (k < entries_.size() && inst < declared && entries_[k].tag == delim)` (`:473`) and `++inst` at `:500` is **unconditional** in the loop body, so an un-mirrored implementation exits after exactly `declared` no-op iterations. The spin argument is correct for the **sibling** function — `include/fixpp/wire/validator.hpp:357`'s outer loop is `while (i < end && ents[i].tag == delim_tag)`, with **no** instance bound — and was transplanted here without being re-derived against this site. That is precisely research **D-4a**'s own lesson — *"a site can be sound on the first question and broken on the second"* — recurring inside the clause that records it, which is why the correction is stated rather than silently reworded.

What the omission actually costs: `declared` comes from `parse_declared_count` → `parse_bounded_u32`, which **saturates at `UINT32_MAX`** (`include/fixpp/wire/tag_scan.hpp:63-79`), and there is **no instance-count cap anywhere** — `max_group_entries_per_instance = 4096` (`include/fixpp/wire/offset_table.hpp:28`) bounds *entries per instance*, not instances. So a malicious count buys ~4.3 × 10⁹ no-op iterations of an attacker-chosen shape, and a benign small count returns **promptly, silently and correct-looking**. This does not contradict the function's own leading comment (*"the actual instance scan is separately bounded by `entries_.size()`, so a malformed/lying count can never over-consume"*): `entries_.size()` bounds what can be **consumed**; it does not bound the **iteration** count when `k` does not advance.

**The MUST is unchanged — only its justification moves.** This correction adds **no** instance-count cap requirement: that would be a new scope decision, not a corrected rationale, and the exposure is a bounded DoS amplification reachable only at nesting depth `kMaxGroupDepth` with a saturating attacker-supplied count. The post-delimiter descent already has this guard; the twin must not be delivered without it. **W-10a leg 4 is the witness, and it must be able to tell the mirrored implementation from the un-mirrored one** — see that leg, which the old spin wording had left unable to.

**C-8.0c.4 — Invariants that MUST keep holding (C-4.1's, mirrored).**

- **Per-instance entry cap (`:496-499`).** `(k - inst_start)` now includes the entries of a nested group opened *at* the delimiter. That is the **same accounting** `:487`'s post-delimiter descent already produces for a nested group opened one position later — the amendment applies one rule at both positions rather than introducing a new one. **Assessment, inferred and to be confirmed by the FR-021e task, not asserted as measured**: no shipped shape breaches it, because the cap is `default_max_group_entries_per_instance = 4096` (`include/fixpp/wire/offset_table.hpp:28`) and no group instance in the ten dictionaries approaches 4096 entries. It is called out because a breach would be a **new rejection**, which is SC-007's subject; "low, and here is why" belongs in the bundle, an assumption does not.
- **`declared`-bounded outer loop (`:473`).** Instance counting stays capped at `inst < declared` and hard-bounded by `entries_.size()`; a lying declared count still cannot run off the end. Descending changes *where the next instance starts*, never *how many are consumed*.
- **Extent termination (`:476-479`).** An instance still ends at the first tag that is not a member of the outer group under `ctx`. Descent changes how the *delimiter* is consumed, never how the extent ends — C-5.3's wording, at the offset-table site.
- **Empty and absent nested groups.** A nested group at the delimiter with `declared == 0`, or a delimiter that is the last entry (`k + 1U >= entries_.size()`), MUST behave exactly as the bare `++k` does today. `consume_group_extent`'s own `:461-462` and `:447-449` already give that.
- **The probe's precision is inherited, not newly created.** The `group_member_fn_(child, X, next)` shape can in principle answer true for a scalar whose successor happens to be registered under `child`. That risk already exists at `:485-486` for every post-delimiter member; C-8.0c adds one more evaluation of the same predicate at one more position and does not widen it.

## The lookup surface — resolved

**C-8.1 — Reuse the existing dictionary-callback seam; do not thread a new parameter through the public read API.** `OffsetTable` already carries an opaque dictionary pointer and a membership callback:

```cpp
using group_member_fn_t = bool (*)(void const*, group_context const&,
                                   std::uint16_t, std::uint16_t) noexcept;
```

(`include/fixpp/wire/offset_table.hpp:79-80`, with `void const* opaque_dict` supplied at construction, `:119-121` / `:126-128`.) The splitter's change is a **sibling callback** of the same shape returning the context's delimiter — `group_delim_fn_t`, resolving through the same `opaque_dict` to `table_view::group_first_field(msg_type, parent_path, no_tag)`. The callback set is membership-oriented today; this widens it by exactly one entry.

**C-8.2 — The ancestor path is already available at the splitter; nothing needs threading.** The parent path the lookup needs is **`stored_group_context()`**'s path — the same value C-4.1's validator descent uses — so the key is `(msg_type, stored_group_context().parent_path, no_tag)` and the two producers query the **same key**, which is what makes FR-021b's agreement structural rather than coincidental.

*Evidence, corrected 2026-07-31 (Gate A round 2, Codex #1).* Round 1 opened this clause by citing `group_context_for(no_tag)`. That accessor is **not** evidence for it and is the wrong value: it returns `stored_group_context().pushed(no_tag)` (`src/wire/offset_table.cpp:424-426`), and `pushed()` **appends** `no_tag` to `parent_path` (`include/fixpp/wire/group_view.hpp:56-62`), so keying on it would query `(msg_type, parent_path + no_tag, no_tag)` — one element too long, and a violation of Entity 1's "`parent_path` excludes `no_tag`" invariant (C-1.3). The citation is replaced by the two facts that actually carry the clause:

- the stored context is seeded once per parse via `set_group_context` (`include/fixpp/wire/offset_table.hpp:193-204`, whose doc records the ROOT seeding at `MessageView` construction) and read back by `stored_group_context()` (`:327`); for a ROOT table it is `{msg_type, [], 0}`, so the key is `(msg_type, [], no_tag)`;
- for a NESTED sub-table, `build_nested_subview` seeds the stored context **verbatim, with no further push** (`src/wire/offset_table.cpp:718-720`) from the caller's `entry_context::group_ctx`, which is the container path **already pushed** with the outer group's `no_tag` (`include/fixpp/wire/group_view.hpp:90-95`). So splitting a nested `no_tag` keys on `(msg_type, parent_path + outer_no_tag, nested_no_tag)` — also correct.

The splitter is reached from `group_slices(no_tag)` / `group_slices_status(no_tag)` (`src/wire/offset_table.cpp:614`, `:621`) on a table whose context is already seeded by one of those two routes. `group_context_for()` is used elsewhere for the *child* context and MUST NOT be used as this lookup's key.

**C-8.3 — No public signature changes.** `group_slices(no_tag)` and `group_slices_status(no_tag)` keep their signatures. `group_slices()` remains the one-line delegation 073 made it (`src/wire/offset_table.cpp:614-616`), so every top-level caller — the C-ABI top-level group getter, `MessageView::group<>()` — compiles and behaves identically apart from the corrected boundary. No C ABI symbol is involved.

**C-8.4 — Fallback disposition: exactly two cases, both observable.** *(second disjunct deleted 2026-07-31, Gate A round 2, Codex #2.)*

| case, as the splitter can actually test it | disposition |
|---|---|

**Why the round-1 second disjunct ("or the context does not resolve") is deleted, not merely narrowed.** The splitter *cannot observe the state it branched on.* `table_view::group_first_field(msg_type, parent_path, no_tag)` has **already** fallen through to the bare global before the splitter sees a value (`include/fixpp/dict/table_view.hpp:349-365`), and it returns a scalar `std::uint16_t` — unlike `group_member_tags`, there is no second span whose `.data()` pointer can discriminate a miss from a correct answer (the discriminator this bundle relies on in `group_ctx_delims.md`'s lookup-miss section and `research.md`'s Measurement-provenance section). So "the context did not resolve" is not a testable predicate at this seam, and a clause that both branches on it and asserts "the dictionary wins unconditionally" cannot hold.    **Why the round-3 form was a false-green, stated so it is not re-introduced.** `overflow` is a `bool&` threaded from `group()`'s `bool overflow = false;` (`src/wire/offset_table.cpp:549`), so the depth-cap branch's `overflow = true` (`:443`) reaches `group()`'s check at `:551-553` and `err_group_too_large` is returned **whether or not** the `if (overflow) return k;` mirror is present. Both of the round-3 leg's assertions therefore passed against an un-mirrored implementation: the leg whose own text warned that *"a witness that only checked the error code would never run"* was specified as exactly that witness.

   **Fixture constraint (MUST).** The depth-capped shape's `declared` **at the frame whose descent hits the depth cap** — not the outermost frame's — MUST be **≥ 2**. At `declared == 1` the mirrored and un-mirrored implementations are indistinguishable **by any means**, because the outer loop at `:473` runs exactly one iteration in both.

   **The discriminator: a `group_member_fn_` invocation count, deterministic and needing NO production change.** `group_member_fn_t` is a plain function pointer supplied at `OffsetTable` construction (`include/fixpp/wire/offset_table.hpp:79-80`, `:119-121` / `:126-128` — the same seam C-8.1 widens), so the case supplies its **own counting wrapper** that delegates to the real predicate and records invocations. No new seam is added and none should be.

   The arithmetic that makes it decisive, derived in **the frame whose descent hits the cap**: the recursion returns at `:442-444` **before** any probe call, `k` is left unadvanced, and the inner loop at `:476` contributes nothing because `entries_[k].tag == delim` still holds on entry — so each wasted outer iteration costs **exactly one further** `group_member_fn_` evaluation, the delimiter-position descent probe. A mirrored implementation performs that probe **once** and returns; an un-mirrored one performs it `declared` times, i.e. `declared − 1` more in that frame alone, and more still in the enclosing frames, which lack the same mirror and therefore re-enter it. The assertion below does not depend on that compounding — only on the mirrored total being **invariant** under this frame's `declared` while the un-mirrored total is not.

   **Assert it differentially, not against a hand-derived constant, and make "same fixture" structural.** The case runs the depth-capped fixture at two counts **of the cap-hitting frame's count field** — `declared = 2` and `declared = 8` — and asserts the recorded invocation totals are **equal**. The two runs MUST differ in **exactly one digit of that frame's count-field value** — the cap-hitting frame's, **not** the outermost frame's — with the **entry layout byte-identical and the physical instance count unchanged**. Varying the **outermost** frame's count instead would **false-green**: per the paragraph above, only the cap-adjacent frame fails to advance `k`, so the un-mirrored total is invariant under every enclosing frame's `declared` as well. That is legitimate here and it is what makes the invariance structural rather than argued: because `k` never advances **in that frame** on the un-mirrored path, `entries_[k].tag == delim` holds on every iteration of *that* frame's loop regardless of how many instances are physically present, so that frame's declared count alone drives the iteration count. Two runs that differed in layout would reintroduce exactly the derivation burden this assertion exists to avoid. The mirrored implementation's total is invariant under `declared`; the un-mirrored one's grows by the difference. This keeps leg 1's *"by construction, not captured"* discipline without an absolute magic number that no later reader can re-derive: an absolute total would have to account for every enclosing frame's probes — `kMaxGroupDepth = 16` levels of them (`include/fixpp/wire/offset_table.hpp:340`) — which is exactly the un-re-derivable constant leg 1 forbids.

   **The per-test `TIMEOUT` stays — as a BACKSTOP, never as the discriminator.** A timing-based gate is fragile, and this project already carries the lesson that a hung test with no per-test bound burns the job. It bounds the blast radius of an unanticipated non-termination; the invocation-count equality is what actually decides the leg.
